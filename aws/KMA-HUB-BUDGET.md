# 기상청 API 허브 호출 예산

키 하나(`KMA_HUB_KEY`)를 Lambda **15개**가 나눠 쓴다. 그래서 한 수집기의 낭비가
다른 수집기를 굶긴다. 이 문서는 **누가 얼마를 쓰는지**와 **하루를 어떻게 나누는지**를 적는다.

회계는 `aws/_shared/kma_hub.py` 가 자동으로 남긴다. **15개 전부가 여기에 잡힌다**
(2026-09-08 에 gk2a-clouds 를 넣기 전까지는 14개만 잡혔다).

- `wind/kma-calls/{날짜}.json` — 서비스별 합계 + `quotaHitToday`
- `wind/kma-calls/{날짜}/{lambda}.json` — 람다별 실행 수 + 엔드포인트별 호출

⚠️ **날짜는 KST 기준이다.** 허브 용량이 KST 자정에 풀리기 때문이다.
(2026-09-07 이전에는 UTC 로 세고 있어 "오늘 얼마나 남았나"를 계산할 수 없었다.)

---

## 한도에 대해 아는 것 / 모르는 것

**모른다.** 기상청은 일일 용량값을 공표하지 않는다. 그래서 코드 어디에도 한도를 숫자로 적지 않는다.

### ⚠️ 2026-09-08 정정 — 예전 추정치(3,570)는 믿을 수 없다

전에 여기 "소진 지점 ≈3,570회"라고 적었다. **그 근거가 무너졌다.**

회계 날짜를 UTC → KST 로 바꾼 것이 2026-09-07 22:54 KST 다. 그 전 장부는 UTC 로 셌으므로
남아 있는 두 파일 중 **어느 것도 온전한 KST 하루가 아니다**:

| 파일 | 실제로 덮는 구간 | |
|---|---|---|
| `2026-09-06.json` | UTC 09-06 하루 = **KST 09-06 09:00 → 09-07 09:00** | 두 KST 날에 걸쳐 있다 |
| `2026-09-07.json` | UTC 09-07 00:00 부터 = **KST 09-07 09:00 → 24:00** | 15시간뿐. 아침 9시간이 빠졌다 |

그래서 두 날이 서로 맞지 않는다 — 자정에 풀리는 한도를 KST 자정 기준으로 세지 않았으니 당연하다.

| | 총 호출 | 성공 | 소진 시각 |
|---|---:|---:|---|
| `2026-09-06.json` | 4,391 | 4,107 | 19:00 KST |
| `2026-09-07.json` | 2,479 | 2,182 | 18:35~19:00 KST |

같은 한도를 때렸다면 성공 수가 4,107 과 2,182 로 **2배 가까이 벌어질 수 없다.**
창이 어긋난 탓이 대부분이고, 나머지는 아래 gk2a-clouds 처럼 장부 밖에 있던 호출이다.

→ **한도값은 여전히 모른다. 이제는 추정치도 적지 않는다.**
  `DAILY_BUDGET` 2,800 은 한도의 추정이 아니라 **우리가 정한 상한**이다.

### 온전한 첫 하루

**2026-09-08 (KST) 이 KST 로 온전히 세는 첫 날이다.** 그날 `wind/kma-calls/2026-09-08.json` 의
`total.calls` 와 `quotaHitToday` 가 처음으로 뜻이 있는 값이 된다.

- `quotaHitToday: false` 로 하루가 끝나면 → 우리 사용량(약 2,660)이 한도 아래다.
- `true` 면 → 한도는 그 시각까지의 누적보다 낮다. 그 숫자가 **처음으로 믿을 수 있는 하한**이다.

### 사람이 해야 할 것 — 허브 마이페이지

코드로는 여기까지가 끝이다. 실제 한도값과 증량 신청 가능 여부는
**apihub.kma.go.kr 마이페이지에서 사람이 확인해야 한다.** 확인되면 이 문서와
`kma_hub.DAILY_BUDGET` 을 함께 고친다. (AWS 콘솔 로그인은 이것과 무관하다 — 기상청 계정이다.)

## 시간당 배분 — 이른 시간이 저녁을 굶기지 못하게

`kma_hub.pace(s3, bucket, name, cost)` 가 실행 앞에서 판정한다.

```
자정부터 흐른 비율 = (지금 KST - 자정) / 24시간
허용치            = DAILY_BUDGET × 흐른 비율 + BUDGET_GRACE
지금까지 쓴 양이 허용치를 넘으면 → 이번 회차를 건너뛴다
```

- `DAILY_BUDGET` 기본 2,800 (환경변수 `KMA_DAILY_BUDGET`)
- `BUDGET_GRACE` 기본 200 — 자정 직후에도 가장 비싼 회차(kma-mountain ≈165)가 한 번은 돌게
- **`ALWAYS_ON` 은 배분에서 빼지 않는다**: kma-warn · quake-asia · kma-lightning ·
  typhoon-official · kma-aws-min. 예산이 말라도 이 다섯은 계속 부른다
- 회계 파일을 못 읽으면 **통과시킨다**. 회계 때문에 수집이 멈추면 안 된다

지금 배분을 받는 곳: `kma-fcst` · `kma-mountain` · `kma-life`

## 2026-09-08 에 한 것

### 1. gk2a-clouds — 15번째 수집기가 장부 밖에 있었다

`aws/gk2a-clouds/cth_pipeline.py` 가 허브의 GK2A LE2/CTPS(운고)를 부르는데
`kma_hub` 를 안 썼다. **10분마다 도니까 하루 144회가 장부에 없었다.**

더 나쁜 건 실패했을 때다. `_kma_candidates()` 가 3시간(180분)을 10분씩 되짚어
**한 회차에 최대 19번** 불렀고, `stop()` 도 `pace()` 도 보지 않았다.
허브가 403 을 내면 매 회차가 19번씩 마른 한도를 때린다 — 09-06 의 5시간 차단 동안
30회차 × 19 ≈ 570회. **차단이 스스로를 연장하는 구조였다.**

고친 것:
- `@kma_hub.accounted('gk2a-clouds')` — `combined_handler.handler` 가 실제 진입점이다
  (`cth_pipeline_lcc.run = cth_pipeline.run` 이므로 base 를 고치면 실제 경로가 고쳐진다)
- `kma_hub.track('CTPS-CTH')` 로 호출을 센다
- 403 을 보면 **되짚기를 즉시 멈춘다.** 같은 산출물이 NOAA NODD 거울에 무료로 있으므로
  잃는 자료가 없다 — 공식 경로(허브)를 먼저 시도한다는 진실 규칙은 그대로다
- 되짚기 180분(19회) → **40분(5회)**

검증 (실제 코드에 가짜 urlopen 을 물려 확인):

| 상황 | 고치기 전 | 고친 뒤 |
|---|---:|---:|
| 403 (용량 초과) | 19회 호출 | **1회 뒤 중단** |
| 404 (아직 미발표) | 19회 호출 | 5회, 전부 장부에 기록 |

배포 뒤 실제 호출로 확인: `cthReady: true`, `KMA_GK2A_AMI_L2_CTPS_CTH_API_HUB`,
`wind/kma-calls/2026-09-08/gk2a-clouds.json` 에 `CTPS-CTH` 로 기록됨.

### 3. 배포 스크립트가 회계 모듈을 빠뜨리던 곳

`deploy-python.sh` · `deploy-lite.sh` 는 `handler.py` 안에서만 `import kma_hub` 를 찾았다.
gk2a-clouds 는 `cth_pipeline.py`·`combined_handler.py` 가 부르므로 그냥 지나쳤을 것이고,
그러면 **Lambda 가 import 에서 죽는다.** `"$DIR"/*.py` 전체를 보도록 고쳤다.
`gk2a-clouds/deploy_cth_into_existing.sh` 에도 `kma_hub.py` 동봉을 넣었다
(겸사겸사 Windows Git Bash 에서 돌도록 `zip` 의존을 python 으로 바꾸고, POSIX 경로를
Windows 실행파일에 넘기던 것을 `cygpath` 로 맞췄다 — 그 전에는 그냥 죽었다).

## 다룰 때 알아야 할 것

```bash
# ⚠️ default 프로필은 만료된 root 세션이다. 무슨 명령이든 "aws login" 만 나온다.
export AWS_PROFILE=earthus-deploy

# 오늘 장부
aws s3 cp s3://earthus-cache-kr/wind/kma-calls/$(date +%F).json - --region ap-northeast-2

# 규칙 이름은 목록으로 못 찾는다(events:ListRules 는 AccessDenied). 람다 정책에서 나온다
aws lambda get-policy --function-name kma-mountain --region ap-northeast-2   --query Policy --output text | grep -o 'rule/[A-Za-z0-9_.-]*'
```

`events:PutRule` 과 `DescribeRule` 은 된다. `ListRules` · `ListTargetsByRule` 은 안 된다.
