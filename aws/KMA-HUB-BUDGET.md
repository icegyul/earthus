# 기상청 API 허브 호출 예산

키 하나(`KMA_HUB_KEY`)를 Lambda 14개가 나눠 쓴다. 그래서 한 수집기의 낭비가
다른 수집기를 굶긴다. 이 문서는 **누가 얼마를 쓰는지**와 **하루를 어떻게 나누는지**를 적는다.

회계는 `aws/_shared/kma_hub.py` 가 자동으로 남긴다.

- `wind/kma-calls/{날짜}.json` — 서비스별 합계 + `quotaHitToday`
- `wind/kma-calls/{날짜}/{lambda}.json` — 람다별 실행 수 + 엔드포인트별 호출

⚠️ **날짜는 KST 기준이다.** 허브 용량이 KST 자정에 풀리기 때문이다.
(2026-09-07 이전에는 UTC 로 세고 있어 "오늘 얼마나 남았나"를 계산할 수 없었다.)

---

## 한도에 대해 아는 것 / 모르는 것

**모른다.** 기상청은 일일 용량값을 공표하지 않는다. 그래서 코드 어디에도 한도를 숫자로 적지 않는다.

**실측으로 좁힌 것은 이렇다.**

| 항목 | 근거 |
|---|---|
| 용량은 **KST 자정에 풀린다** | 09-05·09-06 이틀 모두 차단 구간이 정확히 자정에 끝났다. 낙뢰(5분)·레이더(5분)·AWS(10분) 수집기의 403 개수를 시간당 실행수로 나누면 세 수집기가 같은 시각을 가리킨다 |
| 09-06 은 **19:00 KST** 에 소진 | 위 계산으로 차단 구간 정확히 5.0시간 |
| 09-07 은 **18:35~19:00 KST** 에 소진 | 같은 계산, 22:35 KST 시점 차단 3.5시간 |
| 소진 지점 ≈ **3,570회** | 자정부터 19:00 까지의 예정 호출을 스케줄로 적분한 값 |

→ 한도는 **3,500~3,600 사이로 본다. 추정이다.** 진짜 값을 알게 되면 이 문서와
`kma_hub.DAILY_BUDGET` 을 함께 고친다.

## 시간당 배분 — 이른 시간이 저녁을 굶기지 못하게

`kma_hub.pace(s3, bucket, name, cost)` 가 실행 앞에서 판정한다.

```
자정부터 흐른 비율 = (지금 KST - 자정) / 24시간
허용치            = DAILY_BUDGET × 흐른 비율 + BUDGET_GRACE
지금까지 쓴 양이 허용치를 넘으면 → 이번 회차를 건너뛴다
```

- `DAILY_BUDGET` 기본 2,800 (환경변수 `KMA_DAILY_BUDGET`)
- `BUDGET_GRACE` 기본 200 — 자정 직후에도 가장 비싼 회차(kma-mountain ≈165)가 한 번은 돌게
- **`ALWAYS_ON` 은 배분에서 빼지 않는다**: kma-warn · quake-asia · kma-lightning ·
  typhoon-official · kma-aws-min. 예산이 말라도 이 다섯은 계속 부른다
- 회계 파일을 못 읽으면 **통과시킨다**. 회계 때문에 수집이 멈추면 안 된다

지금 배분을 받는 곳: `kma-fcst` · `kma-mountain` · `kma-life`

## 남은 조정 (AWS 콘솔 권한 필요)

예상 사용량 3,019 는 추정 한도의 약 85%다. 아래 둘을 하면 **약 2,510(70%)** 이 되어
kma-mountain·kma-fcst 가 양보하는 일이 거의 없어진다.

### 1. kma-mountain 하루 8회 → 4회 (−499)

산악 예보는 3시간마다 발표되지만 등산 참고 자료이고, 코드가 스스로
"등산 계획은 반드시 기상청 공식 발표를 확인하세요"라고 적어 최종 정본이 아님을 밝힌다.
6시간 간격이면 최대 3시간 더 늦어지는 것이 전부다.

```bash
aws events put-rule --region ap-northeast-2 \
  --name earthus-kma-mountain \
  --schedule-expression 'cron(40 2,8,14,20 * * ? *)' \
  --description '산악 예보 (발표 8회 중 4회만 받는다 — 허브 예산)'
```

### 2. kma-aws 45분 → 매시 정시 (−10)

지상 매시 관측인데 45분마다 돌아, 한 시간 안에 두 번 도는 회차가 생긴다.
handler 가 `tm` 을 시간 단위로 절삭하므로 그 초과분은 100% 같은 응답이다.

```bash
aws events put-rule --region ap-northeast-2 \
  --name earthus-kma-aws \
  --schedule-expression 'cron(25 * * * ? *)' \
  --description '지상 매시 관측 (정시 자료는 10~20분 뒤에 올라온다)'
```

## 아직 안 고친 것

- **kma-upper 의 403 오분류.** `kma_hub.classify()` 가 "미승인 403"과 "용량초과 403"을
  똑같이 `quota_exhausted` 로 본다. 그래서 프로파일러(`kma_wpf`)가 미승인이면 전역
  플래그가 켜져 정본인 안정도지수(`upp_idx`)까지 네트워크 없이 막힌다.
  호출 절감 문제가 아니라 **자료 손실**이다.
- **`aws/schedules.sh` 가 실제 배포와 다르다.** 낙뢰를 10분이라 적었지만 실측은 5분이고,
  kma-warn·kma-aws-min·kma-fcst 는 이 파일에 아예 없다. 이 파일만 보고 주기를 판단하면 안 된다.
- **README 가 kma-fcst 에만 있다.** 나머지 12개는 handler 독스트링이 유일한 문서다.
