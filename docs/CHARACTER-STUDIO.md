# EARTHUS 캐릭터 제작실

관리자 메뉴 → 캐릭터 제작실 (`/v3/character-studio.html`). 기존 Supabase 로그인과 관리자 UID 목록을 사용하며, 서버에서는 JWT와 `admins` 테이블의 RLS 조회를 다시 확인한다. 화면만 가리는 권한 검사를 신뢰하지 않는다.

## 한 번에 만들기 (자동 제작)

이름과 설명, 위도·경도만 넣고 **한 번에 만들기**를 누르면 다섯 단계를 이어서 실행한다.

1. 설명으로 자연어 프롬프트를 만들어 **디자인 시트**를 생성하고 그 해시로 디자인을 확정한다.
2. 그 시트를 참조로 **단일 3/4 투명 이미지**를 생성하고 **썸네일**을 코드로 만든다.
3. 그 단일 이미지를 참조로 **분리 파츠 시트**를 생성한다.
4. 파츠 시트의 **알파 경계를 읽어 6칸을 각각 측정**하고 자르기·크기·위치·회전 중심을 계산해 캐릭터를 세운다. 격자 칸을 그대로 자르지 않고 그림이 실제로 있는 곳만 자른다. 비었거나 너무 작은 칸은 칸 전체로 되돌리고 어떤 파츠인지 이름을 알려 준다.
5. `완성되면 지구에 바로 올리기`가 켜져 있으면 `characters/{id}/` 5개 파일을 쓰고 공개 catalog에 넣는다.

누르기 전에 유료 생성 횟수와 예상 출력 비용($0.541, 3회)을 확인 창으로 보여 준다. 진행 카드에 단계별 상태가 남고 **이 단계까지만 하고 멈추기**로 다음 단계부터 중단할 수 있다(이미 시작한 생성은 취소되지 않는다). 각 단계는 자기 전제를 기록에서 직접 읽으므로 화면을 새로 열거나 실패한 뒤 다시 눌러도 **남은 단계부터 이어서** 한다. 이미 만들어 둔 이미지는 다시 사지 않는다.

자동 제작은 사람의 중간 확인을 관리자의 그 한 번의 누름으로 대신한다. 서버가 검사하는 것은 확정 해시의 일관성이지 사람이 눈으로 봤는지가 아니다. 생성 품질은 모델 출력에 따라 달라지므로, 공개 전에 보고 고치려면 체크상자를 끄고 아래 수동 단계를 쓴다.

## 제작 순서 (수동)

1. 이름·영문 ID·설명·지역·리그 입력. 한국어 이름의 ID는 고유 영문 ID로 자동 생성하고 저장 전 수정할 수 있다.
2. 디자인 시트 업로드 또는 생성 → 디자인 확정.
3. 단일 3/4 투명 PNG 업로드 또는 생성. 썸네일은 코드로 자동 생성한다.
4. 분리 파츠 PNG 업로드 또는 생성. 기본 3열×2행: 머리, 몸, 왼팔 / 오른팔, 왼다리, 오른다리. 이미지를 다시 그리지 않고 영역과 크기·위치·겹침·회전 중심을 편집한다. 3~7개 파츠를 지원한다.
5. 동작 확인 → 위도·경도·크기 설정 → 지구 미리보기 → 저장하고 지구에 적용.

디자인 시트를 교체하면 기존 이미지는 보존하되 종속 이미지의 기준 해시가 달라져 공개를 차단한다. 단일 이미지 교체 후에는 파츠를 다시 등록해야 한다. 파츠와 동작 수정 후에는 다시 확인을 눌러야 한다.

## 저장과 공개

- **브라우저에 저장**: IndexedDB에 PNG Blob을 포함한 초안을 저장. 브라우저 데이터 삭제 시 없어지므로 서버 저장 또는 ZIP을 함께 사용한다.
- **서버에 저장**: S3 `character-studio/records/`, `character-studio/assets/`에 비공개 초안을 저장. 수정 전 ETag를 확인해 다른 창의 변경을 덮어쓰지 않는다.
- **지구에 적용**: 4종 PNG와 manifest의 확인 상태를 서버에서 검증한 뒤 `app/v3/characters/{id}/`에 정해진 5개 파일을 저장한다. `versions/{revision}/`에도 같은 이름을 보관하고 공개 catalog는 이 불변 버전을 참조한다.
- **지구에서 내리기**: catalog에서 제외한다. 원본 초안과 과거 파일은 유지한다. 캐시 때문에 이미 열린 화면은 새로 열어야 한다.
- **ZIP 내보내기**: `characters/{id}/{id}_master_sheet.png`, `_runtime_3q.png`, `_parts_atlas.png`, `_thumbnail.png`, `_manifest.json`을 생성한다.

PNG는 3.5MB 이하, 각 변 32~4096px. 일반적으로 1536px를 권장한다. 단일 이미지와 파츠에는 실제 투명 영역이 있어야 한다. 그림자는 텍스처에 포함하지 않고 코드에서 타원으로 만든다.

## 렌더링

`character-globe.js`가 공개 catalog를 읽고 현재 보이는 후보만 지연 로딩한다. 모바일 최대 8개, 데스크톱 최대 20개를 표시하고 화면 밖 캐시는 해제한다. 지구의 기존 렌더 루프를 공유한다. 표면 법선은 캐릭터의 위쪽, 카메라 방향을 표면 접평면에 투영한 벡터는 정면이다. 반대편 지구의 캐릭터는 가린다.

기본 LOD: 화면 높이 100px 초과에서 레이어, 80px 미만에서 단일 이미지. 히스테리시스로 경계 깜빡임을 줄인다. 파츠 동작은 8초 후 중립 자세로 정지하고 20Hz로 갱신하며 숨긴 탭과 동작 줄이기 설정에서는 멈춘다. 별도 requestAnimationFrame 루프를 지구에 추가하지 않는다. 현대 지구의 공개 캐릭터는 과거 대륙 화면에서는 표시하지 않는다.

캐릭터는 운영자가 배치한 창작 캐릭터이며 실황 관측 자료가 아니다. 기존 실황 생물·기상 데이터의 위치나 표현은 바꾸지 않는다.

발과 루트는 표면 법선에 정렬한다. 카메라가 바로 위에 있을 때 종이판이 옆면만 보이는 특이점을 피하려고 그림 평면에만 시선에 따른 기울기를 적용한다. 이 보정은 확대·축소에 따라 연속적으로 변한다.

## 이미지 생성 연결

API 키 없이도 업로드·편집·저장·배치가 동작한다. 키가 없으면 서버가 `503`을 반환하고 유료 생성 작업·사용 횟수를 만들지 않는다.

- 모델: `gpt-image-2`, high 품질. 마스터/파츠 1536×1024, 단일 1024×1024. 출력 기본 예상 합계 $0.541. 입력 비용과 재생성 비용은 별도다. 기준: 2026-09-04 OpenAI 공식 이미지 생성 문서.
- API 키: AWS Systems Manager Parameter Store의 `/earthus/character-studio/openai-api-key`, 유형 `SecureString`, AWS 관리형 기본 키 사용. 클라이언트 파일·로그·Git에 넣지 않는다.
- 서버는 프롬프트를 구성하고 참조 이미지를 가져온 뒤 Lambda 비동기 작업으로 생성한다. 고유 요청 ID와 조건부 저장으로 중복 과금을 막는다. 캐릭터별 최대 12회, 자동 유료 재시도 없음.
- `generation_count`와 `estimated_output_usd`는 서버 소유 값이다. 후자는 요청된 출력의 예산 추정치이며 청구액이 아니다. 작업 결과의 `usage`에는 API가 반환한 사용량이 보존된다.
- 수동 단계에서는 생성 결과가 관리자 확인 전 공개되지 않는다. 자동 제작은 `완성되면 지구에 바로 올리기`를 켠 그 누름이 확인을 대신하므로, 격자 배치·일관성·알파 품질이 어긋난 결과도 그대로 공개될 수 있다. 편집 단계는 그래서 남겨 둔다.

## 배포

PowerShell에서 저장소 루트 기준:

```powershell
./aws/character-studio/deploy.ps1
# 이름 있는 AWS 프로파일을 사용하는 경우
./aws/character-studio/deploy.ps1 -Profile earthus-deploy
```

먼저 AWS 로그인과 기존 `prototype/js/config.local.js`의 관리자 설정이 필요하다. 스크립트는 `earthus-character-studio` CloudFormation 스택, 범위가 제한된 IAM 역할, Python Lambda, Function URL과 14일 로그 보관을 만든다. 기존 버킷의 전체 정책·CORS는 변경하지 않는다. 초안 프리픽스가 외부 공개되지 않는 기존 버킷 권한을 유지해야 한다. 공개 함수 URL이어도 모든 실제 작업은 Supabase 관리자 인증을 요구한다.

배포 스크립트가 반환된 공개 API URL만 `character-config.js`에 기록한다. 지정 정적 파일과 관리자 링크를 S3에 올리고 CloudFront 캐시를 무효화한다. `characters/catalog.json` 또는 사용자가 만든 이미지를 정적 배포물로 덮어쓰지 않는다.

AWS와 OpenAI의 실제 연결은 자격증명이 있는 환경에서 확인해야 한다. API 키는 나중에 SSM에 추가하면 재배포 없이 연결된다. 결제 설정·모델 접근 권한도 OpenAI 계정에 필요하다.

## 로컬 검증

```powershell
python tools/character-studio/dev_server.py --repo . --port 8793
node --test tools/character-studio/test_core.mjs
python tools/character-studio/test_backend.py
node tools/character-studio/test_browser.mjs
node tools/character-studio/test_auto.mjs
```

`test_auto.mjs`는 자기 서버(8794, `.studio-auto-data`)를 직접 띄웠다가 끄므로 위 개발 서버가 없어도 된다. `--fake-images`를 붙인 개발 서버는 OpenAI 대신 **도형 PNG**를 돌려주므로 자동 제작 흐름은 검증되지만 **그림 품질은 검증되지 않는다.** 이 대체는 루프백 개발 서버에만 있고 Lambda 코드에는 없다.

브라우저 주소: `http://127.0.0.1:8793/v3/character-studio.html?preview=1`. 로컬 서버는 loopback에만 바인딩하고 동일한 로컬 Origin만 허용한다. 로컬 저장과 공개는 `.studio-data/`에만 이루어진다. 운영 도메인의 `?preview=1`은 관리자 로그인을 우회하지 않는다. 로컬 서버는 OpenAI 또는 AWS를 호출하지 않는다.

검증된 범위: 업로드 알파 검사, 디자인 확정, 파츠 수정, 동작 확정, 서버 저장·재열기, ZIP CRC와 5개 파일, 공개·내리기, 실 WebGL 렌더, 거리별 LOD, 법선 정렬, 뒷면 가림, 모바일 가로 넘침, 관리자 인증 선차단, 생성 멱등성, 저장 충돌.

자동 제작에서 추가로 확인한 것: 키가 없으면 버튼이 잠김, 비용 확인 창의 횟수와 금액, 생성 3회 연쇄, 알파 경계 측정 자르기(칸 침범 없음·칸 전체로 잘리지 않음), 세워진 비율(발이 바닥, 키가 한 칸), 공개 5개 파일과 catalog 항목, **실제 `/v3/` 지구가 catalog를 읽어 그 캐릭터를 그리는 것**(실행하면 `artifacts/character-studio/auto-on-globe.png` 로 남는다. 이 폴더는 커밋하지 않는다), 공개 끄기 시 목록에 안 오름, 빈 칸 되돌림.

미검증: AWS 실제 배포·운영 관리자 로그인·실제 이미지 생성. 키와 AWS 자격증명이 없는 상태에서 성공으로 표시하지 않는다. **자동 조립은 도형 고정물로만 검증했다** — 실제 모델이 그린 파츠가 칸을 넘거나 붙어 나오면 측정이 그만큼 어긋난다. 첫 실사용 캐릭터는 공개 체크를 끄고 만들어 눈으로 확인할 것.
