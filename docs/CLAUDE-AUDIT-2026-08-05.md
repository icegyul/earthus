## 0. 작업 전에 반드시 읽을 것

먼저 [`docs/HANDOVER.md`](./HANDOVER.md)를 처음부터 끝까지 읽는다. 특히 다음 원칙은
기능이나 화면 디자인보다 우선한다.

- earthus가 예보하거나 원인을 지어내지 않는다.
- 모든 값에 출처·관측/발표 시각·표본 수를 붙인다.
- 자료 없음과 사건 없음을 구분한다.
- `clampToGround`와 무한 애니메이션을 사용하지 않는다.
- `⚠️⚠️` 주석은 사고 기록이므로 지우지 않는다.
- 운영 배포는 변경 파일만 올리고 Content-Type과 CloudFront 반영을 확인한다.
- 비밀값은 문서·채팅·커밋에 넣지 않는다.

현재 작업 트리에는 이 감사와 무관한 기존 변경이 있다. 사용자 작업으로 간주하고 보존한다.

```text
M  aws/social-draft/handler.py
?? prototype/supabase/.temp/
?? supabase/
?? 샘플/천리안2A 위성.png
```

## 1. 결론

earthus의 시각적 정체성과 데이터 설명 철학은 강하다. 특히 첫 화면의 지구 표현,
산불 상세의 출처·시각·탐지 픽셀·한계 설명은 좋은 기준이다.

현재 가장 큰 문제는 기능 수가 아니라 **화면 상태와 신뢰 정보가 서로 맞지 않는 것**이다.
Windy 기능을 추가하기 전에 다음 세 가지를 먼저 안정시켜야 한다.

1. 지금 어떤 레이어가 켜져 있는가.
2. 화면의 값·색·선이 어느 출처의 어느 시각 자료인가.
3. 자료가 없거나 실패한 것인지, 실제 사건이 없는 것인지.

정상 첫 로드와 점검한 주요 흐름에서는 치명적인 콘솔 예외가 없었고,
`prototype/js` 전체 JavaScript 문법 검사도 통과했다. 그러나 여러 오류가 예외 없이
조용히 잘못 표시되는 형태라 콘솔이 깨끗하다는 것만으로 안전하지 않다.

## 3. 가장 먼저 수정할 문제

### P1-1. 태풍 UI가 모든 정보 패널을 가린다

#### 재현

1. 모바일 390×844에서 태풍 레이어를 켠다.
2. 태풍 하나를 눌러 범례와 타임라인을 띄운다.
3. 태풍 정보창을 닫은 뒤 설정, 뉴스, LAB 또는 `if`를 연다.

#### 실제 결과

- 태풍 범례가 패널 제목과 닫기 버튼 위에 겹쳐 보인다.
- 하단 예보 타임라인이 뉴스 내용, 설정 항목, `if` 입력창을 덮는다.
- 패널의 닫기 버튼이 빨간 점으로만 보이는 문제와 합쳐져 나가기 어렵다.

#### 관련 코드

- `prototype/css/app.css:1645` — `#tcLegend`
- `prototype/css/app.css:2056` — `#fxBar`, `z-index:60`
- `prototype/js/layers/cyclone.js:749` — 태풍 범례 생성
- `prototype/js/ui-timeline.js:28` — 예보 타임라인

#### 기대 결과

- 다른 전체 패널이 열리면 범례와 타임라인을 임시로 접는다.
- 해당 패널을 닫고 태풍 화면으로 돌아오면 기존 태풍 선택과 시각을 복원한다.
- 미래 시각이면 `기관 예보/모델 계산 · 실황 아님` 표시를 계속 유지한다.

### P1-2. 활성 화면과 출처가 서로 다르다

#### 재현

`지구 → 기온 현재`를 켠다.

#### 실제 결과

지구는 기온색으로 바뀌지만 좌하단 출처는 계속
`구름 · NOAA GMGSI 전지구 구름 합성`이라고 표시된다. 첫 화면의 현재 기온과
최고·최저에도 해당 날씨 자료의 출처·발표 시각이 없다.

#### 원인 후보

`prototype/js/ui-source.js:112`의 우선순위 목록에서 `clouds`가 `temp`보다 먼저이고,
`PRIORITY.find()`로 활성 레이어 하나만 고른다.

#### 추가 문제

- 모바일 출처 문구가 `prototype/css/app.css:933`에서 8.5px까지 작아진다.
- 네 번째 `<span>`부터 숨겨 핵심 경고도 사라질 수 있다.
- 히마와리 적외 영상의 `강수량 자체는 아닙니다`가 숨겨지는 사례가 있다
  (`prototype/js/ui-source.js:299`).

#### 기대 결과

- `현재 선택한 주 레이어`의 이름·성격·출처·시각·단위·색상 눈금을 한 묶음으로 표시한다.
- 동시에 켜진 점/선 레이어는 `산불 900 · 태풍 3 · 지진 52`처럼 별도 활성 목록으로 표시한다.
- 출처가 여러 개면 하나를 임의로 숨기지 않는다.

### P1-3. 안전 피드 실패가 사건 없음처럼 보일 수 있다

지진·쓰나미 같은 안전 자료 수집 실패를 `prototype/js/layers/registry.js:219`에서
콘솔 경고만 남기고 삼킨다. 상태값은 개발 HUD에서만 보인다
(`prototype/js/ui.js:1644`).

#### 위험

빈 지도는 사용자가 `현재 위험 없음`으로 해석할 수 있다. 실제로는 API 장애나 마지막
자료 만료일 수 있다.

#### 기대 결과

안전 레이어마다 다음 상태를 사용자 화면에 표시한다.

- 정상: `USGS · 최근 24시간 · 14:20 UTC 갱신`
- 지연: `다음 자료 기다리는 중 · 18분 지연`
- 실패: `자료 확인 불가 · 마지막 성공 13:58 UTC`
- 자료 없음: `받은 자료 0건`이며 실패와 다른 상태

### P1-4. 동의 저장 실패 후에도 가입 완료로 처리될 수 있다

- `prototype/js/auth.js:138`의 `saveConsent()`가 Supabase 오류를 경고만 하고 정상 반환한다.
- `prototype/js/ui-account.js:178`이 로컬 동의 완료값을 기록하고 가입 완료를 표시한다.

네트워크 또는 RLS 오류 시 서버에 동의 기록이 없는데 사용자에게 성공으로 안내될 수 있다.
저장 오류를 호출자에게 전달하고 동의창을 유지한 채 재시도를 안내해야 한다.

개인정보 내보내기도 일부 조회 실패를 빈 배열로 바꾼 뒤 성공 다운로드할 수 있다.

- `prototype/js/auth.js:168`
- `prototype/js/ui-account.js:235`

완전한 내보내기만 성공 처리한다.

### P1-5. 위치 요청과 기본 위치가 일관되지 않다

#### 확인된 문제

- 시작 시 `prototype/js/main.js:97`과 `prototype/js/ui.js`의 `chrome.init()`이 별도로
  위치를 요청한다.
- 실제 위치 요청 구현도 `prototype/js/viewer.js:269`와
  `prototype/js/mylocation.js:25`로 나뉜다.
- 실패하면 홈은 설명 없이 인천을 사용한다 (`prototype/js/ui.js:36`).
- 서핑은 같은 세션에서 양양을 기본값으로 사용한다
  (`prototype/js/ui-surf.js:520`).
- 기본 위치라는 설명은 날씨 상세 아래쪽에서만 보인다
  (`prototype/js/ui-weather.js:405`).

#### 기대 결과

- 위치 요청은 공유 Promise 하나로 통합한다.
- 앱 시작 즉시 권한을 요구하지 말고 `내 위치 사용`을 눌렀을 때 요청한다.
- 권한이 없으면 첫 화면부터 `기본 위치 · 인천`이라고 표시한다.
- 기능마다 임의의 다른 기본 위치를 쓰지 않는다.
- 위치 점과 날씨 기준 위치가 항상 같은 좌표를 사용한다.

## 4. 실제로 작동하지 않거나 잘못 표시되는 기능

### P1-6. 검색 결과의 죽은 항목

`prototype/js/search.js:77`에 제거된 `events`, `sky` 액션이 남아 있다.
실서버에서 `이벤트` 결과를 누르면 검색창만 닫히고 아무 일도 일어나지 않았다.
실행 대상 버튼을 못 찾으면 `prototype/js/search.js:337`에서 조용히 종료한다.

반대로 새 `취미` 기능은 검색 결과에 없다.

검색 인덱스를 메뉴 정의와 한 소스에서 생성하거나, 최소한 실행 대상이 없는 결과는
노출하지 않고 테스트로 막는다.

### P1-7. 항공편 검색 예시와 실제 검색 규칙이 다르다

- UI 예시: `인천, ICN` (`prototype/js/ui-flight.js:100`)
- 실제 검색: 영문 도시명·공항명·IATA 중심 (`prototype/js/flight.js:49`)

운영에서 `인천`은 0건, `ICN`은 정상 동작했다. 한국어 별칭을 검색 인덱스에 넣거나
예시에서 한국어를 제거한다. 사용자에게 불가능한 입력을 권하지 않는다.

### P1-8. `if`의 지진 답변이 규모를 두 번 표시한다

`오늘 지진 몇 건?`의 결과가 다음처럼 표시된다.

```text
M 6.3    M 6.3
M 5.7    M 5.7
M 5.2    M 5.2
```

`prototype/js/ask/answer.js:149`에서 `label`은 이미 `m.name = M 6.3`인데,
`prototype/js/ask/answer.js:163`의 상세값도 다시 규모를 만든다.

오른쪽 상세에는 위치와 발생 시각을 표시해야 한다. 또한 질문은 `오늘`이지만 실제 데이터는
USGS rolling 24-hour feed다 (`prototype/js/layers/hazard.js:43`). 문장도
`최근 24시간 USGS 피드 52건`으로 고친다.

출처 펼침에는 다음을 포함한다.

- 자료 제공처
- 피드 기준 시각/마지막 갱신
- 자료 범위: 최근 24시간
- 적용한 최소 규모 기준
- 원문 링크

### P1-9. 뉴스가 계속 로딩 상태로 보인다

지역 뉴스가 모두 출력된 뒤에도 탭 라벨이 `뉴스 …`로 남는다.
`prototype/js/ui-events.js:274`가 과거 탭명인 `지역 뉴스/Local news`를 찾지만 실제
탭명은 `뉴스`로 바뀌어 업데이트 대상이 없다.

뉴스 내용도 업무 행사, WhatsApp, 스포츠 등 일반 외국어 기사가 대량으로 섞인다.
`확인된 지구 사건`과 `지역 일반 헤드라인`을 같은 `News` 이름 아래 섞지 않는다.
후자는 LAB 또는 별도 탭으로 낮추는 방안을 검토한다.

### P1-10. 운영 화면에 개발자용 문구가 노출된다

설정 하단에 다음 문구가 그대로 보인다.

```text
사업자 정보    config.local.js 에 입력 필요
```

원인은 `prototype/js/ui-account.js:305`의 fallback이다. 사업자 정보가 없으면 행을
숨기고, 관리자에게만 별도 진단을 표시한다. 운영 사용자에게 파일명을 노출하지 않는다.

현재 모든 기능이 무료이고 판매가 잠겨 있는데도 설정 첫 화면에 `구독하기`, `구독`,
`사전등록 · 창립 멤버`가 반복 노출된다. 판매 전에는 하나의 `서비스 소식 받기` 정도로
단순화하는 것이 좋다.

## 5. 모바일·접근성 문제

### P1-11. 가로 화면에서 메뉴 항목이 잘리고 스크롤할 수 없다

844×390에서 1단 메뉴의 `지구`는 위로, `설정`은 아래로 완전히 잘렸다.
`prototype/css/app.css:476`의 중앙 정렬 메뉴에 최대 높이와 세로 스크롤이 없다.

safe area를 포함한 `max-height`와 `overflow-y:auto`가 필요하다.

### P2-1. 닫기 버튼이 13×13px 빨간 점이다

`prototype/css/app.css:170`에서 닫기 버튼은 13×13px이며 × 기호는 hover 때만 보인다.
터치 기기에는 hover가 없으므로 사용자는 상태등으로 읽는다.

- 실제 터치 영역은 최소 44×44px로 만든다.
- 터치 환경에서는 ×를 항상 표시한다.
- 닫기와 내리기의 차이는 색만으로 전달하지 않는다.

### P2-2. 닫힌 UI가 키보드 탭 순서에 남는다

- 검색창은 opacity와 pointer-events만으로 숨긴다
  (`prototype/css/app.css:1226`).
- 메뉴는 화면 밖 transform과 `aria-hidden`만 쓴다
  (`prototype/js/layerbar.js:492`).

실서버에서 닫힌 검색 입력·닫기 버튼·화면 밖 메뉴 버튼이 탭 대상으로 남았다.
닫힌 컨테이너에 `inert`와 `visibility:hidden`을 적용하고, 다이얼로그에는 포커스 트랩과
호출 버튼으로의 포커스 복귀를 구현한다.

### P2-3. 날씨 영역이 키보드로 열리지 않는다

`prototype/index.html:185`의 날씨 영역은 `role="button" tabindex="0"`이지만
`prototype/js/ui-weather.js:59`에는 click 이벤트만 있다. Enter와 Space로 작동하지 않는다.
가능하면 실제 `<button>`으로 바꾸고, 현재 전체 폭에 생기는 브라우저 기본 포커스 테두리도
`:focus-visible`로 정리한다.

### P2-4. 패널과 그래프의 의미 구조가 부족하다

설정·날씨·뉴스·LAB·`if` 패널은 시각적으로 모달이지만 대부분 `role="dialog"`,
`aria-labelledby`, `aria-modal`이 없다. LAB의 그래프는 시각적으로만 보이고 스크린리더가
읽을 대체 요약도 없다.

## 6. 정보 구조 문제

### 메뉴 명칭

- `지구 스타일` 안에 기온·바람·대기질·바다·관측소가 모두 있다.
  실제 명칭은 `레이어`가 맞다.
- 날씨 위성 영상과 인공위성 기능이 모두 `위성`이라는 말로 표현된다.
  `위성 영상`과 `인공위성`으로 구분한다.
- 한국어 화면에 `Alert`, `News`, `LAB`, `if`가 혼재한다.
  특히 `if`는 기능을 추측할 수 없으므로 `물어보기` 또는 `지구에 질문`으로 바꾼다.
- `항공기`, `선박`이 데이터 레이어처럼 보이지만 실제로는 선착순 모집으로 연결된다.
  작동하지 않는 모집 항목은 주 레이어 목록에서 분리한다.

### 활성 레이어 상태

바람·산불·태풍을 차례로 켜면 모두 누적되지만 메뉴를 닫으면 무엇이 켜졌는지 알 수 없다.
빨간 산불 점과 태풍 경로가 한 화면에 섞여도 사용자에게 현재 조합을 설명하지 않는다.

다음 형태의 활성 자료 바를 권장한다.

```text
[기온 · 모델 계산 · 04 UTC] [산불 · NASA FIRMS · 최근 24시간] [태풍 · 기관 발표]
                                               [모두 끄기]
```

면 색상 레이어는 한 장만, 점·선 레이어는 여러 개를 허용하되 활성 상태를 항상 표시한다.

### 수치 범례

기온·습도·수온·파고 등은 색상만 있고 수치 범례가 없다. 색상·단위 정의는 이미
`prototype/js/gridoverlay.js:18`에 있지만 지도 UI에서 사용하지 않는다.

Windy와 비교했을 때 가장 큰 실사용 차이다. 레이어를 켰을 때 다음을 한 묶음으로 표시한다.

- 레이어명
- 관측 / 기관 예보 / 모델 계산
- 색상 눈금과 단위
- 자료 시각과 다음 갱신
- 지구를 누른 지점의 실제 값

### 날씨 서술의 밀도

날씨 상세는 긴 원인 설명이 현재 기온·습도·강수확률보다 먼저 나온다. 사용자는 우선
`지금 상태 → 오늘 변화 → 근거와 긴 설명` 순서로 읽는다. 원인 설명은 관측으로 확정할 수
있는 범위를 넘지 않는지도 다시 검토한다.

홈 33°C와 상세 KMA 35°C처럼 서로 다른 출처의 값이 동시에 보일 때는
`홈: 모델 현재값 / 상세: 기상청 지점값`처럼 차이의 이유를 같은 화면에 적는다.

## 7. Windy에서 참고할 것과 피할 것

### 참고할 상호작용

1. 빠른 레이어 6~8개와 검색 가능한 전체 레이어를 분리한다.
2. 현재 켜진 레이어 수, 활성 목록, 모두 끄기를 제공한다.
3. 레이어·수치 범례·시간·모델·재생을 하나의 조작 영역으로 묶는다.
4. 지구의 한 지점을 누르면 해당 위치의 관측·가까운 관측소·기관 예보·자료 없음을 함께 보여준다.
5. AIFS·IFS·기상청 등을 평균 내거나 승자를 미리 정하지 않고 나란히 비교한다.
6. 부이 실측과 정확히 같은 위치·시각의 모델값을 대조한다.
7. 검증된 레이어 조합 프리셋을 제공한다.
   - 태풍: 구름 + 공식 경로 + 부이
   - 산불: 탐지 + 구름 + 바람 자료
   - 지진: 지진 + 쓰나미 경보
   - 바다: 파고 + 부이
8. 앱 안에 `이 화면 이상해요`를 두되 위치·개인정보 전송은 별도 동의를 받는다.

참고 자료:

- Windy 다중 모델·예측 가능성: <https://www.windy.com/articles/43904>
- Windy 부이 실측과 모델 비교: <https://www.windy.com/articles/43902>
- Windy Radar+ 조합 방식: <https://community.windy.com/topic/36164/windy-launches-radar-layer-combining-satellite-and-radar-view>

### 따라 하지 않을 것

- 관측과 미래 모델을 같은 시각 언어로 섞는 것
- 자료 갱신 시각을 깊은 정보 메뉴 안에 숨기는 것
- 근거·표본 없는 `예측 가능성` 퍼센트
- 무한 바람 입자 애니메이션
- 모든 조작을 지도 위에 동시에 띄우는 것
- 핵심 신뢰성과 오류 처리가 끝나기 전 플러그인·경로계획 기능을 늘리는 것

earthus의 방향은 다음 한 문장으로 유지한다.

> Windy처럼 빠르게 찾고 비교하되, Windy보다 명확하게 이것이 관측인지,
> 기관 발표인지, 모델 계산인지 밝힌다.

## 8. 운영·배포 문제

### 웹푸시 아이콘 경로가 존재하지 않는다

- `prototype/sw.js:82`와 `prototype/js/alarms.js:95`가 `icon.png`을 사용한다.
- 저장소에는 `icon-192.png`, `icon-512.png`, `icon.svg`만 있다.
- 운영 <https://earthus.net/icon.png>은 403이다.

알림 자체가 표시되더라도 아이콘·배지가 깨지거나 무시될 수 있다. 실제 파일 경로로 고친다.

### 서비스워커 캐시 정책이 인수인계와 다르다

운영 `sw.js` 응답은 점검 당시 다음과 같았다.

```text
Content-Type: application/javascript; charset=utf-8
Cache-Control: public, max-age=300
```

`HANDOVER.md`는 `sw.js`에 `no-cache`를 요구한다. 또한
`aws/deploy-app.sh:43,52`는 전체 sync와 JS Content-Type 교정 과정에서
`public, max-age=60`을 적용한다. `sw.js`를 별도로 다시 올리는 예외 처리가 필요하다.

### Open-Meteo 이용조건을 판매 전에 확인한다

`prototype/js/config.js:78`은 무료 엔드포인트인
`https://api.open-meteo.com/v1/forecast`를 직접 사용한다.

Open-Meteo 공식 약관은 무료 API를 비상업용으로 제한하고, 상업용은
`customer-api.open-meteo.com`과 API 키를 사용한다고 설명한다.

- 약관: <https://open-meteo.com/en/terms>
- 상업용 API: <https://open-meteo.com/en/pricing>

현재 상태를 법적으로 단정하지 말고, 유료 판매를 열기 전에 유료 엔드포인트·자체 호스팅·
대체 자료 중 하나를 결정한다. API 키는 클라이언트나 이 문서에 넣지 않는다.

## 10. 각 수정의 완료 조건

- JavaScript 파일마다 다음 문법 검사를 통과한다.

  ```bash
  cp prototype/js/파일.js /tmp/x.mjs && node --check /tmp/x.mjs
  ```

- 390×844, 844×390, 1280×720에서 직접 화면을 확인한다.
- 태풍 선택 후 설정·뉴스·LAB·`if`를 각각 열어 겹침이 없는지 확인한다.
- 기온·수온·파고를 각각 켜 출처·시각·단위·색상 눈금이 맞는지 확인한다.
- 안전 API 실패를 의도적으로 모의해 `자료 확인 불가`가 보이는지 확인한다.
- 닫힌 검색·메뉴가 키보드 탭 순서에서 빠지는지 확인한다.
- 모바일 닫기 버튼의 실제 hit area가 최소 44×44px인지 확인한다.
- 변경 파일만 S3에 올리고 올바른 Content-Type을 지정한다.
- `sw.js`와 HTML은 `Cache-Control: no-cache`를 확인한다.
- CloudFront 무효화 후 운영 URL에서 바뀐 문구·동작·응답 헤더를 확인한다.

## 11. 커밋 제목 예시

이 저장소 규칙대로 `무엇이 잘못돼 있었나`를 한국어로 적는다.

```text
태풍 범례와 타임라인이 다른 정보창을 가리고 있었다
기온 화면인데 구름 자료 출처가 표시되고 있었다
안전 자료 장애가 사건 없음처럼 보이고 있었다
검색 결과 일부가 아무 동작도 하지 않았다
위치 요청이 두 번 실행되고 기본 위치가 서로 달랐다
지진 질문 답변에 같은 규모가 두 번 표시되고 있었다
웹푸시가 존재하지 않는 아이콘을 가리키고 있었다
```

각 커밋 본문에는 원인, 사용자에게 보이던 결과, 검증한 화면 크기와 방법을 적는다.
