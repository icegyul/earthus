## 0. 왜 하는가 — PD 가 말한 목적 (2026-09-27, 원문 요지)

1. **v1 과 v2 경계가 모호하다 → v1 이 v2 에 있는 것을 최대한 가져온다.** Intelligence 도, 예보도 v1 에서 된다.
2. **v2 = Simulation.** 3D 지형 지구를 활용하고 **사용자의 AI 를 연결해** 특정 한 가지가 아니라 **다양하게 계산해 보여준다.**
3. v2 에도 **v1 과 같은 메뉴**를 준다.
4. v2 는 3D 지형 지구라서 Simulation 말고도 **무엇을 더 줄 수 있는지** 알린다(§7-3).
5. **가장 큰 이유 = v2 차별화.**
6. **기기 형태는 셋 — PC · 폴더형 스마트폰 · 세로형 스마트폰.** 각각에 맞는 화면 형식을 주고 **메뉴 UI 를 완벽하게 배치해 쓰기 편하게** 하는 것이 가장 큰 목적. 지금은 **창이 너무 많고 크고 답답하고 잘 안 보인다.**
7. **(설치형)** v2 브라우저·앱은 사용자가 미리 내려받는 프로그램이다 → **지도와 지구를 미리 받아 속도를 올리고, 지구 품질을 Living Earth 만큼 끌어올린다.**

### 7-2. 사용자 AI 연결 — 계산형 MCP

## 8. 설치형 v2 (Win·Mac) — 지구 팩 미리 받기 · Living Earth 급 품질 (새 PD 결정)

### 8-1. 원칙
- **웹(v1·v2)**: 지금처럼 스트리밍·LOD. 방문마다 큰 파일 금지(기존 규칙 유지).
- **설치형(Win·Mac 전용 브라우저)**: 설치·업데이트 때 **지구 팩**을 디스크에 받아 둔다 → 첫 화면 즉시, 확대 시 네트워크 대기 없음. GPU 에는 **보이는 영역만** 올린다(LRU·예산은 그대로).
- 실시간 자료(구름·날씨·재난)는 계속 네트워크. 팩은 **느리게 바뀌는 것만.**
