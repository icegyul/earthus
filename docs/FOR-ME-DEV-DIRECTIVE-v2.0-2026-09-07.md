# FOR ME 개발지시서 v2.0 — BEFORE/AFTER + 유료 UX + 실제 화면 구성

작성 2026-09-07 · v1.0(`FOR-ME-DEV-DIRECTIVE-2026-09-07.md`)을 대체. v1.0 의 코드 위치·줄 번호 목록(0.5절)과 STEP 1 부품(2절)은 그대로 유효하며 여기서 참조한다.
정본 우선순위: v5.3 §1.4 > `MARITIME-INTELLIGENCE-PRODUCT-SPEC-2026-09-06.md` > 이 문서 > `V1-V2-UPSELL-MAP-2026-09-06.md`(매핑표는 이 문서에 맞춰 개정됨)

## 0. 왜 v2.0 인가

v1.0 은 "기존 화면은 그대로, 맨 아래 한 줄 추가, 그 줄 뒤를 잠근다"였다. 퍼널 실험으로는 맞지만 상품으로는 약하다. 사용자가 보는 것은 **문장 하나**이고, "돈 내면 정확히 뭘 더 아는데?"가 안 보인다. (PD 지적 2026-09-07)

v2.0 의 정의는 세 줄이다.

```
FREE          = 무슨 일이 일어났는지 보여준다          (정보)
EXPLORER      = 내게 언제, 왜 영향을 주는지 보여준다    (답)
INTELLIGENCE  = 얼마나 확실한지, 무엇이 달라졌는지,
                실제로 맞았는지 보여준다               (판단에 필요한 분석)
```

**유료의 이유(정정)**: ~~"내가 누른 질문이 잠겨 있다"~~ → **"무료는 현재 상태를 보여주고, 유료는 언제·왜·얼마나 확실한지·무엇이 달라졌는지를 보여준다."**

유료의 핵심은 예보 한 장이 아니라 **내가 보는 사건의 분석이 시간이 지나며 어떻게 바뀌는지를 계속 추적해 주는 것**이다. 공식 사실은 팔지 않는다. EARTHUS 가 여러 자료를 해석해 만든 부가가치만 유료다.

## 1. 단계 구조와 요금제 매핑

```
V1 공식 정보            →  MY IMPACT          →  WHEN · WHY        →  INTELLIGENCE                         →  CONTINUOUS MONITORING
현재 값·공식 발표·뉴스      내 위치 영향 여부       언제 + 왜             + 얼마나 확실 + 무엇이 달라짐 + 근거 + 과거 검증   변화가 생기면 알려줌
FREE                      FREE                  EXPLORER            INTELLIGENCE                             EXPLORER(기본) / INTELLIGENCE(변화 추적)
```

- 요금제 이름(`explorer` / `intelligence`)은 v5.3·`billing.sql`·`access-mode.js` 그대로. **바꾸지 않는다.**
- 화면에는 요금제 이름 대신 **단계 이름**을 쓴다: `MY IMPACT` · `WHEN · WHY` · `INTELLIGENCE`. 단계에서 구독 상품으로 연결한다(§9 결정 1).
- FOR ME 는 단계 이름이 아니라 **EARTHUS 전체를 관통하는 공통 기능의 이름**이다. 모든 메뉴에서 MY IMPACT 로 들어가는 문이 FOR ME 다.

## 2. BEFORE → AFTER (상품 관점)

### BEFORE — 태풍을 알고 있다
```
태풍 13호
현재 위치 · 중심기압 · 최대풍속 · 이동방향 · 발표기관 · 발표시각
관련 뉴스 · 공식 링크 · 설명 · 공유 · 안전 행동
```
(요소 전체 목록과 코드 줄은 v1.0 §0.5. **하나도 지우지 않는다.**)

### AFTER — 태풍이 나에게 어떤 의미인지 안다
```
① 내 위치              부산                                  FREE
② 영향 여부            영향 가능성 있음                        FREE
③ 언제                 09/09 18:00 ~ 09/10 06:00 · 최대 23:00 ± 6h   EXPLORER
④ 왜                   태풍 접근 + 강풍 + 파고 상승             EXPLORER
⑤ 얼마나 확실한가       높음 — 기관 3/3 일치 · 멤버 51/64 접근    INTELLIGENCE
⑥ 이전보다 어떻게 바뀌었나  6시간 전보다 약 7시간 앞당겨짐          INTELLIGENCE
⑦ 실제로 맞았나         과거 분석 기록 · 시작 +2.1h · 최대 +0.8h   INTELLIGENCE
```

### 메뉴별 AFTER 한 줄
| 메뉴 | AFTER 에서 답하는 것 |
|---|---|
| 태풍 | ①~⑦ 전부 |
| 지진 | ① ② + 앞으로 7일 여진 기대(③④) + 기관 일치(⑤) + 규모 개정 이력(⑥) + 실제 여진 수(⑦) |
| 쓰나미 | ① ②(기관 구역 포함/미포함만) + 내 위치 도달시간 SIMULATION_ONLY(③) + 경로 수심(④) + 게시문 ETA 대조(⑤) + 게시문 개정 간 차이(⑥) + 조위계 실측 대조(⑦) |
| 해양(파고) | ① ② + 임계 초과 구간(③) + 너울/풍파/바람(④) + 모델·부이 차이(⑤) + 직전 주기 대비(⑥) + 부이 실측 대조(⑦) |
| 날씨(특보) | ① ② — **특보는 기관 발표라 전부 무료.** 유료는 원인 설명(④, 근거 게이트 통과 시)만 |
| 대기질 | ① ② + 원인(④, 장거리 이동 vs 국내 — `atmos-transport-spike`) |
| 검색 | 동네 등록만 |

## 3. 실제 화면 구성

### 3.1 MY IMPACT (FREE) — 한 줄이 아니라 **영역**

**v2 내 장소 탭** (`main.js:3285` 앞, 사건마다 카드 1장)
```
┌ MY IMPACT · 부산 ───────────────────────── 태풍 13호 ┐
│ 🟠 영향 가능성 있음                                     │
│ 판단 기준    공식 태풍 예보의 강풍역 안 (KMA 09/07 03시)  │
│ 영향 가능성  있음                                      │
│ 상태         감시 중 · 다음 판정 = 앱 열 때·⟳ 때        │
│ [ 내 영향 자세히 보기 → WHEN · WHY ]                    │
└──────────────────────────────────────────────────┘
```
- 판단 기준은 **기관 이름·발표시각**까지 쓴다. 우리가 지어낸 게 아니라 공식 범위에 들어 있다는 사실이다.
- 신호 없음: `🟢 지금은 영향 신호 없음 · 판단 기준 …` 같은 구조, 버튼은 `[ 감시 조건 보기 ]`.
- 자료 없음: `⚪ 판단 불가 — 원천 응답 없음`. 안전으로 바꾸지 않는다.

**v1 시트 7개 · v2 사건 방 · v2 해양 카드** — 같은 영역의 **미니 블록**(3행 + 버튼). 새 fetch 없음.
```
MY IMPACT · 부산      🟠 영향 가능성 있음
판단 기준             공식 예보 강풍역 안
[ 내 영향 자세히 보기 ]
```
위치는 v1.0 §0.5 의 "한 줄" 자리와 같다(안전 행동 버튼 위). 쓰나미 시트는 "기관 발표 구역에 포함/미포함"만 쓴다.

### 3.2 WHEN · WHY (EXPLORER)

```
┌ 부산 · 태풍 13호 영향 분석 ─────────────────────────── WHEN · WHY ┐
│ 예상 영향 시간        09/09 18:00 ~ 09/10 06:00                        │
│ 가장 가능성 높은 구간  09/09 23:00 ± 6시간                              │
│                                                                    │
│ 왜 영향을 받나                                                       │
│  ① 태풍 접근      최근접 거리 약 120 km (09/09 23시, KMA 예보)          │
│  ② 강풍 증가      동네예보 풍속 14 m/s 이상 09/09 20시~                 │
│  ③ 유의파고 증가   해양 모델 3.4 m (임계 2.0 m)                         │
│                                                                    │
│ 예상 변화                                                            │
│  지금        🟡 관심                                                 │
│  12시간 후   🟠 영향 가능성 증가                                       │
│  24시간 후   🔴 최대 영향 구간                                         │
│  36시간 후   🟠 약화                                                  │
│                                                                    │
│ INTELLIGENCE 에서 더 보기                                            │
│   얼마나 확실한가 · 무엇이 달라졌나 · 근거 그래프 · 과거 검증             │
│   [ INTELLIGENCE 로 분석하기 ]                                        │
└────────────────────────────────────────────────────────────────┘
```
- 시각은 **구간 + 최대 구간(±6h)**. ±6h 는 공식 예보 시각 간격(12·24·36·48·72h)을 보간한 데서 오는 폭이다. 이 폭을 숨기지 않는다.
- 원인 세 줄은 각각 **어느 자료의 어느 값** 때문인지 적는다.
- 하단 목록은 잠긴 내용을 **미리 보여준다**. "상세 분석 🔒" 한 단어는 금지.

### 3.4 CONTINUOUS MONITORING

기존 감시 카드(`main.js:3275`, `watch.js` 조건 3종)에 FOR ME 조건을 **더한다**.
| 조건 | 층 |
|---|---|
| 내 동네 MY IMPACT 가 없음 → 있음으로 바뀜 | EXPLORER |
| 예상 영향 시작이 ±3h 이상 움직임 | INTELLIGENCE |
| 신뢰 등급이 한 단계 이상 바뀜 | INTELLIGENCE |
| 사건 종료 후 분석 성과가 나옴 | INTELLIGENCE |
- 판정 시점은 감시 카드 원칙 그대로: **앱 열 때·⟳ 때**. 닫혀 있는 동안은 판정하지 않는다.
- 푸시는 `push-tick` 경로. ⚠️ **`PUSH_TICK_URL`/`PUSH_TICK_TOKEN` 이 아직 설정 전**이라 지금은 로그만 남고 알림은 안 간다(§9 결정 4).

## 5. 계산 사양 (현상별)

원칙: **사용자별 서버 저장 없이, 입력 아카이브를 같은 함수로 재계산해 이력을 만든다.** 계정이 없어도, 개인정보를 남기지 않아도 WHAT CHANGED 와 HISTORY 가 나온다. 계산은 v2 클라이언트(`prototype/v2-three/js/for-me-signal.js` 신설)에서 S3 JSON 을 읽어 한다. 검증(§5.6)만 서버 잡이다.

### 5.1 태풍
| 항목 | 방법 | 원천 | 상태 |
|---|---|---|---|
| 신호 | 공식 예보 어느 시각이든 내 동네가 **방위별 강풍역** 안 | `events/typhoon-official.json` (강풍역·폭풍경계역, 방위별 반경) | 있음 |
| WHEN | 예보 시각 사이를 선형 보간, 강풍역 진입 첫 시각~이탈 시각, 최근접 시각 ± 6h | 같음 | 계산 신설 |

### 5.5 특보·대기질
- 특보: 신호·시간 모두 기관 발표 → **전부 무료**. 유료 항목은 원인 설명뿐이며 `earthus-llm` 근거 게이트를 통과한 문장만 쓴다. 통과 못 하면 항목을 노출하지 않는다.
- 대기질: 신호는 관측소 등급. 원인(장거리 이동/국내)은 `atmos-transport-spike` 산출물 확인 후.

### 5.6 HISTORY·VERIFY 의 저장 원칙
- 우리 판단 기록 = **입력 아카이브 + 같은 함수**. 서버에 사용자별 결과를 저장하지 않는다.
- 필요한 아카이브: 태풍 공식(있음) · ENS(있음, `archive/tropical-intelligence/`) · 파고(**추가**) · 부이/AWS 관측(**확인**) · 게시문 개정(**확인**).
- 검증 잡 `aws/forme-verify`(신설): 사건 종료 후 관측 최대값·시각을 사건별로 `intel/forme-verify/<eventId>.json` 에 남긴다(지점 = 관측소, 사용자 무관). 클라이언트가 내 동네 최근접 관측소로 분석 성과를 계산한다.

## 6. 정직성 규칙 (v1.0 §1 에 더함)

1. 신뢰는 **등급 + 이유**. 보정 확률(%)을 만들지 않는다. 일치 개수는 원시 개수로 쓴다("51/64", "3/3"). PD 가 %를 원하면 **"일치율"**로만 표기하고 "확률"이라 쓰지 않는다(§9 결정 2).
2. 시각에는 항상 폭(±)을 붙인다. 폭의 출처(예보 간격·격자 크기)를 한 줄로 쓴다.
3. 자료가 없는 항목은 화면에서 **뺀다**. "준비 중"·"—" 로 채우지 않는다. WHY ENGINE 의 미사용 자료만 "○ 미사용"으로 남긴다.
4. 기관 발표는 전부 무료. 우리 계산은 상태만 무료. 특보 시트에서 특보 시각을 가리지 않는다.
5. 쓰나미 시트에는 우리 해석을 한 줄도 넣지 않는다. ETA 는 v2 INTELLIGENCE 안에서만, SIMULATION_ONLY 배지와 함께.
6. 사용자별 서버 저장 없음. 이력은 아카이브 재계산.
