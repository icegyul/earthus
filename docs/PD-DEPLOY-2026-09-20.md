## 1. 🔴 공개 날씨 API 키 원장 → 비공개 (먼저 할 것)

`https://earthus.net/public-api/keys.json` 이 지금도 **HTTP 200** 이다(2026-09-20 03:5x 확인). 09-16 부터 열려 있었다.

**순서를 지킨다.** 먼저 배포하면 새 코드가 `archive/` 에서 키를 찾는데 원장이 아직 `app/` 에 있어 **모든 키가 거절된다.**

```bash
# ① 옮긴다 (mv = 복사 후 원본 삭제, 그래서 app/ 쪽은 따로 지울 필요가 없다)
aws s3 mv s3://earthus-cache-kr/app/public-api/ s3://earthus-cache-kr/archive/public-api/ --recursive --region us-east-2

# ② 옮겨졌는지 본다 (아래가 성공해야 한다)
aws s3api head-object --bucket earthus-cache-kr --key archive/public-api/keys.json --region us-east-2

# ③ 배포 (이 스크립트가 ② 를 한 번 더 확인하고 나서 배포한다)
bash tools/deploy-queue-2026-09-20.sh public-api

# ④ CloudFront 에서 옛 응답을 지운다
aws cloudfront create-invalidation --distribution-id E193CZEBLWEB56 --paths '/public-api/*'

# ⑤ 몇 분 뒤 403 또는 404 여야 한다
curl -s -o /dev/null -w '%{http_code}\n' https://earthus.net/public-api/keys.json
```

**⑥ 노출됐던 키는 폐기하고 새로 발급한다.** 이건 코드가 아니라 사람 일이다 — 발급 대상에게 새 키를 전달해야 한다.
발급 도구: `python aws/public-weather-api/add_key.py`. ⚠️ 키 값을 채팅·로그·커밋에 남기지 않는다.
