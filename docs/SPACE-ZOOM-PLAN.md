# 지구 → 우주 줌아웃 — 개발 계획 (검토판)

작성 2026-08-07 · 판단·계획 Claude(Fable) / 제작 Codex
받은 요청: "지구에서 계속 멀어지면 우주로 — 허블·제임스웹 사진을 좌표에,
더 뒤로 가면 태양계(행성 실시간), 더 가면 은하수, 더 가면 나선은하.
화살표로 안내하고 메뉴도 단계에 맞게 바뀌게. **무겁지 않게.**"

---

## 0. 결론 먼저

**만들 수 있다. 단, 한 덩어리가 아니라 "장면(Scene) 사다리"로 만들어야 가볍다.**

- Cesium 하나로 태양계까지 가려는 순간 무거워지고 좌표가 깨진다.
  → 지구 장면(지금 것)과 태양계 장면(새로 만드는 가벼운 것)을 **크로스페이드로 갈아탄다.**
- 행성 "실시간 위치"에 **API 가 필요 없다.** 케플러 궤도요소 계산은 5KB 수학이다.
  네트워크 0회. PD가 조사한 JPL Horizons 는 **검증용(오프라인)** 으로만 쓴다.
- 허블·제임스웹 사진은 런타임에 MAST/ESASky 를 부르지 않는다.
  **Lambda 가 미리 큐레이션한 카탈로그 JSON 하나**(수십 KB)를 받는다.
- 은하수·나선은하 단계는 **자료가 아니라 그림**이다. 우리 은하를 밖에서 찍은
  사진은 존재하지 않는다 — **"상상도" 라벨을 반드시 붙인다.** (아래 §1)

현재 실측 제약 (2026-08-07 코드 확인):
- `viewer.js:124` 카메라 상한 **45,000 km** — 달(384,000km)에도 못 간다. 단계별로 풀어야 한다.
- ICRF(천구 좌표) 변환 코드 없음 — 사진 마커에 새로 필요 (스파이크 P0-2).
- 위성 궤도는 9,000km 부터 자동 표시(SAT_SHOW) — S1 단계가 **이미 있다.**

## 1. 이 기능의 정직성 원칙 ⚠️

이 앱은 "없는 것을 있다고 하지 않는다"로 여기까지 왔다. 우주는 그 원칙이
제일 쉽게 무너지는 주제다. 시작 전에 선을 긋는다.

| 항목 | 원칙 |
|---|---|
| 허블·JWST 사진 위치 | RA/Dec 는 **하늘의 방향**이지 3D 공간의 점이 아니다. 사진 마커는 지구를 둘러싼 **천구(하늘 구면)** 위에 놓는다. 3D 공간에 가짜 깊이로 띄우지 않는다. 알려진 거리(광년)는 정보창에 숫자로 적는다. |
| 행성 위치 | 케플러 근사(JPL 공개 궤도요소)는 수백 년 범위에서 분 단위 각도 오차 — 화면 픽셀보다 작다. "실시간"은 **시각 기준 계산**이지 프레임 애니메이션이 아니다 (행성은 느리다 — 1분에 한 번 다시 계산해도 그림이 같다. 발열 0). |
| 은하수 밖 시점 | **존재하지 않는 사진이다.** NASA/ESA 공식 상상도(artist's impression)를 쓰고 화면에 "상상도 · NASA/ESA" 라벨을 박는다. "당신은 여기" 화살표(태양은 은하 중심에서 약 2만 6천 광년)는 실제 추정치이므로 함께 표기. |
| 나선 소용돌이 애니메이션 | ⚠️ PD가 첨부한 참고 영상(태양이 나선을 그리며 날아가는 것)은 유명하지만 **천문학적으로 과장된 연출**로 여러 천문학자가 지적한 바 있다(궤도면 기울기·속도 비율 왜곡). 태양의 은하 공전을 보여주려면 올바른 기울기(~60°)로 그리고, 연출임을 밝힌다. 그대로 베끼지 않는다. |
| 사진 저작권 | NASA/STScI 는 퍼블릭 도메인에 준하나 **크레딧 표기 요구**("NASA, ESA, CSA, STScI"), ESA/Webb 은 CC BY 4.0. 사진마다 크레딧을 정보창에 넣는다 — 이미 모든 레이어가 출처를 표기하는 앱이라 틀은 있다. |

## 2. 장면 사다리 — 5단계

```
S0 지구        (지금 앱 그대로)                     0 ~ 45,000 km
S1 궤도권      위성·궤도 (이미 있음, SAT_SHOW)       9,000 km ~
S2 하늘 사진   허블·JWST 마커가 천구에 나타남         45,000 ~ 200만 km   ← 카메라 상한 해제
─── 장면 전환 (크로스페이드) ───────────────────────
S3 태양계      행성 8 + 달 + 궤도선, 실시간 위치       별도 경량 장면
S4 은하수      상상도 + "태양은 여기" 화살표           〃 (로그 줌)
S5 국부은하군~ 나선은하 상상도 + 짧은 설명 카드         〃
```

### 단계 전환 규칙
- **내려갈 때(줌인)는 역순으로 자연스럽게.** 어느 단계에서든 지구를 누르면 S0 로 복귀.
- 전환은 카메라 거리 임계값 + 1.2초 크로스페이드. 임계 부근에서 덜컥거리지 않게
  히스테리시스(올라갈 때/내려갈 때 임계를 다르게) 를 둔다 — store.mode 가 이미 쓰는 방식.
- **화살표 안내(받은 요청)**: 각 단계에서 화면 가장자리에 "더 멀리 ↑" 힌트 1개.
  S2 에서 처음 사진 마커가 보이면 코치마크 1회 ("사진을 눌러 보세요") — 기존 coachDone 틀 재사용.

### 오른쪽에 "스케일 자" (신규 UI)
지구 ─ 달 ─ 태양계 ─ 은하수 ─ 은하들 세로 눈금. 지금 어디인지 표시되고,
누르면 그 단계로 비행. 로그 스케일이라 "우주가 얼마나 넓은지"가 그 자체로 교육 콘텐츠다.

## 3. 데이터 계획 — PD 조사 API 판정

| PD가 조사한 것 | 판정 | 이유 |
|---|---|---|
| JPL Horizons | **오프라인 검증용만** | 런타임 호출 불필요 — 행성 위치는 클라이언트 케플러 계산(JPL 이 공개한 궤도요소 표, ~5KB)으로 충분. Horizons 는 월 1회 Lambda 로 우리 계산과 대조하는 채점용 |
| ESA PSA / Gaia | **안 씀** | 탐사선 관측자료·항성 카탈로그 — 이번 기능 목적과 다름 |
| SIMBAD / VizieR | **큐레이션 보조만** | 사진 대상의 거리·형태 메타데이터를 채울 때 오프라인에서 |
| KASI | **안 씀** (이 기능에는) | 일출·월령용. 행성 3D 좌표 없음 — PD 판단대로 |
| **MAST** | **큐레이션 원천 ①** | Lambda(`space-catalog`)가 큐레이션할 때만 호출. 런타임 아님 |
| jwstapi.com | ⚠️ **의존 금지** | 비공식 — 서비스 연속성 보장 없음. 우리 원칙(확인 안 된 외부에 기대지 않기)상 런타임 의존 불가. 큐레이션 참고까지만 |
| ESASky | **큐레이션 원천 ②** | "이 좌표 근처에 무슨 사진 있나" 오프라인 질의용 |

### 새 Lambda 1개 — `space-catalog` (주 1회)
```
MAST/ESASky → 유명 관측 150~300장 선별
  → { name, ra, dec, distanceLy(있으면), telescope, date,
      thumbUrl(우리 S3 캐시), fullUrl, credit } 
  → S3: space/catalog.json (gzip ~40KB) + 썸네일 256px 캐시
```
⚠️ 첫 판은 자동 수집이 아니라 **손 큐레이션 50장**으로 시작한다 (창조의 기둥,
딥필드 등). 유명 사진은 목록이 안 바뀌므로 자동화는 나중 문제다. 빨리 눈에 보이는
것부터 — 그리고 한 장 한 장 크레딧을 사람이 확인하고 넣는다.

### 행성 위치 — 네트워크 0
- JPL 공개 케플러 요소(a, e, i, Ω, ω, M + 세기당 변화율) 8행성 + 달 근사.
- `js/space/kepler.js` 순수 함수 ~150줄. 시각을 넣으면 황도좌표가 나온다.
- ⚠️ 검증 없이는 못 내보낸다: Horizons 값과 8행성 × 4시점 대조를 P2 완료 조건으로.

## 4. 렌더링 — 왜 장면을 가르나

**Cesium 을 태양계까지 끌고 가면 안 되는 이유 둘:**
1. 좌표가 지구 중심 미터계다. 해왕성 거리(45억 km)면 배정밀도 한계로 카메라 지터가 난다.
2. 지구 타일 엔진이 계속 살아 있으면 안 보이는 지구를 위해 GPU 가 돈다 — 발열 규율 위반.

**S3~S5 는 별도 경량 장면:**
- 캔버스 하나에 WebGL 없이도 그릴 수 있는 수준 (점 9개 + 타원 8개 + 배경 그림 2장).
  Three.js 도 과하다. 기존 layerbar 미리보기 캔버스 그리듯 **2D Canvas** 로 시작 →
  부족하면 그때 올린다.
- 전환 순간 Cesium 은 `requestRender` 중단 + 캔버스 숨김 (파괴하지 않는다 —
  재진입이 잦은 UI 라 재생성 비용이 더 크다). 복귀 시 반대로.
- 애니메이션 규율: 태양계 장면도 **정지 화면**이다. 시각이 바뀌면 다시 그린다.
  "재생" 버튼을 누른 동안만 시간이 흐른다 (태풍 타임라인과 같은 문법).

### S2(하늘 사진)는 Cesium 안에서
- 마커는 천구 반지름(예: 지구 중심에서 30만 km) 구면 위 빌보드.
- RA/Dec → 지구고정좌표 변환은 `Cesium.Transforms.computeIcrfToFixedMatrix` 사용.
  ⚠️ 매 프레임이 아니라 **카메라가 멈췄을 때 1회** 갱신 (onCameraIdle 재사용).
- 카메라 상한을 S2 진입 시에만 200만 km 로 올리고, S0 복귀 시 원복.

## 5. 메뉴 — 단계에 따라 바뀌는 것 (받은 요청)

### 원칙 셋

1. **메뉴를 갈아치우지 않고 거른다.** layerbar 에 장면 필터 한 겹만 얹는다.
   새 메뉴 시스템 금지 — 같은 자리, 같은 문법, 내용물만 단계에 맞게.
2. **켜 둔 지구 레이어를 지우지 않는다.** 우주에서 지구 레이어는 무의미하지만,
   끄면 사용자가 돌아왔을 때 고른 것이 사라진다 (loadLayerState 철학 위반).
   → 메뉴에서 **"지구 레이어 3개 켜짐 · 돌아가면 보입니다"** 한 줄로 접는다.
   상태는 보존, 표시만 접기.
3. **안전 감시는 우주에서도 끄지 않는다.** 쓰나미·큰 지진 배너는 어느 단계에서든
   뜬다 — "레이어를 끄는 것은 감시를 끄는 게 아니다"의 우주판.
   배너를 누르면 그 자리로 지구 복귀 비행.

### 어느 단계에서든 항상 남는 것

검색(⌘K) · 설정 · **지구로 돌아가기**(우주 단계에서 맨 위 고정) · 스케일 자 · 안전 배너

### 단계별

| 단계 | 메뉴(2단 시트) | 하단 빠른 칩 | 비고 |
|---|---|---|---|
| S0 지구 | 지금 그대로 | 지금 그대로 | 변화 없음 |
| S1 궤도권 | 지금 그대로 (위성 궤도가 자동 표시될 뿐) | 〃 | 메뉴 변화 없음 — 이미 있는 단계 |
| S2 하늘 사진 | **우주 사진**(신설): 허블 · 제임스웹 · 전체 / **위성**(기존 satcat 묶음) / 오로라(기존) / 달 표시 / ▸지구 레이어 접힘 줄 | 허블 · JWST · 위성 · 달 | ⚠️ 달: `scene.moon.show` 이 지금 꺼져 있다(viewer.js:93) — S2 진입 시 켠다. 38만 km 를 지나는데 달이 없으면 이상하다 |
| S3 태양계 | **태양계**(신설): 행성 이름표 · 궤도선 · 황도면 격자 · **실제 크기 비율** 토글 / ▸지구 레이어 접힘 줄 | 이름표 · 궤도선 · ▶시간 재생 | 시간 재생은 태풍 타임라인과 같은 문법(스크러버+재생). ⚠️ "실제 크기 비율"을 켜면 행성이 점이 된다 — 기본은 과장 크기 + **"크기 과장됨" 라벨 상시** |
| S4 은하수 | 레이어 없음 — **콘텐츠 카드**: 우리 은하 · 태양의 자리 · (상상도 출처) | 없음 (스케일 자만) | 토글할 자료가 없는데 억지 메뉴를 만들지 않는다 |
| S5 은하들 | 콘텐츠 카드: 국부은하군 · 관측 가능한 우주 (여기서 끝) | 〃 | "더 밖은 없습니다 — 여기가 우리가 아는 끝입니다" 카드로 마무리 |

### 사진 정보창 (사진 마커 클릭 — 기존 시트 틀 재사용)

큰 이미지 · 대상명 · 망원경 · 촬영일 · 거리(알려진 것만, 광년) · **크레딧(필수)** · 원본 링크

### 시간 메뉴의 뜻이 단계마다 다르다 ⚠️

S0 의 시간(지금/내일 최고·최저)과 S3 의 시간(행성 위치 재생)은 다른 것이다.
같은 자리에 두되 이름을 다르게 — S3 진입 시 "행성 시간"으로 제목이 바뀐다.
섞이면 "내일 최고 기온" 자리에서 행성이 움직이는 이상한 화면이 된다.

### 나중 후보 (지금 안 함)

별자리 선(S2) · "오늘의 우주" 프리셋 — P4 이후 반응 보고.
(탐사선(제임스웹·보이저)은 나중 후보에서 **승격됨** — 받은 결정, EXPLORE-DEV-SPEC B3-탐사선.)

| **P3 은하 단계** | 상상도 2장 + "여기" 화살표 + 상상도 라벨 | 라벨 없이 통과 불가 | 반나절 |
| **P4 스케일 자 + 메뉴 필터 + 화살표 안내** | UI 마감 | 코치마크 1회만, 접근성(키보드) | 1일 |
| **P5 성능 검증** | 발열·메모리 전수 (기존 감사 방식) | 정지 시 GPU 유휴 확인 | 반나절 |

P1 이 끝나면 그 자체로 배포 가치가 있다 ("지구를 벗어나면 허블 사진이 뜬다").
P2 부터는 P1 반응을 보고 이어가도 된다.
