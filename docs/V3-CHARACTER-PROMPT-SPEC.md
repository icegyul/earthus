■ 0. 가장 먼저 — 이미지 작업은 캐릭터당 2개다

기존 문서는 이미지 작업이 3개였다(마스터 시트 / 투명 3-4 / 파츠 아틀라스).
실측 결과 이미지 모델은 "분리 파츠 아틀라스"를 만들지 못한다.
3열×2행으로 머리·몸·팔다리를 떼어 놓으라고 했더니 통짜 캐릭터 두 개가 나왔다.

파츠는 코드가 단일 3/4 이미지 한 장에서 잘라 만든다. 그래서 파츠끼리 어긋날 수
없다 — 같은 그림에서 나오기 때문이다.

  작업 1  4방향 마스터 시트  → 승인 기준용. 지구에 올라가지 않는다.
  작업 2  단일 3/4 전신      → 이것이 실제로 지구에 서는 그림. 가장 중요하다.
  작업 3  파츠 아틀라스      → 코드가 한다. 프롬프트를 쓰지 말 것.
  작업 4  manifest.json     → 코드가 한다.
  작업 5  썸네일 512px      → 코드가 한다.

문서에서 작업 3~5의 프롬프트 상자를 지우고 "코드가 생성한다"로 바꿀 것.


■ 1. 배경

작업 1 (4방향 마스터 시트)
  불투명. 평평한 아이보리 단색.
  이 시트는 승인 기준이라 지구에 올라가지 않는다. 배경색은 중요하지 않다.

작업 2 (단일 3/4)  ★ 여기가 핵심
  투명 배경(PNG 알파)으로 요청한다.
    "완전히 투명한 배경. 캐릭터만 있고 배경에는 아무 픽셀도 칠하지 않는다."
  캐릭터 발밑에 그림자를 그리지 않는다. 그림자는 코드가 타원으로 따로 그린다.

  ⚠️ 받은 뒤 반드시 확인한다 — 진짜 투명인지, 체크무늬를 그려 넣은 것인지.
     모델이 투명 대신 회색 격자를 "그림으로" 칠해 놓는 일이 있다. 눈으로는
     투명해 보이지만 알파가 없다. 이미지 편집기에서 배경을 지웠을 때 격자가
     그림으로 남으면 실패다.

  ⚠️ 투명이 안 나오면 그때만 크로마 단색으로 다시 뽑는다. 코드가 그 색을 떼어낸다.
     "웜 그레이 단색"은 쓸 수 없다 — 흰·아이보리 캐릭터와 색으로 구분이 안 된다.
     (실측: 흰 예티의 배 254, 흰 배경 253.7. 떼어내면 배가 뚫린다.)
     캐릭터 안에 없는 계열의 진한 색을 캐릭터마다 정한다.
       마젠타 : 예티 · 해태 · 갓파 · 골렘 · 네시 · 빅풋 · 늑대인간 · 재칼로프
       초록   : 도깨비(붉은 피부) · 모스맨(붉은 눈) · 몽골리안 데스웜 · 이무기


■ 2. 프롬프트 문법 — 부정문 금지

"글자가 없어야 한다", "배경이 없어야 한다", "그림자를 넣지 마라" 같은 문장을
프롬프트에 쓰지 않는다. 이미지 모델에서 부정문은 오히려 그것을 불러온다.
(실측: 그 문장을 넣은 시트 두 장 모두 상단에 제목 글자가 박혔고, 한글판은
 "헤발라아의 예티"라는 오타까지 났다.)

원하는 것을 직접 지정하는 문장으로만 쓴다.
  나쁨 : "배경에 아무것도 없어야 한다"
  좋음 : "배경 전체가 완전히 투명하다. 캐릭터 바깥은 한 픽셀도 칠하지 않는다."

기존 문서의 재질 문단("두께 2~3mm 의 무광 수제 색지와 고급 카드지…")은 이미
이 문법이고 아주 잘 먹혔다. 글자 하나 바꾸지 말 것.
작업 1과 작업 2의 재질·화풍 문단은 완전히 같아야 한다.

■ 4. 고를 수 있는 동작 — 이 10가지 외에는 없다

  jump    폴짝 뛰기        spin    빙글 돌기        wave   손 흔들기
  nod     고개 끄덕        wiggle  살랑살랑         bounce 통통 튀기
  rear    앞발 들기        flap    날갯짓           coil   몸 세우기
  stomp   쿵쿵 걷기

손이 닿을 때마다 목록의 다음 동작으로 넘어간다. 세 번 누르면 세 가지를 본다.
"걷기·헤엄·하울링·땅속 이동" 같은 이름은 엔진에 없다. 위 이름으로 바꿔 적을 것.

리그별 기본값 (그대로 써도 된다)
  BIPED_PAPER      jump, spin, wave, nod, wiggle      (5개)
  QUADRUPED_PAPER  jump, rear, nod, wiggle            (4개)
  SERPENT_PAPER    coil, wiggle, spin, nod            (4개)
  FLYER_PAPER      flap, jump, spin, nod              (4개)

캐릭터 성격에 맞게 바꿔도 되지만 반드시 3~5개, 위 목록 안에서만.
예: 골렘은 stomp 를 넣고 spin 을 뺀다. 도깨비는 bounce 를 넣는다.


■ 5. 작업 1 — 4방향 마스터 시트

기존 문서의 프롬프트를 거의 그대로 쓴다. 두 군데만 고친다.
  · "배경" 문장을 "배경 전체가 평평한 아이보리 단색이다"로
  · 부정문("이름이나 글자가 없어야 한다")을 지운다.
    글자를 막는 것은 프롬프트가 아니라 승인 단계다 — 글자가 있으면 반려한다.

네 뷰: 완전한 정면 / 왼쪽 3-4 / 완전한 왼쪽 측면 / 완전한 후면.
같은 기준선 위, 같은 크기, 중립 자세, 중립 표정.


■ 6. 작업 2 — 단일 3/4 (가장 중요)

반드시 들어갈 조건
  · 3/4 방향 전신 한 명, 화면 가운데, 사방에 넉넉한 여백
  · 서 있는 중립 자세.
    ★ 뛰거나 팔을 들거나 웃긴 자세로 만들지 말 것 — 움직임은 코드가 만든다.
      한 장으로 10가지 동작을 다 하기 때문에 자세가 중립이어야 성립한다.
  · 배경 전체가 완전히 투명
  · 작업 1에서 승인한 마스터 시트를 정체성 기준으로 첨부
  · 재질·화풍 문단은 작업 1과 글자 하나까지 같게
  · 머리·몸통·팔·다리의 경계가 눈으로 구분되게 그릴 것
    (코드가 이 경계를 찾아 파츠로 자른다. 팔이 몸에 완전히 녹아 있으면 못 자른다.)


■ 7. 승인 기준에서 고칠 것

  "배경은 웜 그레이 단색이며 …"
    → "작업 2 의 배경은 완전히 투명하며, 배경을 지웠을 때 격자가 그림으로 남지 않는다"
  "파츠 구조: 머리·몸통·팔다리와 필수 부속의 겹침이 명확하다"
    → 유지. 단 파츠를 따로 그리라는 뜻이 아니라 경계가 눈으로 구분되게 그리라는
      뜻으로 문장을 다시 쓸 것.
  추가할 항목
    · 캐릭터 몸에 그림자가 구워져 있지 않다
    · 이름·글자·워터마크가 없다 (있으면 반려. 프롬프트로 막지 않는다)
    · 받침대·바닥·풍경이 없다

## 이 저장소가 이미 하는 일 (문서 작업자는 몰라도 된다)

- 알파에서 관절을 찾아 파츠 6장으로 자르고, 원래 그림에서의 상대 위치 그대로 세운다
- `characters/{slug}/` 아래 정해진 5개 파일과 manifest 를 만든다
- 동작 10가지와 리그별 기본 목록은 `character-core.js` 의 `MOVES` · `RIG_MOVES` 에 있다
- 손이 닿으면 목록의 다음 동작으로 넘어간다
