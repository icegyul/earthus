| | 어디 | 파일 |
|---|---|---|
| 1 | 설정 · 구독 | `index.html` `#btnSubscribe` → `main.js` 에서 **remove()** |
| 2 | 설정 · 요금제 줄 (`무료` + 구독하기) | `ui.js` `renderTierRow()` |

⚠️ **숨기기(hidden)가 아니라 remove() 입니다.** 숨기면 소스에 남고 키보드 탭에 걸립니다.

`SHOW_SUBSCRIBE` 는 안내 화면으로 가는 문을 막습니다. 지금 둘 다 꺼져 있습니다.
⚠️ **이미 결제한 분에게는** 구독 상태와 [구독 관리]가 그대로 보입니다 (`renderTierRow` 의 `!paid` 조건).

문구도 같이 갈았습니다 — 살 방법이 없는데 "구독하면 열립니다"라고 하면 거짓말입니다.

```
잠긴 레이어  "구독하시면 볼 수 있습니다"  → "아직 준비 중입니다"
무거운 위성  "구독 기능으로 두었습니다"    → "내려받는 양이 커서 아직 열지 않았습니다"
             (이유는 남겼습니다 — 실제로 대역폭·연산 때문입니다)
통과 예보    [구독 알아보기] 버튼          → '준비 중입니다' 한 줄
```

### 2-2. 사전등록 = 창립 멤버 (`SHOW_WAITLIST = true`)

`SHOW_SUBSCRIBE` 와 **별개 스위치**입니다. 돈 받는 문은 닫고 "만들고 있습니다"만 엽니다.

화면 내용 (한국어·영어 둘 다, `i18n.STATIC` 의 `wl.*`):

- 머리글 — "지금은 아무것도 받지 않습니다."
- **출시 때 함께 여는 것** — 항공기·선박 실시간 위치(첫 줄) / 되감기·이력 / 위성 전체 목록 / 알림 20곳
- **창립 멤버 500명에게 드리는 것** — 언제나 정가의 반값 / 먼저 연락 / 계정 표시
- **남은 자리** — "500자리 가운데 N자리 남았습니다"
- **계속 무료인 것** — 태풍·지진·쓰나미, 구름·날씨, 3D 학습
- **결제** — "지금 받는 것은 메일 주소 하나뿐입니다."
- 하단에 **약관 제8조 제7항** 링크

⚠️ **항공기·선박 줄에 "지금은 아직 없습니다"를 반드시 남겨 두세요.**
`config.js` 에서 `flight`·`ship` 은 `blocked:'paid'` 이고 자료원이 없습니다.
등록하고 들어왔는데 안 보이면 그게 첫 배신입니다.

⚠️ **값을 숫자로 적지 않았습니다.** 정가가 확정이 아닙니다(`SALES_OPEN=false`).
"정가의 반값"은 정가가 바뀌어도 안 틀리고, 약관과도 같은 말입니다.

### 2-3. 고친 버그 — 남은 자리가 항상 0

`auth.js waitlist.count()` 가 `.from('waitlist').select(count)` 를 쓰고 있었습니다.
`waitlist` 는 RLS 로 **읽기가 막혀** 있어(이메일 목록 보호) 이 방식은
**오류 없이 항상 0** 을 돌려줍니다.

```
RPC waitlist_count()  → 1
기존 코드             → 0        (2026-08-06 실측)
```

선착순 500명을 걸어 놓고 이대로 두면 자리가 다 차도 화면은 500이라고 말합니다.
`schema.sql` 에 있던 `waitlist_count()` RPC 를 쓰도록 고쳤습니다.

⚠️ **못 세면 0 이 아니라 null 이고, null 이면 줄 자체를 감춥니다.**
0 은 마감으로 읽혀서 멀쩡한 자리를 닫아 버립니다.

### 2-4. 덤 — placeholder 가 번역되지 않고 있었음

`applyStatic()` 이 `textContent` 만 건드려서 `placeholder` 는 영어 화면에서도 한국어였습니다.
`data-i18n-ph` 처리를 넣었습니다. 사전등록 이메일칸뿐 아니라
**통합 검색창**("장소 · 레이어 · 기능 검색")과 **질문창**("지금 태풍 어디야?")도 그랬습니다.

## 3. 약관 — 이미 라이브

종전 약관이 화면의 약속과 **정반대**였습니다.

```
제2조 5항  "종전의 창립 멤버 요금제는 폐지. 배지는 요금제와 무관한 별개"
제8조 7항  "⚠️ 영구적 권리를 부여하는 것은 아닙니다"
```

`legal/terms.ko.md` 개정 (부칙에 사유 기재):

- **제2조 제6항 신설** — 창립 멤버 = 사전등록 **선착순 500명**.
  별도 요금제가 아니라 **할인 자격**. 순번은 `waitlist.created_at`.
- **제8조 제7항 신설** — **정가의 50%**. 정가가 바뀌면 **바뀐 정가의 50%**.
  횟수·기간 제한 없음. 서비스 운영 중 유효.
  ⚠️ **이미 창립 멤버가 된 자에게 불리하게 변경하지 않는다** (제3조 예외).
- 종전 7항 → 8항.

⚠️ **정원 500 과 할인율 0.5 는 약관에 적힌 수입니다.**
코드에서만 바꾸면 우리가 우리 약관을 어깁니다. 바꾸려면 약관도 같이 고쳐야 합니다.

## 4. 서버 — 만들었으나 **아직 적용 안 됨**

### 4-1. `supabase/founding.sql` (새 파일)

| 함수 | 하는 일 | 권한 |
|---|---|---|
| `founding_seats()` / `founding_rate()` | 500 / 0.5. **약관에 적힌 수가 사는 유일한 곳** | — |
| `is_founding_email(text)` | 사전등록 순번 ≤ 500 인가 | service_role 만 |
| `guard_profile_columns()` | **교체됨** — 아래 ⚠️ | 트리거 |
| `claim_founding()` | 본인 자격을 굳힌다 | authenticated |
| `price_for(uuid, text)` | **값을 정하는 유일한 곳** | service_role 만 |
| `founding_left()` | 남은 자리 | 모두 |

⚠️⚠️ **`guard_profile_columns()` 를 반드시 같이 적용해야 합니다.**
기존 트리거는 인증된 세션의 update 에서 `founding_member` 를 옛 값으로 되돌립니다.
`claim_founding()` 은 `security definer` 여도 **호출자 세션**에서 돌기 때문에
`auth.uid()`·`auth.role()` 이 그대로 `authenticated` 라 트리거에 걸립니다.
→ **함수는 true 를 돌려주고 값은 false 로 남습니다.** 제일 나쁜 종류의 실패입니다.
거래 안에서만 사는 표식(`app.trusted_write`)을 보고 문을 열도록 바꿨습니다.
PostgREST 로는 임의 SQL 을 못 돌리므로 사용자가 이 표식을 스스로 세울 수 없습니다.

⚠️ `is_founding_email` 을 **anon 에게 주지 마세요.** 남의 이메일을 넣어
"이 사람 가입했나"를 확인하는 조회 도구가 됩니다.

⚠️ `claim_founding()` 은 **이메일을 인자로 받지 않습니다.** 받으면 남의 이메일로
남의 자격을 자기 계정에 붙일 수 있습니다. `auth.uid()` → `auth.users` 로만 찾습니다.
