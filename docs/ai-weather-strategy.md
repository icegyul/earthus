## 0. 기본 판단 — 우리는 어느 쪽인가

영상 속 회사들은 **모델을 만드는 회사**다. 우리는 **모델 산출물을 검증·대조해 보여주는 회사**다.
이 구분이 전략의 전부다.

| 보고서가 제안한 것 | 우리 판단 |
|---|---|
| PyTorch로 4-앙상블 모델 구현 (Step 1~4) | ⛔ **안 한다.** ERA5급 학습 데이터·GPU 클러스터·ML 인력이 없고, 기상법상 예보업무 허가 문제가 생기며, 무엇보다 "우리는 예보 기관이 아니다"는 기존 규율 위반. 보고서의 코드는 장난감 수준이라 실서비스 품질도 안 나온다 |
| 확률적 예보(불확실성 스펙트럼) 개념 | ✅ **차용한다.** 단, 우리가 계산하는 게 아니라 **기관이 만든 앙상블의 스프레드를 표시**한다 |
| What-if 시나리오 (Earth-2) | ✅ if 메뉴(배치 D)의 포지셔닝 어휘로 차용. 단 우리 v1은 시뮬레이션이 아니라 "과거 유사 사례 + 관측값" — 그렇게 정직하게 표기 |
| Coarse-to-Fine 타일 파이프라인 | ✅ **이미 하고 있다.** 지도 타일 레벨 0~9 + 전지구 저해상도/한국 고해상도(관측소 736지점) 구조가 바로 이것. 신규 작업 불필요 |
| AI 모델 산출물 자체 | ✅ **데이터로 소비한다** — 아래 검증 결과 |

## 1. 데이터 소스 검증 결과 (2026-08-02, 직접 확인)

### 🟢 ECMWF AIFS — 최고의 발견. 완전 사용 가능

- **AI 모델(AIFS single/ens)과 물리 모델(IFS)이 같은 버킷, 같은 경로 구조에 나란히 있다** — 실제 디렉터리 열어 확인: `data.ecmwf.int/forecasts/20260801/00z/` 아래 `aifs-ens` `aifs-single` `ifs`
- **CC-BY-4.0, 상업 이용·재배포 명시 허용** ("may be redistributed and used commercially")
- 0.25°, 하루 4회, 15일(360h), GRIB2. AWS S3(`ecmwf-forecasts`, eu-central-1)로도 제공
- ⚠️ 보관 2~3일뿐 — 대조 아카이브를 만들려면 매 런 자체 저장 필요 (기존 verify 아카이브 패턴 그대로)
- ⚠️ attribution 정확한 문구 형식은 구현 전 라이선스 원문 재확인

### 🟢 NOAA FourCastNetGFS — 엔비디아 계열의 유일한 공개 피드

- NVIDIA 자체는 공개 예보 피드가 **없다** (모델·코드만 공개, 실행엔 40~60GB GPU 필요 — 우리에겐 비현실적)
- 대신 **NOAA가 FourCastNet v2 기반 실험 모델 산출물을 CC0으로 공개**: `s3://noaa-nws-fourcastnetgfs-pds`, 하루 4회, 10일, 0.25°, 계정 불필요
- ⚠️ 'experimental' 명시 — 화면에 실험 상태 고지 필수 (우리 정직성 규율과 일치)
- ⚠️ ECMWF는 2026년 5월부로 외부 AI 모델(FourCastNet·Pangu·GraphCast) 차트 제공 종료 — ECMWF 경유 경로는 계획에 넣지 말 것

### 🟡 Google WeatherNext 2 — 한국이 차단 국가다 → ⛔ **제외 결정 (2026-08-02)**

**"가능한 것만 쓴다"** — 서면 합의가 필요한 소스는 안 쓴다. 리그는 ECMWF 쌍 + NOAA로 구성.
(아래 검증 기록은 나중에 사정이 바뀔 때를 위해 남긴다)

- 산출물이 Earth Engine·BigQuery로 공개되지만 **약관이 이원화**: 48시간 지난 데이터 = CC-BY-4.0(상업 가능), **48시간 이내 실시간 = 한국(South Korea)이 Restricted Country로 명시** — 접근도, 한국 내 제공도 금지
- 예외는 Google과 이메일 서면 합의(weathernext@google.com)뿐 → 원하면 **대표님 액션 아이템**
- 48h+ 과거 데이터도 "experimental modelling only, not validated for real world use" 고지 의무
- 가중치는 CC BY-NC-SA(비상업) — 자체 구동 경로도 막힘

### 🟡 Open-Meteo 앙상블 API — 기술은 완벽, 상업은 유료

- **실제 API 호출로 검증**: 서울 좌표, 16일치, 멤버 31개 시계열이 그대로 반환됨. ECMWF AIFS ENS(51멤버)·**Google WeatherNext 2(64멤버!)**까지 앙상블 목록에 있음
- **#12(Open-Meteo 상업 조건) 이걸로 해소**: 무료 티어는 비상업 전용(일 1만 콜). 상업은 유료 구독, **앙상블은 Professional 플랜 이상**(2023년 발표 기준 $99/월, 현 금액은 결제창 확인 필요). 프로토타이핑은 무료로 허용
- ⚠️ Open-Meteo가 중계하는 WeatherNext 2를 한국 서비스가 쓰는 것이 Google 약관의 한국 제한을 우회하는지는 **불명** — 사용 전 확인 필요. 안전하게는 WeatherNext 제외하고 쓰면 됨
- 스프레드(표준편차)는 안 주고 멤버 원시값만 줌 — 폭 계산은 우리 몫(간단)

## 2. 이걸로 만드는 것 — "AI vs 물리모델 리그"

기존 계획 #19(예보 리그)의 확장이자 간판 승격. **아무도 안 하는, 우리 정체성에 정확히 맞는 상품**:

> "구글·ECMWF의 AI가 슈퍼컴퓨터를 이겼다는데, **한국 날씨에서도 그럴까?**
> earthus가 매일 채점합니다."

- **참가자 (확정 — 라이선스 확인된 것만)**: ECMWF AIFS(AI) vs ECMWF IFS(물리) — 같은 기관이라 가장 공정한 쌍 · NOAA FourCastNetGFS(AI) vs GFS(물리) · 기준선으로 기상청 예보.
  ⛔ Google WeatherNext 제외(한국 차단), ⛔ NVIDIA 직접 구동 제외(GPU 없음)
- **채점**: 우리가 이미 모으는 관측(kma-aws 736지점, OISST 등)과 대조. verify 아카이브 패턴 재사용
- **표현**: 리그 테이블 + "이번 주 승자". 불확실성은 AIFS-ENS 스프레드로 표시
- **규율**: 우리는 심판이지 선수가 아니다. 예보를 만들지 않고 채점만 한다 — 기존 원칙과 완전 정합
- 영상 보고서가 말한 "4개 독립 모델 앙상블"의 우리식 번역이 바로 이 기관 앙상블이다

### 기존 배치와의 연결

| 기존 항목 | 이 전략이 주는 것 |
|---|---|
| 배치 B (14일 날씨 시트) | 앙상블 스프레드로 "후반부 불확실성 표기"를 말이 아니라 **밴드 그래프**로. 경로 2택: ① Open-Meteo Professional(월 ~$99, 쉬움) ② ECMWF 오픈데이터 직접(무료, GRIB2 처리 Lambda 필요 — 무거움) |
| 배치 D (if) | Earth-2의 what-if 어휘 차용. v1은 유사사례 기반임을 명시 |
| 배치 E (태풍 유사경로) | ✅ **표현 방식 확정(2026-08-02)**: "유사 태풍 12개 중 8개가 북동 전향 (67%)" — **아날로그 앙상블**. 모델 없이 확률을 정직하게 말하는 법. 표현 규율은 아래 §2-b |

### §2-b. 아날로그 앙상블 표현 규율 (확정)

1. **건수가 먼저, 퍼센트는 괄호** — "12개 중 8개 (67%)". 퍼센트만 쓰면 모델 예측처럼 읽힌다. 건수가 있어야 검증 가능한 사실이 된다
2. **표본이 작으면 퍼센트를 아예 뺀다** — 유사 태풍이 5개 미만이면 "5개 중 3개"까지만. 3/4을 75%로 쓰는 순간 정밀한 척하는 거짓이 된다 (Wilks 소표본 문제 — 방법론 조사 #10과 연결)
3. **공식 예보 병기 + 라벨** — 항상 "과거 사례" 라벨을 달고 기상청·JMA 공식 예보 원뿔을 나란히 보여준다. 문구는 "이렇게 갈 것이다"가 아니라 "과거의 비슷한 태풍들은 이렇게 갔다"
| #19 예보 리그 | 본 문서의 "AI vs 물리모델 리그"로 승격 |
