## A. 결론

- **결론:** TWA 한 앱에 v1+v2 를 담는 방향과 크롬 새 탭을 2D 로 만드는 방향은 **둘 다 실현 가능하다.** 다만 초안에는 **토스 결제창이 앱 안에 뜰 수 있는 구멍**과 **사실과 다른 저장소 주장**이 있다. 그대로 승인하면 두 가지가 일어난다.
  1. 판매를 여는 날 Play 정책 위반과 약관 위반이 동시에 난다.
  2. Play 의 Data safety 신고가 실제로 모으는 자료와 어긋난다.
- **결함:** 모두 24건이다. 치명 3 · 높음 8 · 중간 9 · 낮음 4.
- **빠진 절:** 14개다.
- **일정:** 초안의 "2주 셸"은 두 가지가 해결돼야 성립한다.
  - PD 의 사업자 상태: 통신판매업 신고, 법인·D-U-N-S
  - 법적 페이지의 자리표시자
  - 둘 다 날짜가 없다. 공개 출시는 **최소 6~10주(추정)**로 봐야 한다.

## B. 결함 목록 (심각도 · 위치 · 증거 · 고칠 것)

### 치명

**1. [치명] v2 에는 결제 단추가 없다 — "v2 에서 결제 단추 → Play 시트"는 없는 화면을 전제한다**
- **초안 위치:** §0-1 ⑤, §3-4, Phase 2 완료 기준 1
- **증거:**
  - `prototype/v2-three/js/*.js`·`index.html` 에서 `subscribe|checkout|billing|toss` 를 찾으면 결제 코드는 0건이다. 주석 한 줄만 걸린다(`main.js:5763`).
  - v2 가 가져오는 공용 모듈은 `access-mode.js`·`usage.js` 뿐이다.
  - v2 의 로그인 단추는 v1 으로 통째로 이동한다: `location.href = '/?login=1&back=…'`(`main.js:5765-5769`).
  - 결제 어댑터는 v1 에만 있다(`prototype/js/billing.js:261-310`).
- **고칠 것:** 지시서에 **결제가 실제로 시작되는 화면**을 적는다.
  - 경로: v1 의 구독 화면(`billing.js`·`ui-subscribe`) · v2 의 잠금 → v1 구독 화면 이동 경로(`/?subscribe=…&back=/v2/…` 같은 새 경로가 필요하다)
  - Phase 2 완료 기준 1은 이렇게 다시 쓴다: "v2 잠금 카드 → v1 구독 화면 → Play 시트 → 결제 후 **원래 v2 화면으로 돌아와** 잠금이 풀린다."

**2. [치명] `?src=twa` + `sessionStorage` 판정은 딥링크·알림으로 들어오면 비어 있다 → 앱 안에서 토스 창이 뜬다**
- **초안 위치:** §3-4, R1
- **증거:**
  - App Links(`earthus.net/*` 전체, §3-2)로 앱이 열리면 TWA 는 그 URL 을 연다. `start_url` 을 거치지 않는다.
  - 알림을 누르면 `sw.js` `notificationclick` 이 `clients.openWindow(url)` 을 부른다. 새 창이라 sessionStorage 가 비어 있다.
  - 공유 링크, 검색 결과, 다른 앱에서 연 링크도 모두 같다.
  - 이 경우 `billing.js:336` 의 `available()` 필터가 `web`(토스)을 고른다.
- **고칠 것:** 판정 신호를 셋으로 겹친다.
  - ① 네이티브 런처(LauncherActivity 재정의 `getLaunchingUrl()`)가 **모든 진입 URL**에 `src=twa` 를 붙인다. Bubblewrap 기본값이 아니라 별도 Kotlin 코드다.
  - ② `matchMedia('(display-mode: standalone)')`. 이미 `push.js:31-33` 에 있다.
    - 대가: PWA 로 설치한 일반 Chrome 사용자도 토스가 막힌다. 이 대가를 받아들일지 **PD 가 정한다.**
  - ③ `document.referrer` 가 `android-app://` 로 시작하는지 [UNVERIFIED]. 보조 신호로만 쓴다.
  - 완료 기준에 넣을 결과: "알림 탭 · App Link · 공유 링크 세 경로로 들어온 앱에서 결제 단추를 누르면, Play 시트 또는 `앱에서는 결제할 수 없습니다` 가 뜬다."

**3. [치명] Data safety·처리방침이 실제 수집과 어긋난다 — 이대로 신고하면 허위 신고다**
- **초안 위치:** §3-6 Data safety 행("로그인 이메일·위치·이용 기록"), §2-1 법적 페이지 행
- **증거 — 처리방침 문장과 어긋나는 실제 수집:**
  - **저장 지점 좌표:** `push.js:176-179` 가 `alert_spots` 에 `lat, lon, label` 을 사용자 id 와 함께 서버(Supabase 도쿄)에 넣는다. 그런데 `privacy.ko.md:61`·`:119` 는 "위치정보는 회사 서버에 저장하지 않습니다"라고 쓴다.
  - **AI 질문 문장:** `/api/ask` → Lambda `earthus-llm` → Gemini(`ask-earth.js:18`). 처리방침에서 `gemini` 를 찾으면 0건이다. 질문 문장이 Google 로 가는데 처리위탁·국외이전 표에 없다.
  - **결제:** `privacy.ko.md:163` 은 "결제 처리(토스)는 국외로 이전되지 않습니다"라고 쓴다. Play 결제를 넣는 순간 거짓이 된다(Google 이 결제를 처리한다).
- **증거 — 초안 목록에서 빠진 수집 항목:**
  - `push_subscriptions` 의 endpoint 와 platform(`push.js:141-148`)
  - 동의한 사람의 `analytics_events`. userId 와 sessionPseudonym 이 붙고 365일 보관한다(`analytics.js:128`, HANDOVER §7).
  - 익명 `usage_bump` 카운터(`usage.js`)
  - 번역 문장 → MyMemory
  - 현재 위치와 IP → BigDataCloud (**제3자 공유**다)
- **고칠 것:** Phase 0 산출물에 **"실제 수집 목록 표"**를 넣는다(코드 위치, 연결 여부, 보관 기간, 제3자). Data safety 는 이 표에서만 답한다. 처리방침은 이 표에 맞춰 고치고, PD 가 법무 확인을 받는다. 이 일은 Phase 1 AAB 업로드보다 **먼저**다. 내부 테스트 트랙도 Data safety 가 필요하다.

    - `.gitignore` 에 `*.keystore`·`*.jks`·`local.properties`·`app/build/` 를 넣는다.
    - 키스토어 경로를 저장소 밖으로 지정한다.
  - 비밀번호는 환경변수로 넘긴다. `twa-manifest.json` 에는 경로와 별칭만 남는지 확인한다.
  - 완료 기준(결과): "`git -C … status --ignored` 에 키 파일이 ignored 로만 나온다."

- **증거:**
  - 운영 `clouds/meta.json` 에 `variants.webp2048.sha256` 이 실려 있다(`c876a1f0…`).
  - `main.js:1609-1620` 은 `?t=` 로 엣지 캐시를 가를 수 없다고 이미 적었다. HEAD·Range 우회도 실패했다고 적었다.
- **고칠 것:**
  - 확장이 받은 blob 의 SHA-256(`crypto.subtle`, 1.5 MB)을 meta 의 값과 비교한다.
  - 다르면 S3 직접 주소로 다시 받는다. S3 직접은 늘 ACAO `*` 다.
  - 그래도 다르면 **이전 그림과 이전 시각을 유지**한다.
  - 완료 기준(결과): "표시 중인 구름의 sha256 = meta.variants.webp2048.sha256, 라벨 시각 = meta.time."
  - 참고: v2 웹에도 적용할 수 있지만 이 지시서 밖이다.

**13. [중간] 신선도 규칙이 네 자료 중 하나에만 있다**
- **초안 위치:** §4-3 `feeds.js`("파일의 freshnessPolicy 우선"), §4-2
- **증거:**
  - 운영 파일에 `freshnessPolicy` 가 있는 것은 `events/kma-warn.json` 뿐이다(`freshMinutes 30`, `staleAfterMinutes 45`).
  - `wind/kma-aws.json` 과 `events/quake-asia.json` 에는 없다.
  - 시각 형식도 서로 다르다: `"20260924 14:00"` / `"202609241532"`.
- **고칠 것:**
  - 자료마다 고정 임계값을 지시서에 적는다. 예: 지상관측 90분 초과 → `기온 자료 지연 (마지막 HH:MM)`.
  - '최근 지진'의 시간 창을 정한다. 예: 24시간. 창 안에 없으면 `지난 24시간 한·일 기관 발표 지진 없음 · 기상청·JMA HH:MM 기준`.

## C. 빠진 절 (설계는 하지 않고 목록만)

1. **실제 수집 자료 목록 표** — Data safety·처리방침의 유일한 근거(#3)
2. **안드로이드 뒤로 단추 동작**
   - `popstate` 를 처리하는 곳은 `earth-view-state.js` 하나뿐이다.
   - 서랍·시트·Inspector 가 열린 채 뒤로를 누르면 페이지가 바뀌거나 앱이 닫힌다.
   - 딥링크로 `/v2/` 에 들어와서 뒤로를 누르면 앱이 끝난다.
   - v1↔v2 를 여러 번 오가면 기록이 쌓인다.
   - OAuth 뒤의 기록도 문제다.
3. **오프라인·첫 실행 나쁜 망**
   - v1 SW 는 `/v2` 요청을 건드리지 않는다(`sw.js` 92행). 그래서 앱 안 v2 오프라인은 Chrome 오류 화면이 된다.
   - 첫 실행부터 오프라인이면 SW 가 없다.
   - 필요한 것: 출처·시각이 붙은 오프라인 화면. TWA 품질 기준과의 관계는 [UNVERIFIED].
4. **태블릿·폴더블**
   - `orientation any`
   - 720px 경계(`earth-switch.js` NARROW)와 600~900dp 화면
   - 펼침·접힘 때의 WebGL 재생성
   - 완료 기준에 태블릿 1대를 넣는다.
5. **접근성** — TalkBack 으로 전환기·로그인·설정·값 카드를 읽을 수 있는가. 지구 위 숫자 라벨은 캔버스라 읽히지 않으므로 DOM 대체가 필요한지 정한다.
6. **다크/라이트** — `prefers-color-scheme` 는 저장소 어디에도 없다. 앱과 새 탭은 **어두운 화면 전용**이라고 명시한다. 상태바·내비게이션바 색도 정한다(theme-color 세 값 통일과 함께).
7. **WebGL 없는 기기** — 스토어 필터(`uses-feature glEsVersion`) 여부와, 지구가 안 뜰 때의 안내 화면. v1 은 WebGL 필수라고 안내한다(`index.html:309`).
8. **설치·이용 측정**
   - 새 개인정보를 만들지 않는다.
   - Play Console·CWS 대시보드 통계를 쓴다.
   - `analytics-contract.js` 의 `app.opened.entryKind` 에 `TWA` 범주를 더하는 안(동의자만)을 PD 결정으로 올린다.
9. **충돌·ANR 가시성** — Play Vitals 밖에 없다. 웹 오류는 `error.shown` 뿐이다.
10. **한국 전자상거래법 × Play 환불**

    - Play 환불과 서버 권한 회수. 1회성 상품이면 Voided Purchases 로 동기화한다 [UNVERIFIED 명칭]. RTDN 은 구독에만 해당한다.
    - 약관 "해지 절차 없음"과의 정합
11. **스토어 등록정보 문안**
    - Play 제목·짧은 설명(80자)·전체 설명(ko/en)
    - "뉴스 앱" 신고 여부. v1 에 뉴스 레이어가 있다.
