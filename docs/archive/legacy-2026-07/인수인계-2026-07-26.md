## 0. 프로젝트 한 줄 요약

손으로 돌리는 사실적인 3D 지구본 위에, 실시간 지구 데이터(기상·재난·위성·로켓·야생동물·해양 등)를 레이어로 얹어서 보여주는 앱.
무료 티어는 기상 + 교육 콘텐츠, 유료 구독 티어는 그 외 전체 데이터.

**장기 비전(소개용 스토리)**
> "처음엔 지구를 보여주는 서비스지만, 쌓이는 데이터는 결국 '지구 어디선가 일어나는 이상징후를 실시간으로 감지하고 검증하는 AI'로 성장한다."
>
> - 1단계(현재): 실시간 지구 시각화 앱, 사용자 확보
> - 2단계: 사용자 검증·제보가 쌓이며 라벨링된 크로스도메인 데이터셋 축적
> - 3단계: 그 데이터로 학습한 이상탐지/예측 AI, B2B 확장(보험·물류·언론사)

## 1. 확정된 기술 스택

| 항목 | 결정 | 비고 |
|---|---|---|
| 3D 엔진 | **Cesium** | 위경도 좌표계, 이미지 타일링(WMTS), 대기광, LOD가 기본 내장. Three.js 대비 개발 속도 우위로 선택 |
| 클라우드 | **AWS** (신규 계정 생성 예정) | NOAA GFS / ECMWF 데이터가 AWS 오픈데이터에 호스팅되어 있어 전송비 이점 |
| 정적 파일/영상 CDN | Cloudflare R2 (2차 도입 검토) | egress 비용 없음, SNS 자동배포 영상 서빙에 유리 |
| 무거운 렌더링 작업 | AWS Lambda 등 서버리스 워커 | 필요할 때만 실행 → 평시 비용 거의 0 |
| 인증/구독 관리 | Supabase 또는 Firebase 검토 | 직접 구현 회피, 개발 시간 절약 |

### AWS 계정 생성 시 필수 초기 세팅 (아직 미완료)
1. aws.amazon.com 계정 생성 (이메일 + 신용카드)
2. **결제 알림(Billing Alarm) 즉시 설정** ← 가장 자주 놓치는 부분
3. 루트 계정 직접 사용 금지 → IAM 관리자 계정 별도 생성
4. 루트 계정 MFA(2단계 인증) 활성화

## 3. 요금제 구조 (확정)

### 무료 티어 ("무료요금제")
- 기상 정보 (무료 또는 일회성 $2)
- **자연현상 3D 교육 콘텐츠** (열돔·태풍 형성원리 등) ← 학생 교육자료 활용 목적, 무료 확정
- 화면 상단 광고 노출
- **예약/예매 기능은 무료 사용자에게도 전면 개방** (수수료 수익 극대화를 위해 게이팅하지 않음)

### 유료 구독 티어
- 기본가 **월 $10**, 프로모션 시 **$5**
  - 프로모션은 Apple/Google 네이티브 프로모션 오퍼 기능 사용 (제3자 인증 불필요)
  - ⚠️ $5가 사실상 기본가가 되면 손익분기 구독자 수가 약 2배로 증가 → **기간 한정/타겟팅(첫 달, 이탈 방지)으로 운영 권장, 상시 병행 티어로 두지 말 것**
- 포함 콘텐츠: 위성 궤도, 로켓 발사, 재난, 이벤트 뉴스, 야생동물 이동, 해양·지상 관측소, 태양 관측, 해양 쓰레기 등

### 출시 시점 제외 항목 (Phase 2로 연기)
- **항공기 실시간 추적** — FlightRadar24 Business API 약 $99.99/월
- **선박 실시간 추적** — Datalastic 약 €99/월
- 이유: 유료 상업 API 비용 부담. 구독 매출 확보 후 업데이트로 추가
- 이 사실을 사전등록 페이지에서 "목표 달성 시 언락" 방식으로 마케팅에 활용 (아래 8번 참조)

### 손익 참고치
- 손익분기 추정: 구독자 약 35~110명 (프로모션 사용률·비용 시나리오에 따라)
- 1년차 현실적 기대치: 다운로드 수천~수만, 무료→유료 전환율 1~5% → **유료 구독자 100~500명 수준**
- 벤치마크(참고용, 직접 비교 대상 아님): Flightradar24 = 누적 1.2억 다운로드, 연매출 약 $40M, 카테고리 1위까지 약 20년

## 5. 기능 명세

### 5-1. 레이어 구조 (핵심 아키텍처)
모든 기능은 **개별 온/오프 가능한 레이어**로 구현. 사용자가 켠 레이어만 렌더링.

**성능 병목은 데이터 용량이 아니라 동시 렌더링 오브젝트 수.** 필수 최적화 2가지:
1. **클러스터링**: 줌아웃 시 개별 아이콘 대신 집계 배지로 병합("이 지역 항공기 47대") → 줌인 시 개별 전개
2. **뷰포트 기반 로딩**: 현재 화면 범위 데이터만 요청 (전 지구 일괄 로드 금지)

> 이 두 가지를 구현하면 저사양 기기에서도 다중 레이어 사용 가능. 미구현 시 고사양 기기도 버벅임.
> Cesium은 LOD/타일링이 기본 내장이라 유리하나, 커스텀 엔티티 클러스터링은 별도 구현 필요.
>
> 부수효과: 무료 티어(기상)=경량 레이어, 유료 티어(선박·항공·야생동물)=고부하 레이어 → 과금 구조와 성능 구조가 자연스럽게 일치.

### 5-2. 이벤트 신뢰도 검증 레이어 ⭐ (핵심 차별화)
GDELT 노이즈 대응. 아래 요소로 스코어링:
- 다중 소스 교차 검증
- 소스 가중치
- 위치+시간 기반 중복 제거
- **미확정 / 확정 2단계 표시 분리**
- 시간 경과에 따른 감쇠(decay)

> 이 신뢰도 스코어가 **후속 파이프라인 3곳의 게이트**로 동작함:
> ① 뉴스 가공 여부 ② SNS 자동영상 배포 여부 ③ 향후 AI 학습 라벨

### 5-3. 뉴스 / 이벤트 표시 (저작권 준수 설계)
| 이벤트 등급 | 처리 |
|---|---|
| **고신뢰 확정 이벤트** | 제목 영문+한국어 번역 / 본문은 **자체 재작성 + 분석 원고**(영문·한국어 양쪽) / 원문 직링크 병기 |
| **그 외 이벤트** | 영문 제목만 리스트 노출 + 원문 직링크 |

> 원문 본문 재현 금지(저작권). 자체 분석·재구성 + 원문 링크 제공 방식이 안전.

### 5-4. 라이브 방송 임베드
| 이벤트 유형 | 방식 |
|---|---|
| **로켓 발사** | LL2 API의 공식 스트림 URL 자동 매칭 → 유튜브 iframe 임베드 (임베드는 유튜브 공식 기능이므로 저작권 문제 없음). 발사 임박 시 URL이 채워지는 경우가 많아 **폴링 필요**. 군사/비공개 발사는 스트림 부재 → "링크 없음" 처리 |
| **자연재난** | 통합 API 없음. **기관 유튜브 채널 화이트리스트 수동 큐레이션** 필요(USGS, JMA, 각국 재난당국). 이벤트 발생 시 해당 지역 담당기관 라이브 여부 체크 |
| **분쟁/공격 뉴스** | ❌ **단일 임베드 금지**. 공식 발신 주체가 없고, 특정 매체 라이브를 앱이 선택 임베드하면 "공식 중계"처럼 오인될 위험. 가공원고+원문링크 유지, 필요 시 **복수 언론사 링크 나열** |

### 5-5. 로켓 발사 → 위성 궤도 연계
발사 예정 위치 아이콘 + 카운트다운 → 탭 시 미션 정보(로켓/페이로드/기관) + 라이브 임베드 → 발사 후 궤도 진입 시 **위성 궤도 추적 레이어로 자연 연결** (하나의 미션이 두 기능을 관통)

### 5-6. 자연현상 3D 설명 콘텐츠 (무료 티어)
**요구사항 (중요)**:
- 팝업 설명창이 아니라 **실제 지구본 지도 위 해당 좌표에 3D로 직접 표현**
- 단순 원리 설명이 아니라, **현재 그 위치에서 발생 중인 현상 + 며칠 후 변화 예측**까지 설명
  - 예: "이 열돔은 현재 여기 있고, N일 후 태풍/비구름에 밀려 소멸 예정"
  - 예측값은 **GFS/ECMWF 예보모델 수치 그대로 활용** (자체 예보 모델 개발 불필요)
- 기존 자료(NASA 등) 활용이 아닌 **자체 제작 에셋**

**구현 난이도 (완화됨)**:
- 정교한 실시간 프로시저럴 렌더링 불필요. **미리 만들어둔 3D 그림(정적 에셋)을 좌표에 배치**하는 수준으로 충분
- 필요한 로직: 실제 좌표 배치 + 실제 현상 규모에 맞춘 스케일 조정 (Cesium 엔티티 기본 기능으로 처리 가능)
- 에셋 제작 자체는 코드 밖 작업 (직접 제작 / 3D 아티스트 / Meshy·Tripo 등 생성 도구)

**콘텐츠 라이브러리 (한 번 만들면 재사용)**:
- [x] 열돔
- [x] 태풍/허리케인 형성 원리
- [x] "쓰레기섬은 섬이 아니다" (해양 미세플라스틱)
- [ ] 엘니뇨 / 라니냐
- [ ] 극소용돌이발 한파
- [ ] 장마전선
- [ ] 극한호우
- [ ] (추가 목록화는 추후 진행 예정)

> ⚠️ **정확도 주의**: 학생 교육자료로 활용되므로, 예측 문구를 자동 생성할 경우
> **실제 예보모델 수치에 근거한 것만 생성**되도록 제한하고, 일반화된 추측 문장이 섞이지 않도록 검수 단계 필수.

### 5-7. 다국어
- 기본 2개 언어: **영어 / 한국어**
- 기기 언어가 한국어면 한국어, 그 외는 영어로 초기 설정
- 설정에서 수동 변경 가능
- ⚠️ **기기 언어 감지는 최초 1회 기본값으로만 사용**. 사용자가 수동 변경하면 저장 → 이후 실행 시 기기 언어로 덮어쓰지 말 것
- 앱스토어 리스팅(설명·스크린샷)도 언어별 별도 등록 필요 (앱 내 설정과 별개 메커니즘)
- 온도 단위(℃/℉)는 **언어 설정과 분리된 별도 옵션**으로 두기 권장

### 5-8. 마니아층 / 바이럴 기능 (전부 채택)
- 유명 항공편 실시간 공동 관람 (선례: FR24의 엘리자베스 2세 여왕 운구기 추적 — 첫 1분간 600만 뷰)
- 현재 하늘의 동시 비행기 수 실시간 카운터 / 기록 경신 알림
- "순간의 지구" 스냅샷 공유 카드 (SNS용)
- 방문 국가 색칠 게임화
- 매일 "지구 브리핑" 푸시 알림 (로켓 발사·일식·주요 지진 등)
- 대척점(지구 반대편 지점) 뷰어
- 오로라 / 스타링크 목격 커뮤니티 제보 지도
- 로켓 발사 카운트다운 + 실시간 궤도 시각화

> 선례: 2021년 에버기븐 수에즈 운하 좌초 시 MarineTraffic이 전 세계적으로 밈화되며 바이럴.
> "실제 사건 추적 = 바이럴"이라는 가설의 검증 사례.

### 5-9. 화면 구조 / UI 방향 (확정)

**레퍼런스**: Living Earth (Radiantlabs) — 상세는 12번 참조. **진입 화면의 비주얼을 계승**한다.

**계승 요소**
- 순수 검정 배경 + 실제 별자리
- 지구를 화면 중앙에 띄우고 UI는 위아래로 분리 — **지구를 아무것도 가리지 않음**
- 대기광(rim light) 강하게 — "떠 있다"는 느낌의 핵심
- 주야 경계선 + 야간 도시 불빛 (현재 시각이 지구에 그대로 반영)
- 얇은 타이포, 패널·테두리 없음, 컨트롤은 화면 구석으로

**2-state 구조**

리빙어스 레이아웃은 확대를 전제하지 않는다(한 도시 날씨 앱이라 상·하단이 고정 크롬). 우리는 확대 후 핀·레이어 토글·정보 카드가 필요하므로 상태를 둘로 분리한다.

| 상태 | 시점 | 화면 |
|---|---|---|
| **Ambient** | 앱 진입 ~ 전지구 뷰 | 리빙어스 룩. 지구 전체 + 시계 + 현재 위치 날씨. 레이어 UI 전부 숨김 |
| **Explore** | 확대 시작 이후 | 시계·기온 페이드아웃 → 레이어 토글 + 핀 등장. 정보는 하단 시트 |

전환은 끊기는 이벤트가 아니라 **연속적**으로: 확대 제스처 시작 → 크롬 서서히 페이드 → 카메라 고도 임계 도달 → 핀 등장.

> 부수효과: 무료 티어 사용자는 Ambient에 머물고, 유료 레이어 사용자는 Explore에서 산다 → **과금 구조와 화면 구조가 일치**.
> 차별점: 리빙어스는 아무리 확대해도 그냥 큰 지구지만, 우리는 **확대하면 다른 앱이 되는** 구조.

**Cesium 관점**
- 기본 제공(공수 작음): 별 배경(SkyBox), 대기광(SkyAtmosphere), 주야 음영, 야간 이미지 블렌딩, 구름 타일 오버레이
- 직접 구현 필요: **기본 Cesium 위젯 전부 비활성화 후 룩 재구성**(끄지 않으면 "GIS 도구" 인상이 남음), Ambient↔Explore 전환 애니메이션, 클러스터 배지 디자인, 태풍 진행방향 화살표

### 5-10. 핀 / 레이어 노출 규칙 (확정)

**원칙: 전지구 뷰를 깨끗하게 유지한다.** 데이터 성격별로 노출 시점을 다르게 둔다.

| 종류 | 예 | 노출 시점 |
|---|---|---|
| **면** | 구름, 기온, 강수, 미세플라스틱 농도 | 전지구부터 항상 (텍스처라 밀도 문제 없음) |
| **선** | 위성 궤도, 태풍 예상 경로, 야생동물 이동 | 전지구부터 (전지구에서 봐야 의미가 있음) |
| **점** | 관측소, 화산, 발사장, POI, 예매 | **국가~시도급부터** |
| **이벤트** | 지진, 재난, 고신뢰 뉴스 | 중요도 임계 통과분만 전지구 노출 (아래) |

**이벤트 예외 근거**: 규모 7.0 지진이 방금 났는데 전지구 뷰에서 아무것도 안 보이면 앱 정체성("지구는, 지금도 움직이고 있다")과 어긋난다. 규모 7+ 지진은 연 10~20회라 화면이 어지러워지지 않으며, 오히려 **깨끗한 지구 위에 맥동하는 점 하나**가 리빙어스와의 결정적 차이를 만든다.
→ 전지구 노출 대상: 규모 6.5+ 지진, 활성 태풍, 임박한 로켓 발사, 5-2 신뢰도 검증을 통과한 확정 이벤트.

**클러스터링 — A안 확정**

5-1의 클러스터링은 **전지구에 배지를 띄우지 않는 방식**으로 확정.
- 전지구: 배지 **없음** (Ambient 보호)
- 국가급 진입 후: 밀집 지역에서만 집계 배지
- 시도급: 개별 핀 전개

> 전지구에 집계 배지를 띄우는 방식(Flightradar24 스타일)은 **채택하지 않음**. 5-1의 "줌아웃 시 집계 배지" 서술은 이 규칙으로 대체된다.

**줌 임계 (초안 — 실기기 조정 필요)**

행정구역 단위로는 임계를 잡을 수 없다(경기도 / 텍사스 / 시베리아 주의 실제 크기가 수십 배 차이). **카메라 고도** 기준으로 구현한다.
- 핀 등장: 약 **1,500km** 이하 (한국·일본이 화면에 꽉 차는 정도)
- 개별 전개: 약 **500km** 이하

> **성능상 이점**: 전지구 뷰에서 점 데이터를 아예 요청하지 않으므로, 5-1이 지적한 "동시 렌더링 오브젝트 수" 병목과 뷰포트 기반 로딩 부담이 상당 부분 자동으로 해결된다. UX 선택이 성능 아키텍처와 일치하는 구조.

## 6. 마케팅 자동화 파이프라인

### 6-1. 이벤트 자동 영상 배포
**흐름**: 이벤트 감지 → 서버에서 지구본이 해당 좌표로 줌인하는 애니메이션 자동 렌더링 → 뉴스 오버레이 + "이벤트 발생, 확인하세요" 문구 합성 → SNS 자동 게시

**배포 채널**: 인스타그램 / 페이스북 (Meta Graph API) + 틱톡 + 유튜브 쇼츠
- 각 플랫폼 자체 API로 자동 업로드 지원. 플랫폼별 앱 심사/인증 절차 각각 필요
- 세로 9:16 포맷 공용 사용
- 영상 말미에 앱 아이콘 + "지금 확인하기" 다운로드 유도 문구 필수

> ⚠️ **필수 안전장치**: 5-2의 신뢰도 검증을 **자동배포의 게이트로 반드시 적용**.
> 확정 이벤트만 자동 배포, 미확정은 앱 내 표시로만 제한.
> (미검증 이벤트가 자동으로 영상까지 만들어져 공개 SNS로 나가는 사고 방지)

### 6-2. 평상시 콘텐츠 (이벤트 공백 대응)
큰 재난/분쟁이 없는 날에도 **공연 정보 → 예매 연결** 콘텐츠를 노출.
- 지구본이 비어 보이지 않음
- 예매 수수료 수익이 평상시에도 발생
- SNS 계정이 며칠씩 조용해지지 않아 알고리즘 노출에 유리

## 7. 사전등록 랜딩 페이지 (제작 완료, 연동 필요)

산출물: `earthus-waitlist.html`

**컨셉**: "항공기·선박 실시간 추적은 유료 데이터라, 창립 멤버가 목표만큼 모이면 그 매출로 연다"

**창립 멤버 혜택 (3종)**:
1. **평생 가격 고정** — 이후 기능 추가로 가격이 올라도 창립 멤버는 최초 가격 유지 (실비용 0, 유인 효과 큼)

### 13-3. 구름 — 결정 (2026-07-26)

**결론: MVP 는 "전지구 배경에 구름 없음 + 아시아·태평양 확대 시 Himawari 10분 갱신".**

#### 왜 GIBS 를 그대로 못 쓰나

4-1은 "구름 = NASA GIBS, 기본 배경용으로 충분"이라 했으나 **실제로 얹어보니 부족하다.**

- MODIS `Cloud_Fraction` 은 과학용 **위색(false-color)** 산출물 → 분홍/보라로 렌더됨
- 탈채도해도 "구름비율"이라 옅은 구름까지 전부 칠해져 **지구를 통째로 덮음**
- 극궤도라 **스와스 이음매**가 줄무늬로 남음
- 트루컬러는 구름처럼 보이지만 결측 구간이 검게 뚫림
- 무엇보다 극궤도 위성(Terra/Aqua/VIIRS)은 통과 시각이 몰려 있어 **합쳐도 하루 1~2회**가 한계 → 리빙어스의 3시간보다 오히려 나쁨

#### 갱신 주기

| 위성 | 전체 디스크 | 고빈도 영역 |
|---|---|---|
| **Himawari-9** | **10분** | 2.5분 (타겟 영역 — 한반도 포함 여부 확인 필요) |
| GOES-16/19, GOES-18 | 10분 | 5분(미 본토) / 1분(메소스케일) |
| Meteosat MSG | **15분** ← 전지구 합성의 병목 | 5분(유럽) |
| Meteosat MTG | 10분 | 2.5분 |

**MVP = 10분** (Himawari 1기). 2.5분은 비용 4배인데 이득이 한·일 근접 줌에서만 나오므로 나중에.
전지구 5기 합성으로 확장 시 **15분**(MSG 병목), MTG 전환 후 10분.

#### 수집·보관 원칙

**수집은 표시보다 촘촘하게, 단 가성비 최적점에서.** 추후 재분석과 0번 장기비전(이상탐지 AI)에 쓰려면 시간 해상도가 필요하고, 놓친 프레임은 복구가 비싸다. 다만 무작정 모으면 비용이 감당 안 된다.

비용 구조 (MVP 추정, AWS 계정 생성 후 실측 보정 필요):

| 항목 | 수집 주기 비례 | 월 비용 |
|---|---|---|
| 저장 (프레임당 등장방형 1장, WebP ~400KB) | ✅ | **~$0.5** (1년 누적 20GB) |
| 컴퓨트 (Fargate 2vCPU/4GB, 프레임당 1.5분) | ✅ | **~$10** (10분 주기) / ~$43 (2.5분) |
| 전송 | ❌ 사용자 수에 비례 | CloudFront 시 10만 DAU에 월 $500+ |

→ **핵심은 "얼마나 자주"가 아니라 "무엇을 저장하느냐"다.** 타일 피라미드를 통째로 보관하면 용량이 100배로 뛴다.
프레임당 **등장방형 원본 1장만** 남기고 타일은 최신 것만 상시 생성, 과거는 온디맨드.

→ **전송비는 1번의 Cloudflare R2 로 해결한다** (egress 0). 컴퓨트는 AWS(원본이 AWS 오픈데이터라 수신 무료), 서빙은 R2.

→ **솎아내기는 지금 하지 않는다.** 용량이 문제가 되는 규모가 아니다. 1년 뒤 재평가.

> 수집 파이프라인은 사용자 요청과 분리된 배치 작업이라, 주기를 높여도 앱 응답성에는 영향이 없다.
> 버벅임은 수집이 아니라 타일 서빙에서 온다 → R2/CDN 으로 해결할 문제이지 수집 주기를 줄일 이유가 아니다.

#### 12번 수정 필요

12번의 "구름 갱신 주기 우위(리빙어스 3시간 vs 우리 10분)"는 **전지구 화면에서는 사용자가 인지할 수 없다.**
전지구 뷰에서 1픽셀 ≈ 34km 이므로 10분 이동(약 8km)은 0.24픽셀이다. 국가급 이하로 확대해야 보인다.
→ 마케팅 문구는 출시 시점에 다시 정한다. **기술 목표를 마케팅에서 역산하지 말 것.**

### 13-4. 기술 함정 (재발 방지)

1. **GIBS 는 EPSG:3857 을 써야 한다.** EPSG:4326 격자는 `2×1 → 3×2 → 5×3 → 10×5` 로 Cesium 의 `GeographicTilingScheme`(2→4→8→16)과 어긋난다. 레벨 0 만 맞아서 전지구 뷰는 정상으로 보이고 확대하면 전부 400 이 난다 — **원인 찾기가 매우 어렵다.**
2. **`lightingFadeOutDistance < lightingFadeInDistance`** 여야 한다. 뒤집으면 근거리에서 지구가 검게 죽는데 에러도 경고도 없다.
3. **Ambient/Explore 는 크롬만 바꾸면 안 된다.** 야간면에서 확대하면 지표가 안 보인다 → 고도에 따라 기본면 `nightAlpha` 를 램프.
4. satellite.js v5 에는 `json2satrec` 이 없다 → `FORMAT=tle` + `twoline2satrec`.
