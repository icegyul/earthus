우리 회사(달루어)가 만든 서비스 **earthus** 를 소개하는 제품 섹션(또는 페이지)을
이 사이트에 추가해줘. 아래 내용은 확인된 사실이니 **그대로 쓰고, 추측으로 살을 붙이지 마.**

## earthus 가 무엇인가

전 세계 기상·해양·재난 관측 자료를 3D 지구본 하나에 모아 보여주는 웹 서비스.
NOAA·NASA·ECMWF·USGS·기상청 등 12개 기관의 공개 자료를 쓰고, 관측 레이어는 41종.
화면에 뜨는 모든 값에 **출처와 관측 시각**을 함께 적는 것이 이 서비스의 핵심.
설치·가입 없이 브라우저에서 바로 열림 (PWA). 주소: https://earthus.net

## ⚠️ 가장 중요 — earthus.net 의 글을 베끼지 마

`https://earthus.net/intro.html` 에 이미 소개 페이지가 있어. 거기 문장을 그대로
가져오거나 줄여 쓰면 **검색엔진이 중복으로 보고 둘 중 하나만 색인해.**
두 페이지가 둘 다 살아남아야 하므로 **답하는 질문을 다르게** 가야 해.

- earthus.net/intro.html → "이게 뭐고 어떻게 동작하나" (제품 설명)
- **이 사이트 → "달루어가 무엇을 만드는 회사인가"** (회사 관점)

그래서 아래 원고는 이미 회사 관점으로 다시 쓴 것이야. 이걸 쓰고,
더 줄이거나 늘릴 때도 earthus.net 문장을 참고하지 말고 이 원고만 변형해.

```
달루어가 만든 earthus는 전 세계 기상·해양·재난 관측 자료를 3D 지구본 하나에
모아 보여주는 웹 서비스입니다. NOAA·NASA·ECMWF·USGS·기상청 등 12개 기관이
공개하는 자료를 서버가 정해진 주기로 받아 화면용으로 가공하며, 관측 레이어는
41종입니다.

다른 날씨 서비스와 갈라지는 지점은 "숫자를 어디까지 책임지는가"입니다.
earthus는 화면에 뜨는 모든 값에 어느 기관에서 온 자료인지와 언제 관측된
것인지를 함께 적습니다. 원본 기관이 응답하지 않으면 보관해 둔 마지막 자료로
그리고 그 사실도 화면에 적습니다. 값만 보여주고 출처를 감추면, 맞는지 틀리는지
확인할 방법이 사라지기 때문입니다.

앞일을 다룰 때도 같은 원칙을 씁니다. earthus는 예보 기관이 아니므로 진로나
결과를 단정하지 않고, 대신 과거를 셉니다. 태풍이라면 1980년 이후 서태평양
태풍 1,477개 가운데 지금과 위치·진행방향·강도·계절이 닮았던 시점을 찾아
"유사 사례 30건 중 13건이 북서쪽으로 진행(43%)"처럼 알려줍니다. 세는 방법과
표본 수를 함께 밝히므로, 읽는 사람이 그 숫자를 얼마나 믿을지 스스로 정할 수
있습니다.
```

## 이미지 — 반드시 절대 URL 로

우리 사이트에 호스팅돼 있어. **다운로드해서 복사하지 말고 이 주소를 그대로 써.**
전부 1600×1000. 하나만 쓴다면 globe.

| 용도 | WebP (우선) | JPEG (폴백) |
|---|---|---|
| 로고 | https://earthus.net/logo-lockup.webp | https://earthus.net/logo-lockup.png |
| 대표 · 첫 화면 | https://earthus.net/shots/globe.webp | https://earthus.net/shots/globe.jpg |
| 태풍 | https://earthus.net/shots/cyclone.webp | https://earthus.net/shots/cyclone.jpg |
| 뉴스 | https://earthus.net/shots/news.webp | https://earthus.net/shots/news.jpg |
| 기상특보 | https://earthus.net/shots/alerts.webp | https://earthus.net/shots/alerts.jpg |
| 산불 | https://earthus.net/shots/wildfire.webp | https://earthus.net/shots/wildfire.jpg |
| 해수면 온도 | https://earthus.net/shots/sst.webp | https://earthus.net/shots/sst.jpg |

`<picture>` 로 webp 우선 + jpg 폴백을 걸고, `width`/`height` 를 넣어 레이아웃이
밀리지 않게 해줘. 아래 화면은 `loading="lazy"`.

**alt 문안 (그대로 써 — 접근성이자 이미지 검색 노출 근거)**

```
globe    : earthus 첫 화면. 3D 지구본 위에 NOAA GMGSI 전지구 구름 합성이 얹혀 있고, 현재 시각과 지역 기온이 표시돼 있다.
cyclone  : 서태평양 상공. 구름 합성 위로 태풍의 소용돌이 구조와 눈이 또렷하게 보인다.
news     : 지구본 위 사건이 일어난 위치마다 말풍선이 붙어 분류와 기사 제목을 보여준다.
alerts   : 한반도 화면. 지역마다 발효 중인 기상특보 건수가 원 안의 숫자로 묶여 있다.
wildfire : 미국 서부 야간 화면. 도시 불빛 위로 산불 위치가 붉은 점과 원으로 표시돼 있다.
sst      : 태평양 지구본에 해수면 온도가 색 격자로 칠해져 있다.
```

## 링크

```html
<a href="https://earthus.net/">earthus 열기</a>
<a href="https://earthus.net/intro.html">기능과 자료 출처 전체 보기</a>
```

⚠️ `rel="nofollow"` 를 붙이지 마. 자사 제품 링크에 nofollow 를 달면 검색엔진이
회사와 제품을 연결하지 못해.

## 구조화 데이터

이 페이지 `<head>` 에 넣어줘. **`url` 은 이 사이트의 실제 주소로 바꿔.**
(모르겠으면 지어내지 말고 나한테 물어봐.)

```html
<script type="application/ld+json">
{
  "@context":"https://schema.org",
  "@type":"Organization",
  "name":"달루어",
  "url":"「이 사이트 주소」",
  "makesOffer":{
    "@type":"Offer",
    "itemOffered":{
      "@type":"WebApplication",
      "name":"earthus",
      "url":"https://earthus.net/",
      "applicationCategory":"WeatherApplication",
      "operatingSystem":"Web, iOS, Android, Windows, macOS",
      "description":"공공기관의 지구 관측 자료를 3D 지구본 위에 모아 보여주는 웹 서비스. 모든 값에 출처와 관측 시각을 함께 표시한다."
    }
  }
}
</script>
```

earthus.net 쪽에는 이미 `provider`/`publisher` 를 달루어로 걸어 뒀어.
양쪽이 서로를 가리켜야 검색엔진이 "회사 ↔ 제품"으로 인식해.

## ⚠️ 절대 쓰면 안 되는 표현

카피를 다듬다 보면 넣기 쉬운데, **사실이 아니거나 아직 못 하는 것들**이야.
재난 자료를 다루는 서비스라 과장 한 줄이 곧 사고가 돼.

| 쓰지 말 것 | 이유 |
|---|---|
| "AI로 날씨를 예보합니다" | 예보하지 않음. ECMWF 의 AI 모델(AIFS) 예측을 **기록만** 하고 있고, 물리 모델과의 성적 비교는 자료가 며칠치뿐이라 아직 공개 전 |
| "가장 정확한 날씨" | 정확도를 비교 검증한 적이 없음. 근거 없는 주장 |
| "재난 알림 서비스" | 공식 재난 경보 채널이 아님. 기상청·행안부 발표를 대신하지 않음 |
| "AI가 분석해 드립니다" | 화면의 설명 문장은 전부 관측값에서 **계산된** 것. 문장 생성에 AI 를 쓰지 않음 |
| "실시간" 을 전체 수식어로 | 원본 주기가 자료마다 다름(구름 1시간, 지진 2분, 영국 예보 3시간). "실시간 관측 자료를 모아"처럼 자료를 수식하는 건 괜찮지만 서비스 전체를 "실시간"이라 하면 과장 |

그리고 **여기 없는 숫자나 기능을 지어내지 마.** 더 필요하면 나한테 물어봐.
