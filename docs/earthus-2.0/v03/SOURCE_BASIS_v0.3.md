# EARTHUS 2.0 Engine Foundation v0.3 — Source Basis

## Source-supported constraints retained

- EARTHUS 1.0 remains a static Web/PWA with Cesium, AWS Lambda/EventBridge, S3/CloudFront and Supabase control-plane. The v0.3 package does not replace that stack.
- Existing Globe Core and Thermal/Quality are reused; KTO, Seoul population and KMA are adapter targets; AirKorea and operations are hardened.
- Observation, official forecast/warning, Earthus analysis/forecast, estimated distribution and simulation remain different evidence classes.
- Cloud, precipitation, runoff, river flow and flood are separate data/engine domains.
- Bathymetry/trench remains a technical gate for deep underwater/geology features.
- Official safety and evacuation information stays free and cannot be weakened by derived recommendations.
- Layer OFF must stop feature polling/animation and release owned resources.

## New v0.3 architecture additions

The following are engineering additions proposed to close gaps; they are not claims that EARTHUS 1.0 already has them:

- Canonical data tile/time-slice/cache/revision layer.
- Ocean state/wave/swell/tide/coastal exposure engines.
- Unified hazard event/warning/depth/lightning/wildfire/cyclone foundations.
- Planet State Graph, analog retrieval, route exposure and decision explanation.
- Visual material grammar, accessible label budget and common picking contract.
- Security redaction, endpoint abuse control, privacy minimization and access audit.
- Fault injection, replay regression and launch-gate compiler.
- Earthus↔Aetherus launch/space event bridge that preserves separate runtime ownership.

All formulas in v0.3 are foundations. Dataset-specific calibration and official-provider contracts remain required before Production activation.
