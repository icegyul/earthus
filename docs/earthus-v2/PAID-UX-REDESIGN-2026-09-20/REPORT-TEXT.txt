# 1. 이번 개편에서 절대 지켜야 하는 8가지 규칙
항목
개발 기준
1. 현상 우선
Temperature, Wind, Rain, Clouds, Ocean, Hazards, Air Quality, Space, Terrain을 1급 현상 메뉴로 제공한다.
2. 단일 Global Timeline
메뉴마다 새로운 시간 막대/슬라이더를 만들지 않는다. 시간축은 화면 전체에서 단 하나만 존재한다.
3. Data와 View 분리
데이터 선택과 지형 과장/태양각/위성 색 혼합 같은 렌더링 조작을 같은 패널에 두지 않는다.
4. Stepped visualization
온도/강수/대기질/해양 편차/위험도는 연속 그라데이션만으로 표현하지 않는다. 구간형 색 + contour + 숫자 라벨을 조합한다.
5. Inspector
선택한 위치/이벤트/관측소의 정확한 값, 단위, 시간, 출처, 모델을 우측에서 읽는다.
6. Compare first-class
모델 비교는 설정이 아니라 독립 작업이다. 카메라/시간/고도/legend가 동기화되어야 한다.
7. Intelligence is evidence-first
AI 문장보다 원수치·출처·시간·계산근거가 먼저 보인다.
8. Simulation is a workspace
시뮬레이션은 일반 레이어 메뉴에 섞지 않고 별도 공간으로 분리한다.

# 3. 메뉴별 1:1 비교 및 개발 기준
## 01. Temperature / 기온
항목
개발 기준
CURRENT EARTHUS
현재 V2는 설정과 표현 튜닝이 한곳에 섞여 있고, 사용자가 느끼는 온도 표현은 연속적인 색 변화에 의존한다. 사용자가 온도의 경계를 빠르게 읽거나 특정 임계구간을 비교하기 어렵다.
MAPPED.earth
mapped.earth는 temperature를 핵심 단추로 즉시 전환하고, 지구 자체를 데이터 필드로 바꾸는 단순 진입 구조를 사용한다.
WINDY
Windy는 Temperature를 1급 현상으로 두고, map overlay와 isolines를 별도로 조절한다. 현재 메뉴에는 Temperature와 Isolines가 분리되어 있다.
EARTHUS AFTER
온도는 기본을 Stepped Bands(구간형)로 바꾸고 2°C/5°C 등온선을 선택적으로 오버레이한다. 우측 Inspector에는 Surface/850hPa, Actual/Anomaly, Model, Time만 남긴다.

AFTER 콘셉트 — Temperature / 기온
### 개발 Acceptance Criteria
연속 그라데이션 단독 표현 금지
온도 경계가 눈에 보이는 구간형 팔레트 지원
등온선에 숫자 라벨 제공
관측/예보/평년 대비 편차를 동일 UI에서 전환
Legend가 항상 데이터 의미와 단위를 표시

## 02. Wind / 바람
항목
개발 기준
CURRENT EARTHUS
바람은 단순 숫자나 한 가지 시각 효과가 아니라 방향성과 속도를 동시에 읽어야 한다. 현재 UI에서 표현 튜닝이 별도 설정으로 분산되면 데이터보다 조작이 먼저 보인다.
MAPPED.earth
mapped.earth는 wind를 핵심 레이어로 두고 실제 필드가 움직이는 3D 지구 자체를 데이터 시각화로 사용한다.
WINDY
Windy는 Wind를 1급 메뉴로 제공하고 Particles animation, Altitude, Forecast model, Isolines 등을 별도 제어한다.
EARTHUS AFTER
지도 자체는 애니메이션 입자와 속도 밴드를 보여주고, 우측에 높이(10m/850hPa 등), 모델, 시간, 입자 강도를 컴팩트하게 둔다. 입자 강도는 슬라이더가 아니라 3단 프리셋으로 바꾼다.

AFTER 콘셉트 — Wind / 바람

고도/모델/시간은 동일 Inspector에 배치
속도 legend는 m/s·kt 단위를 동시 지원
강풍 핵심영역은 contour/핵 강조 가능

## 03. Rain / 강수

## 05. Ocean / 해양
항목
개발 기준
CURRENT EARTHUS
EARTHUS의 해양 범위에는 해수면 온도·편차·파고·너울·해류가 있다. 그러나 이를 한꺼번에 보여주기보다 현상별 핵심 표현과 분석을 분리해야 한다.
MAPPED.earth
mapped.earth는 Currents, SST, SST HD, SSTA를 명확히 구분하고, 해류는 애니메이션 field로 보여준다.
WINDY
Windy는 Waves, sea를 하나의 해양 카테고리로 묶고 파랑/해류/해상 상태를 전문 사용자가 선택한다.
EARTHUS AFTER
Ocean은 SST / SSTA / Currents / Waves 4개 핵심 모드로 단순화한다. SST와 SSTA는 색상 밴드가 다르고, Currents는 유선/입자, Waves는 방향+높이 glyph로 표현한다.

AFTER 콘셉트 — Ocean / 해양
### 개발 Acceptance Criteria
SST와 anomaly의 색 의미를 명확히 분리
해류는 입자/streamline 기본 ON
파고와 너울을 별도 수치로 표현
해수면 온도는 °C와 threshold legend 제공
해양 데이터 업데이트 시각과 출처를 Inspector에 고정
유료 UX 포인트: Explorer: SST/SSTA/Currents / Pro: high-res SST·wave·current 비교
## 06. Hazards / 재난
항목
개발 기준
CURRENT EARTHUS
EARTHUS는 태풍·지진·산불·쓰나미·기상특보 등 안전 데이터를 제공한다. 이 영역은 시각적 화려함보다 심각도와 공식성, 최신성이 먼저 보여야 한다.
MAPPED.earth
mapped.earth는 현상을 데이터 필드로 보여주는 데 집중하고, 재난 전용 정보층은 비교 대상이 제한적이다.
WINDY
Windy는 Hurricane tracker와 Warnings를 별도로 제공하며, 경보를 현상별로 읽을 수 있게 한다.
EARTHUS AFTER
Hazards는 Event-first UI로 전환한다. 지도에서 이벤트를 선택하면 Track/Warning Area/Intensity/Official Source/Updated Time이 오른쪽 Inspector에 뜬다. 색은 단계형 Severity로 제한한다.
  [IMG media/image7.png]
AFTER 콘셉트 — Hazards / 재난
### 개발 Acceptance Criteria
재난 데이터는 연속 그라데이션보다 severity band 우선
태풍은 경로·예측영역·현재위치 분리
지진은 진앙/규모/깊이 동시에 표시
산불은 hot spot와 perimeter를 구분
공식 발표 시각과 기관명을 항상 노출

## 07. Air Quality / 대기질
항목
개발 기준
CURRENT EARTHUS
EARTHUS 범위에는 PM2.5·PM10·오존·자외선 등이 있다. 대기질은 색상 자체보다 건강 기준과 관측값을 명확히 읽게 해야 한다.

EARTHUS AFTER

CURRENT EARTHUS
EARTHUS 범위에는 오로라·일식·인공위성 궤도 등 sky/space가 포함된다. 일반 기상 레이어와 같은 방식으로 처리하면 제품 정체성이 약해진다.

EARTHUS AFTER
Space를 독립 top-level 메뉴로 만들고 Aurora / Satellites / Solar activity를 하위 모드로 둔다. 위성은 선택한 위성의 궤도·고도·속도·다음 통과를 Inspector에 표시한다.

# 5. 유료구독자가 느껴야 하는 변화
유료 사용자에게 보여줘야 하는 차이는 "잠금 아이콘이 많다"가 아니다. 같은 지구를 보더라도 유료 사용자는 더 빨리 정확한 답을 얻고, 비교하고, 근거를 확인하고, 다음 단계로 들어갈 수 있어야 한다.
항목

PRO
현상 선택 → compare → multi-source/model → intelligence → simulation → export/share
안전정보
태풍/지진/쓰나미 등 safety information은 구독 여부와 무관하게 계속 접근 가능하게 유지

# 7. 금지사항
메뉴 하나를 열 때마다 길쭉한 새 slider bar를 생성하지 않는다.
연속 그라데이션 하나만으로 온도·강수·대기질·위험도를 표현하지 않는다.
데이터 선택과 렌더링 튜닝을 같은 패널에 넣지 않는다.
AI 설명을 데이터보다 앞에 배치하지 않는다.
모델 비교를 settings submenu로 숨기지 않는다.
유료 기능을 잠금 아이콘만으로 표현하지 않는다. 먼저 사용 가치가 보여야 한다.
# 8. 현재 참고 사이트에서 확인한 구조
Mapped Earth는 현재 live globe에서 speed, temperature, wind, borders, rivers, NO₂, rainfall, population을 짧은 버튼 집합으로 제공한다. About 페이지에는 GFS/ECMWF, SST/SST HD/SSTA, currents, aurora, PM2.5/aerosol, ERA5 Time Machine 등 각 field와 데이터 출처가 설명되어 있다.
Mapped Earth: mapped.earth/earth / About
Windy의 현재 Menu는 Wind, Temperature, Rain/snow, Clouds/aviation, Waves/sea, Air quality, Drought, Warnings를 1급 카테고리로 제공하고, Weather radar, Satellite, Wind, Rain/thunder, Temperature, Hurricane tracker, Clouds, Waves, Rain accumulation 등 세부 레이어를 제공한다. 또한 Altitude, Display on map, Particles animation, Isolines, Forecast model을 독립 제어로 분리한다.
Windy: windy.com/menu
현재 EARTHUS V2 /v2 화면은 Search, Share/Image, Settings, cloud source, snow/ice, auto rotation, simulation/render tuning, terrain exaggeration, contour interval, hillshade, satellite blend, sun position, 3D Earth / 3D Terrain toggle를 노출한다. 이 자체가 현재 화면에서 확인된 구조이며, 본 보고서는 이 중 데이터 탐색과 표현 튜닝을 분리하는 것을 핵심 개선점으로 삼는다.
EARTHUS V2: earthus.net/v2/

# 10. 최종 결론
EARTHUS V2가 존재해야 하는 이유는 Windy보다 메뉴가 많아서도, Mapped Earth보다 지구가 더 예뻐서도 아니다. 핵심은 "3D Earth 위에 실제 관측/모델 데이터를 올리고 → 차이를 선명하게 읽고 → 출처를 확인하고 → Intelligence로 해석하고 → Simulation으로 다음 상황을 시험하는" 하나의 작업 흐름이다. 따라서 이번 개편은 메뉴를 더 추가하는 프로젝트가 아니라, 데이터 시각화·탐색·근거·비교·분석·시뮬레이션을 하나의 일관된 interaction model로 통합하는 프로젝트다.
# 11. 개발 참고 문서용 한 줄 지시
"EARTHUS V2를 레이어 모음이 아니라 분석 작업 공간으로 재구성한다. 현상 선택은 1탭, 시간축은 1개, Inspector는 1개, 데이터와 View는 분리하며, 온도/강수/대기질/위험도는 stepped band + contour + label을 기본 시각 언어로 사용한다."
