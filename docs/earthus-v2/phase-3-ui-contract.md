## 불변식 10 (지침서 §44)

### 1. Intelligence 는 최상위 메뉴가 아니다 — 단, 제품명은 예외다

`.es-switch` 의 "Intelligence"(`earth-switch.js:69`)는 **v2 제품 자체의 공개 이름**이고 배포된 URL(`/Intelligence`)이다. **이것은 §0.3 의 대상이 아니며 건드리지 않는다.**

§0.3 의 대상은 `#intel-tab` 의 "EARTH INTELLIGENCE"(`ui-shell.js:496`) 하나다. 이것은 현상을 고르면 그 현상의 이름을 달아야 한다.

> 시험: 우측 손잡이 라벨이 현상 선택 시 고정 문자열 'EARTH INTELLIGENCE' 로 남아 있지 않을 것. 동시에 `.es-switch` 의 세 알약은 그대로 있을 것.

### 2. 현상은 정본 레지스트리에서만 온다

`prototype/v2-three/js/phenomenon-registry.js` 의 `PHENOMENA` 66개 · `LAYER_PHENOMENON` 109개가 유일한 출처다. UI 가 자체 현상 목록·자체 라벨·자체 질문을 만들지 않는다.

> 시험: UI 가 렌더한 현상 id 집합 ⊆ `Object.keys(PHENOMENA)`. 유령 현상 0.

### 3. 레이어는 1차 내비게이션 단위가 아니다

LEVEL 2 는 현상 66개다. 레이어 109개를 그대로 나열하지 않는다. 한 현상이 여러 레이어를 흡수하면(20현상 54레이어) 그것은 현상 안의 자료다.

단 **기능은 하나도 없애지 않는다**(§32). 레이어는 현상 안에서 계속 켜고 끌 수 있다.

> 시험: LEVEL 2 에 노출되는 항목 수 ≤ 66. 109개 레이어 전부가 어떤 현상이나 명시된 자리(배경·조작 9개)에 도달 가능.

### 4. 능력이 없으면 탭이 없다

`capabilities[cap] === false` 면 그 능력의 진입점을 **렌더하지 않는다**. "준비 중" 도, 비활성 버튼도 아니다.

> 시험: `simulation:false` 인 현상에서 시뮬레이션 진입점 0. `forecast:false` 에서 예보 진입점 0.

### 5. 사건 신원은 정본 event id 다

`tc-<GDACS eventid>` / `eq-<USGS feature id>`. 배열 인덱스·레이어 인덱스·렌더 순서·UI 위치를 신원으로 쓰지 않는다. 정렬·재렌더·페이지네이션에도 같아야 한다.

> 시험: `tools/test_v2_event_id.mjs` (PHASE 2, 6건) 유지. UI 개편 후에도 통과.

### 6. 질문은 현재 현상 문맥을 상속한다

`/api/ask` 페이로드에 현재 선택된 현상·레이어 복합키·사건 id 가 들어간다. 질문창이 전역 챗이 되지 않는다.

> 시험: 현상 선택 후 질문 페이로드에 `phenomenonId` 가 존재.

### 7. 지도와 패널은 같은 선택 문맥을 공유한다

`MAP STATE = PANEL STATE = CONTEXT STATE`. 지도에서 사건을 고르면 패널이 같은 현상 문맥을 갖고, 패널에서 능력을 바꾸면 지도가 따라간다.

> 시험: `getSelection()` 과 지도 상태가 같은 복합키를 가리킨다.

### 8. 리포트는 리포트 계약을 쓴다

`REPORT_KIND_PHENOMENON`(9종, 그중 7종만 현상 대응)과 `aws/_shared/report_contract.py` 의 필드 이름을 그대로 쓴다. 임의 필드명을 만들지 않는다.

`ocean-drift` · `marine-bloom` 은 대응 현상이 없다 — UI 가 억지로 현상에 붙이지 않는다.

> 시험: UI 가 참조하는 리포트 종류 ⊆ `REPORT_KIND_PHENOMENON` 의 키.

### 9. 시뮬레이션은 실제 능력이 있을 때만 노출한다

정확히 2개다: `ocean.wave`(Gerstner) · `hazards.tsunami`(√(g·h) Dijkstra). 마케팅이나 UI 균형 때문에 늘리지 않는다.

⚠️ 현재 결함: `hazards.tsunami` 의 scenario 탭이 **태풍 카드**를 그린다(`main.js:4291-4324` 에 쓰나미 분기 없음). 능력이 약속한 것과 내용이 다르다 — PHASE 3 에서 고치거나, 고치기 전까지는 능력을 노출하지 않는다.

> 시험: 시뮬레이션 능력 참인 현상 = 정확히 2. 그 외 현상에서 시뮬레이션 진입점 0.

### 10. UI 단순화로 내부 능력이 사라지지 않는다

진입점을 줄이는 것이지 기능을 줄이는 것이 아니다(§32). 109 레이어의 렌더·데이터·라우팅은 그대로 남는다.

> 시험: `tools/check-v2-consistency.mjs` 가 계속 exit 0 — 레이어 109, 핸들러 누락 0, 유령 0.

## 추가 규칙 — 사용자에게 내부 구조를 보이지 않는다 (§0.5)

레이어 id · 씬 id · provider 이름 · 엔진 이름 · 내부 능력 키(`simulation`, `forecast` …)를 사용자 문구에 노출하지 않는다.

> 시험: 질문창·현상 이름·능력 라벨에 `/` 를 포함한 복합키나 영문 능력 키가 나타나지 않는다.

예외: 출처 표기(`USGS`, `GDACS`)는 **신뢰 정보**이므로 계속 보인다(§20). 그것은 내부 구조가 아니라 근거다.
