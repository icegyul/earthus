## 5. 실패 증거와 조치

- 첫 정적 배포 명령에서 shell 예약 배열 `path`를 반복 변수로 덮어 `git/aws`를 찾지 못했다.
  업로드 시작 전 중단됐고 운영 변경은 없었다. 변수명을 `release_file/release_js`로 바꿔 재실행했다.
- CloudFront invalidation 생성은 성공했지만 배포 IAM에 `GetInvalidation` 권한이 없어 상태 조회는
  `AccessDenied`였다. 완료를 추정하지 않고 운영 8개 SHA-256, response header, desktop/mobile
  실화면으로 반영을 증명했다.
- 브라우저 검수 중 page scope의 `performance`를 host scope에서 참조한 읽기 검사가 1회 실패했다.
  제품 오류가 아니며 DOM·network-loaded CSS·운영 hash로 다시 검증했다.

- 장소 운영기관의 폐쇄를 생성하지 않으며 `CLOSED` status를 만들지 않는다.
- PR-01/02 private shadow authoritative 전환, TPW flag on, 판매, SNS 자동 게시 없음
- AETHERUS astrometry 동시 신규 파일과 `work/`는 commit/deploy하지 않았다.
- EventBridge schedule 조회 권한은 없었으나 기존 10분 운영 snapshot freshness와 수동 실행을 확인했다.

## 7. 롤백

Lambda는 published version `1`을 남겼다. 즉시 완화 시 직전 코드 package로 `$LATEST`를
되돌리고 `events/kma-warn.json` source/time/count를 확인한다. 정적 UI는 `beeca6d^`의 8개
파일을 Content-Type과 no-cache header로 재업로드하고 같은 10개 경로를 무효화한다.
롤백 중에도 특보 실패는 SAFE가 아니라 UNKNOWN이어야 한다.
