## 3. 운영 파일 무결성과 헤더

cache-busting CDN GET의 SHA-256이 로컬 배포 파일과 모두 일치했다.

| 운영 경로 | bytes | SHA-256 |
|---|---:|---|
| `/js/activity-profile-policy.js` | 13,282 | `2852bb40e141492063adc634b323378c1d2fabfbd516e0fdc19d3612f5f0154d` |
| `/js/forecast-confidence.js` | 3,320 | `61601bb55ff9182d5fbd3f7ced4438e1106a4c2da4c1b24771648e04c0136c3b` |
| `/js/activity-decision-core.js` | 13,341 | `377813089ad324675b8280094f419fcdf488cd659ac84cf354a387c167484b2f` |

세 S3 object와 CDN 응답은 모두 다음을 확인했다.

- `Content-Type: text/javascript; charset=utf-8`
- `Cache-Control: no-cache`
- CDN `x-cache: RefreshHit from cloudfront`

배포 계정은 이전 PR과 마찬가지로 `cloudfront:GetInvalidation` 권한이 없어 status waiter는
조회하지 못했다. 무효화 생성은 성공했고, cache-busting GET의 실제 바이트·헤더·ES module
import·golden replay가 성공했으므로 운영 반영은 독립적으로 입증됐다.

## 7. Rollback

현재 공개 앱은 세 모듈을 참조하지 않으므로 앱 rollback에는 `index.html`이나 `main.js` 변경이
필요 없다. 모듈 자체 rollback이 필요하면 검증된 직전 object version을 같은 Content-Type과
`no-cache`로 복원한 뒤 세 경로만 무효화한다. 새 object를 바로 삭제하는 방식은 사용하지 않는다.
