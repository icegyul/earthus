## 3. 운영 파일 무결성

| 운영 경로 | bytes | SHA-256 |
|---|---:|---|
| `/js/reservation-impact.js` | 22,436 | `f92a264ce5edfcb8e4dc117e3d5821f9d43e0babdf9bc06feeca836a9753eb31` |

S3 head와 cache-busting CDN GET에서 다음을 확인했다.

- `Content-Type: text/javascript; charset=utf-8`
- `Cache-Control: no-cache`
- CDN body SHA-256이 커밋 파일과 일치
- CDN 응답 `x-cache: Miss from cloudfront`

운영 ES module replay는 provider가 `AVAILABLE`인 상태에서 공식 호우 WARNING을 입력했을 때
`ACTION_REQUIRED`, `PENDING_USER_CONFIRMATION`, evidence `n=2`를 반환했다. 동시에
`providerAction=null`, `notificationSent=false`를 확인했다. 이는 합성 계약 시험이며 실제
예약·날씨·특보·재고가 아니다.

CloudFront 무효화 생성은 성공했다. 배포 계정은 기존과 같이 GetInvalidation 권한이 없으므로
상태 waiter 대신 CDN 해시·헤더와 실제 module replay로 반영을 입증했다.
