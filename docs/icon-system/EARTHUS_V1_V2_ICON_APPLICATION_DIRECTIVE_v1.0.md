# EARTHUS V1 + V2 — ICON SYSTEM APPLICATION DIRECTIVE v1.0

## Purpose

Apply the approved EARTHUS Icon System to both V1 and V2 without changing data engines or product semantics.

## Non-negotiable UX Architecture

Primary menu = observable data / phenomenon.
Intelligence = second-stage action inside the selected primary data context.
Simulation = third-stage advanced workflow.
User AI = used at Simulation interaction layer, not as a standalone primary menu.

## V1

1. Preserve the familiar direct-access menu behavior.
2. Replace old/generic menu symbols with EARTHUS circular icons.
3. Keep labels next to icons.
4. Maintain visual hierarchy: icon → label → selected state.
5. Do not turn Intelligence into a top-level standalone menu.
6. Do not turn Simulation into a top-level standalone menu.

## V2

1. Use the same icon registry and asset names as V1.
2. Left navigation is the primary first-order data/phenomena navigation.
3. Desktop: icon + label; compact icon state may be used only where space demands.
4. Mobile: icon + label inside the drawer; do not compress the entire menu into unlabeled symbols.
5. One primary phenomenon is the visual protagonist at a time; related secondary overlays may coexist according to layer-combination rules.
6. On selecting a subject, expose:
   - Current
   - Change
   - Anomaly
   - Compare
   - Intelligence
7. Intelligence opens in the context of that subject.
8. Explorer gets evidence-based analysis/report.
9. Simulation appears as the next advanced step and is entitlement-gated for Pro+.
10. Simulation is not a generic navigation destination.

## Visual QA

Check both V1 and V2 at:
- 1920×1080
- 1440×900
- 1280×800
- 1024×768
- 430×932
- 390×844
- 375×812

Acceptance:
- no clipped icon
- no inconsistent icon scale
- no mixed icon families
- no text/icon collision
- active state clearly visible
- icon remains recognizable at 24–32px
- mobile menu remains understandable without scrolling through huge icon walls
