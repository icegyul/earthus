## 1. 핵심 판단

현재 가장 큰 문제는 데이터의 양이 아니라 **선택한 정보가 무엇인지, 어디의 언제 자료인지, 무엇을 뜻하는지 알아내는 비용**이다. 메뉴를 켜는 것과 사용자가 답을 얻는 것 사이에 단계가 너무 많다. 입체 지구와 전문 데이터는 강점이지만, 결과를 읽는 화면은 아직 데이터 공급자와 개발자의 언어에 가깝다.

우선순위는 ① 사실·예보·미확정 상태의 오해 제거 ② 메뉴 선택과 결과 연결 ③ 장소·시간·범례의 일관성 ④ 미션 컨트롤 가독성·빈 화면 해소 ⑤ 세 서비스 간 동일 기능의 연결이다. 새로운 레이어 추가보다 이 다섯 가지를 먼저 고치는 편이 사용자가 얻는 정보량을 늘린다.

이 보고서는 전 메뉴의 정보 구조 개선안을 다루며, 모든 기능이 정상이라고 인증하는 시험 성적서는 아니다. 메뉴 진입·선택·화면 응답을 확인한 항목, 화면에 노출된 목록과 소스를 대조한 항목, 권한·외부 응답 때문에 최종 결과를 검증하지 못한 항목을 구분한다. 모든 좌표·시각 조합, 모든 사진·관측소 개별 레코드, 결제·알림 발송·위치 허용은 검증 범위 밖이다.

추가 소스 검토: v2 메뉴 명세에서 연안 침수 **예상도**가 OFFICIAL_OBSERVATION, WorldPop 인구 조각이 OBSERVED로 분류돼 있다. 기관의 공식 자료라는 사실과 관측·추정이라는 자료 성격을 분리해야 한다. 이 두 항목도 배지 정비 시 함께 수정할 대상이다. 우주 사진관에서는 59점 목록과 첫 사진의 제목·공개일·크레딧·공식 원본 연결을 확인했다. 이 구조를 유지하면서 대상 유형·파장·쉬운 설명으로 검색을 보강하는 것이 적절하다.

## 4. 사용자가 정보를 얻는 공통 흐름

**장소 또는 관심 대상 선택 → 질문 선택 → 핵심 결과 → 지도에서 확인 → 변화·출처 확인**으로 정리한다.

| 단계 | 화면에 필요한 내용 | 예시 |
|---|---|---|
| 장소·대상 | 검색 + 최근 본 대상 + 명확한 적용 범위 | 서울 / 동해 / 특정 태풍 / 특정 발사 |
| 질문 | 사용자의 표현으로 된 진입점 | 비가 오는 곳 / 바람이 센 곳 / 이곳의 파도 / 다음 발사 |
| 첫 결과 | 값 + 단위 + 유효시각 + 자료 종류 | 파고 값, 해상 모델, 유효 시각 |
| 해석 | 색·높이·선의 의미와 비교 기준 | 빨강은 값이 높음, 높이는 실제 비율이 아님 |
| 다음 행동 | 실제 동작하는 1~2개 버튼 | 관측 부이 비교 / 공식 발표 / 위치 보기 |
| 근거 | 출처·발표·관측·수집 시각·결측 범위 | 최신 수집과 원래 관측 시각을 따로 표시 |

색으로만 설명하지 않는다. 지도에 보이지 않는 결과도 목록에서 찾을 수 있어야 한다. 키보드로 카드 선택 → 지구 위치 이동 → 상세 보기까지 가능하게 만든다. 도시·시군구 이름은 가급적 한글을 먼저 쓰고 국제 식별명은 보조로 둔다.

## 5. 서비스별 구조 제안

### v1 — 생활 질문의 시작점

현재 큰 메뉴의 '지구 보기 / 읽고 분석 / 활동 / 이동'은 유지할 가치가 있다. 다만 전체레이어는 전문가용 목록으로 두고, 앞에는 '내 주변 날씨·현재 경보·바다 활동·여행지·오늘 밤 하늘'을 배치한다. 기존 기능을 없애지 않고 기본 진입점의 순서만 바꾸는 방식이다.

위성 이름이 여러 번 반복되는 구름 메뉴는 '구름 보기' 안에서 **범위: 전지구·동아시아·한반도 / 영상: 자동·가시광·적외·수증기 / 자료 시각**으로 정리한다. '천리안'이라는 이름보다 사용자가 보고 싶은 것과 지원 조건이 먼저 보여야 한다.

### v2 — 비교하고 이해하는 화면

지형·날씨·해양·사람·여행·재해의 여섯 분류는 유지한다. 긴 전체 목록에는 검색, 범주 접기, 켜진 항목만 보기, 현재 지역 지원 필터를 추가한다. 13/13 같은 개발 진행 숫자는 사용자 가치가 작으므로 결과 수 또는 자료 시각으로 대체한다.

지도 오른쪽 결과는 '선택한 주제' 하나를 중심으로 표시한다. NOW/WHY/NEXT는 각각 **현재 자료 / 자료의 근거 / 예보와 예정**으로 명칭을 풀어 쓴다. WHAT IF는 '가정 실험'으로 분리한다. 질문 기능은 현재 켜진 데이터·선택 장소·대상 시각을 입력창 위에 보여준다.

### AETHERUS — 우주 탐험과 관측 준비

'미션 컨트롤 / 태양계 / 우주 사진 / 우리은하 / 우주의 크기'를 유지하되 각각의 첫 화면에서 질문 하나를 해결한다. 미션 컨트롤의 첫 질문은 '다음 발사가 언제이며 어떤 상태인가'다. 태양계는 '어떤 천체를 볼 것인가', 사진관은 '무엇을 관측한 사진인가', 은하 화면은 '우리 위치와 규모가 어떻게 되는가'에 집중한다.

v1·v2의 위성·발사·사진 메뉴가 각각 다른 기능처럼 보이지 않도록 동일한 대상 상세 페이지와 상태 계약을 공유한다. 서비스 변경 시 장소·시각·대상은 가능한 범위에서 유지하고, 유지되지 않는 것은 명시한다.

| 위성 필터 | 기본 배치에서 숨긴 위젯은 주제를 골라도 안 보임 | 주제에 맞는 위젯을 임시 표시, 전체로 돌아가면 저장 배치 복구 |
| 읽기 크기 | 7~10px 표제·본문·상태 다수 | 주요 제목 16~20px, 본문·메타 14~16px, 줄바꿈 허용 |
| 레이아웃 | 큰 지구와 좁은 고정 높이 위젯 다수 | 다음 발사와 정보 카드를 우선 배치, 전체 화면 세로 스크롤 |
| 반응형 | 중간 폭에서 4번째 이후 하단 위젯 숨김 | 위젯을 숨기지 않고 열 수를 줄여 이어 배치 |
| 상태 표현 | READY·UNAVAILABLE·LOCATION REQUIRED 혼재 | 일정 미확정·중계 대기·자료 미수신·위치 필요 등 의미별 표기 |
| 위성·ISS 탭 | 같은 결과를 가리키는 두 탭 | 위성 통과 탭으로 통합 |
| 오늘 볼 하늘 | 위치 미선택 안내만 있음 | 태양계·관측 사진으로 이어지는 실제 버튼 제공 |
| 지구 날씨 | 위치를 선택하면 연결된다고 안내하지만 코드상 고정 빈 상태 | EARTHUS에서 장소별 날씨를 보는 실제 경로로 안내 |
| 장식 궤도 | 실위치와 무관한 허블·JWST 타원 | 제거 |

이 수정은 로컬 소스와 미리보기에 적용했다. 운영 배포는 수행하지 않았다. 전 서비스의 정보 구조 개편은 아래 부록과 실행 순서에 제안으로 남겨 두었다. 지구 날씨 자동 동기화·전체 발사 선택·운영 캐시 변경·시각 해석 수정은 이번 수정 완료 목록에 포함하지 않는다.

추가로 필요한 미션 컨트롤 개선: 발사 목록의 행을 선택하면 카운트다운·중계·임무가 같은 발사를 바라보게 만들기, 팔로우와 선택 상태를 분리하기, 중계 없음 카드는 작게 접기, 위치를 수동 검색해 ISS 통과를 확인할 수 있게 만들기, 원자료 시각의 UTC/KST 해석과 Kp 갱신 시각 대조하기. '오늘 볼 하늘'의 실제 관측 가능성 계산은 구름·지평선·태양고도·위치 데이터를 연결한 뒤 제공해야 한다.

## 7. 시스템 차원의 개선

| 영역 | 필요한 변경 | 완료를 판정하는 조건 |
|---|---|---|
| 메뉴 계약 | id·사용자 질문·자료 종류·영역·시각·상태·결과 화면을 한 명세로 관리 | 메뉴, 지도, 카드에서 이름과 배지가 동일 |
| 데이터 시각 | observedAt / validAt / issuedAt / retrievedAt 분리 | 과거 발표가 새로 수집됐다고 현재 경보로 보이지 않음 |
| 공통 장소 | 지도 중심, 선택 장소, GPS 위치를 별개로 두고 적용 대상을 표시 | 서울을 선택한 채 해양 포커스로 옮겨도 맥락이 명확 |
| 비동기 상태 | 요청별 소유권·취소·이전 응답 무시·로딩 즉시 표시 | 빠른 메뉴 전환에도 마지막 선택의 결과만 표시 |
| 레이어 관리 | 활성 목록·전체 끄기·주제별 권장 조합·호환성 설명 | 서로 다른 주제 수십 개가 의도치 않게 누적되지 않음 |
| 성능 | 화면에 필요한 데이터 우선, 동일 API 요청 합치기, 비활성 엔진 정지 | 저성능 기기에서도 목록·메뉴·닫기가 즉시 반응 |
| 지도 접근성 | 지도와 대응하는 목록/표, 키보드 선택, 색 외 단위·문자 | 지구 드래그 없이도 장소의 값을 찾을 수 있음 |
| 오류 복구 | 실패 사유의 사용자 표현, 재시도, 마지막 성공, 대체 자료 | 빈 화면에서 다음 행동을 알 수 있음 |
| 운영 관제 | 소스별 수집/원자료 신선도/지역 공백/권리 상태 분리 | '정상 11/11'이 개별 레이어 정상으로 오인되지 않음 |
| 회귀 시험 | 메뉴 클릭에서 결과 제목·자료 종류·단위·시각까지 검증 | 버튼 존재만 확인하는 시험으로 통과시키지 않음 |

본문 글자 16px·보조 정보 14px는 이 제품에 대한 디자인 제안이다. WCAG가 모든 텍스트에 16px을 요구한다는 뜻이 아니다. 텍스트를 200% 확대해도 정보와 기능이 사라지지 않는 기준으로 실제 검수해야 한다. [W3C 텍스트 확대 기준](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html).

## 8. 실행 순서와 검수 기준

| 순서 | 작업 묶음 | 검수 과제 |
|---|---|---|
| 1 | 관측/모델 오표기·미확정/READY·발표 유효성 | 사용자가 자료 종류·대상 시각을 설명할 수 있는가 |
| 2 | 미션 컨트롤 수정 검수·운영 적용 준비 | 모든 주제에서 결과 또는 다음 행동이 있고 글자가 읽히는가 |
| 3 | 메뉴→해당 결과 연결·관광 유형별 목록·뉴스 복구 | 무장애 여행지를 눌러 개별 여행지의 접근성 정보를 찾는가 |
| 4 | 장소·시간·범례·활성 레이어 공통화 | 지도와 카드가 같은 장소와 시각을 가리키는가 |
| 5 | 세 서비스 간 대상 상세 공유·모바일·키보드 | 돌아가기·새로고침·서비스 전환 뒤 맥락이 유지되는가 |

검수 시나리오: 서울의 현재 기온 찾기, 특정 해역에서 모델 파고와 부이 관측 비교, 현재 유효한 태풍 공식 발표 찾기, 무장애 여행지 한 곳의 실제 편의 정보 확인, 다음 발사의 미확정 여부 설명, ISS 위치 권한 없이 수동 장소로 진입, 특정 우주 사진의 대상·망원경·출처 확인. 새 사용자 5명을 대상으로 첫 유효 정보까지의 시간·잘못 이해한 자료 종류·뒤로가기 횟수를 측정한다. 이는 향후 실험 제안이며 실제 사용자 연구를 수행했다는 뜻이 아니다.

## 9. 검증 결과와 남은 범위

- 새 필터 정책·발사 상태 회귀 테스트: 2개 통과.
- 기존 Mission Control 계약 테스트: 통과. 이 테스트는 화면 전체의 정상 보증이 아니라 정책·레이아웃 계약 검증이다.
- 변경 JavaScript 구문 검사와 diff 공백 검사: 통과.
- 로컬 브라우저: 미션 컨트롤 진입, 위성 통과 위젯 표시, 전체 복귀, 한국어 상태와 확대된 카드 확인.
- 레이아웃 편집 열기·닫기를 확인하고 편집 위젯 이름도 한국어로 맞췄다. 글자·카드 크기 확대를 확인한 것이며 브라우저 200% 확대 검수를 완료한 것은 아니다.
- 미확인: 실제 휴대폰·스크린리더·모든 지도 데이터 최종 로딩·위치 허용 후 ISS 계산·계정/구독/알림의 외부 동작·운영 배포 후 회귀.
- 운영 조회 중 확인한 실패는 해당 시점의 관측이다. 영구 장애나 서버 전체 장애로 단정하지 않는다.

## 10. 부록 읽는 법

아래 메뉴별 표에서 **UI**는 운영 화면에서 개별 클릭 후 응답을 확인한 범위, **목록·소스**는 노출된 메뉴와 코드의 연결·설명을 검토한 범위다. UI라고 표시돼도 모든 데이터 응답의 완료와 과학적 정확성 검증을 뜻하지 않는다. 권한 필요한 메뉴는 허용 전 화면까지다. 메뉴별 개선안은 실행된 수정이 아니라 제안이며, 실제 수정 범위는 6절에만 기록했다.

P0: 오해·기능 단절 / P1: 핵심 정보 접근 / P2: 탐색·학습 편의. 메뉴별 결과 표(menu-review.md), 필터 가능한 보고서(review.html), 구조화 목록(menu-inventory.json)을 같은 폴더에 제공한다.
