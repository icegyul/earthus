## 1. 8월 4일 v1 오픈 (D-8)

### 1-1. 도메인 — 카페24로 등록해도 된다. 단 역할을 정확히 알고.

**핵심 기술 사실 [확인]:**
- 앱은 S3 정적 호스팅이다. 커스텀 도메인 + **HTTPS** 는 CloudFront + ACM 인증서(us-east-1)가 사실상 유일한 경로다.
- HTTPS 는 선택이 아니다 — **위치 권한(geolocation)이 HTTPS 없이는 동작하지 않는다** (mylocation.js 실측). 내 위치·특보 알림·한국탭이 전부 위치에 걸려 있다. PWA(2단계 앱스토어 경로)도 HTTPS 필수.
- 등록업체(카페24/호스팅케이알)는 **DNS 창구일 뿐, 트래픽은 그쪽을 지나지 않는다.** "어디가 서비스가 좋냐"의 실질은 가격·DNS 편의·이관 용이성 셋뿐이다.
- CloudFront 는 도메인 연결 외에 **자동 압축(gzip/brotli)** 을 준다 [확인]. S3 정적 서빙은 압축이 없어서 지금 736지점·6,840지점 JSON 이 원문 그대로 나간다 — CloudFront 만 붙여도 전송량이 JSON 기준 70~90% 준다 (추정). **성능·비용·발열(§8) 모두에 오픈 전 최고 가성비 작업.**

**결정:** 가격이 같다면 카페24로 등록 → **네임서버를 Route 53 로 이관** (apex 도메인을 CloudFront 에 붙이려면 ALIAS 레코드가 필요한데 Route 53 가 표준 지원). 등록업체별 .net 정확 가격은 (확인 필요 — 리서치 에이전트가 세션 한도로 실패, 결제 화면에서 직접 비교하면 됨. 통상 연 1.5~2.5만원 수준(추정)이라 어느 쪽이든 결정 요인이 아니다).

**방어 등록 (상표 §3 와 연동):** earthus.com / earthus.kr 이 열려 있다면 같이 잡아 두는 것을 권한다 — 연 1~2만원의 보험이다 (추정).

## 2. 뉴스 시스템 — 차별화의 핵심

### 2-1. "3줄 요약"은 저작권 원칙과 충돌하지 않는다 — 설계로 푼다

**법적 기반 [확인 — 단, 법률 자문 아님 → [전문가 확인]]:**
- 한국 저작권법 **제7조 5호**: "사실의 전달에 불과한 시사보도"는 보호 대상이 아니다. 미국도 Feist(1991) 판례로 사실 자체는 비보호.
- 기사 제목·짧은 문구는 일반적으로 비보호 — 지금의 "제목+링크" 원칙은 안전.
- **핵심 구분: 기사 본문의 요약(표현의 파생) ≠ 여러 출처에서 추출한 사실의 재기술(새 창작).** 후자는 침해가 아니다.

**안전 설계 4원칙:**
1. 입력은 **여러 매체의 제목 + GDELT/UCDP 메타데이터**(장소·시각·행위자·규모)만 — 본문은 저장도 입력도 하지 않는다
2. 출력은 "어디서·언제·무엇이·어느 규모" 형식의 **중립 사실문 3줄** (한/영 동시 생성)
3. **NumSources ≥ 3** (3개 매체 이상 보도)만 요약 — 단일 기사 의존 배제, 원문 링크 병기
4. 재난·전쟁을 오락으로 소비시키지 않는다 — 사망자 카운터·순위표 금지 (기존 원칙 유지)

**비용 [확인]:** Claude Haiku 4.5 + Batch API 로 하루 200건 요약 시 **월 $6~12** (건당 입력 ~800tok·출력 ~250tok 기준). 실시간성이 필요하면 일반 호출로 월 ~$12. → ANTHROPIC_API_KEY 를 news-brief Lambda 에 넣으면 기존 구조 그대로 돈다.

### 2-2. 전쟁·난민·테러·붕괴 카테고리 — 데이터 경로 [확인]

| 경로 | 무엇 | 조건 | v1 판단 |

### 2-3. 번역

- 요약문: 생성 시 **한/영 이중 생성·저장** (UI 언어에 맞춰 표시)
- 기사 제목: **원어 그대로 유지** (기존 원칙 — "매체가 이렇게 썼다"를 보존), 필요시 브라우저 번역 안내
- GDELT 는 내부 번역(109개 언어)으로 **검색은 영어 키워드로 전 언어가 걸리지만**, 번역된 제목을 공개 필드로 주지는 않는다 [확인] — 그래서 요약 생성이 우리 몫이다.

**아래 3-2 의 "09류가 최대 리스크"라는 평가는 틀렸습니다.**
지정상품 원문을 열어 보니 `EARTH,US`(박주현)는 **스마트폰 케이스·그립톡**, `Earth&us`는

판단하므로 "09류에 선등록이 있다"는 사실 자체는 거절 사유가 아닙니다.

대신 놓쳤던 리스크가 있습니다 — **국내에 earthus 를 실사용하는 사업자가 셋**(얼스어스 카페 ·
어스어스 굿즈 · 어더스 의류)이고 `.com`/`.co.kr`/`.or.kr` 이 전부 선점돼 있습니다.
법적 리스크는 낮고 **브랜드·검색 혼선 리스크가 높습니다.**

### 3-2. 리서치로 확인된 판단 재료

- **표장 유사성**: 대법원 법리(외관·칭호·관념 전체관찰)상 "earthus" vs "EARTH,US"(어스어스)·"Earth&us"(어스앤어스)는 **칭호·관념 유사 위험이 상당하다** (추정). 문자만으로는 09류 거절 가능성을 안전 가정으로 둘 것.
- **그래도 공존 가능한 이유**: 표장이 유사해도 **지정상품 유사군코드가 다르면 공존 등록**이 된다 [확인]. "EARTH,US"가 09+14+16류 조합인 점에서 잡화·굿즈 계열일 가능성(추정) — **KIPRIS 상세보기로 두 선등록의 지정상품·유사군코드(소프트웨어 G390802 계열 포함 여부)를 확인하는 것이 모든 전략의 분기점.** 30분이면 된다.
- **부분거절제도** [확인]: 2023.2.4 시행 — 일부 상품에 거절이유가 있어도 나머지는 등록된다. 여러 류를 묶어 내도 "전부 사망"하지 않는다.
- **공존동의제** [확인]: 2024.5.1 시행 — 선등록권자의 동의서가 있으면 유사해도 등록 가능. 협상 카드가 하나 늘었다. [전문가 확인]
- **불사용취소심판**: 등록 후 3년 미사용 상표는 취소 청구 가능 — **"Earth&us"(2022.06 등록)는 이미 3년이 지나 지금 청구 가능**, "EARTH,US"는 2028.07 이후. 상대 실사용 흔적을 지금부터 아카이빙.
- **"earthus&earth" 변형은 비추천** — `&`+EARTH 구성을 공유해 Earth&us 와 오히려 가까워지고, 결합상표는 요부('earthus')만 분리 관찰되므로 회피 효과가 없다 [확인 — 분리관찰 법리].
- **유효한 변형**: ① 한글 음역 2단 병기 **"EARTHUS 어서스"** (칭호를 '어서스'로 고정해 '어스어스'와 차별화) ② 로고 결합상표 병행 출원 ③ 지정상품을 "기상정보·지구관측 소프트웨어"로 특정. 셋을 조합.
- **선사용 항변(상표법 99조)은 신생 서비스가 원용하기 사실상 어렵다** [확인] — "오픈하고 나서 생각"이 가장 비싼 선택지다.

## 5. 2단계 — 달 · 태양계 · 은하 [확인 중심]

### 5-1. 달 — 생각보다 가깝다

- CesiumJS 가 **달을 공식 지원**한다: `Ellipsoid.MOON` + Cesium Moon Terrain (ion 자산 2684829, LRO+가구야 합성).
- ⚠️ 단, **Cesium ion 무료 플랜은 비상업 한정** — 유료화 예정인 우리는 ion 을 쓰면 $149/월. **대안: NASA Moon Trek WMTS 타일 직접 사용(퍼블릭 도메인, 무료)** — `trek.nasa.gov/tiles/Moon/EQ/LRO_WAC_Mosaic_Global_303ppd_v02/...` 형식, 키 불요. 지형 기복 없이 타원체+영상이면 교육용으로 충분. **권장.** (CORS 는 배포 전 실측 필요)
- **아폴로 착륙지 6곳 좌표 확보** (NSSDC 공식): 11호 고요의 기지 0.67416°N 23.47314°E 등 — 사실정보라 저작권 무관.
- **암스트롱 발자국**: 별도 공식 좌표는 **존재하지 않는다** [확인]. 착륙선(LM) 좌표를 쓰고 "이 지점 사다리 아래에서 첫발"로 서술하는 것이 정확한 표현 — 지어내지 않는 우리 원칙 그대로.
- 소련 루나 9/16/17/24, 창어 3/4(최초 뒷면)/5/6(최초 뒷면 샘플), 찬드라얀 3(최초 남극권) 좌표도 확보 — "달 탐사의 역사" 레이어가 바로 만들어진다.
- LROC **웹사이트 게시 이미지는 ASU 저작권** — PDS 데이터 제품만 퍼블릭 도메인. 긁어 쓰면 안 된다 [확인].

### 5-2. 태양계 — 나선 궤적, 정확하게

- 행성 위치: NASA Horizons API 가 아니라 **astronomy-engine (MIT, 116KB, 브라우저 계산)** 권장 — API 비용 0, 정적 서빙 구조와 정합 [확인].
- 사용자가 원하는 "태양이 앞으로 나아가며 행성이 나선을 그리는" 시각화는 **과학적으로 타당하다**: 태양 은하공전 ~230km/s, 황도면-은하면 각도 60.2°.
- ⚠️ **단, 인터넷의 'vortex' 영상(DJ Sadhu)은 세 가지가 틀렸다** [확인 — 천문학자들 반박]:
  1. 90° 직각으로 그려 태양이 행성을 **항상** 앞서가는 듯 묘사 — 실제는 60.2°라 행성이 앞서기도 뒤처지기도 한다
  2. "vortex(소용돌이)" — 매질의 끌림을 함의. 실제는 상호작용 없는 **나선(helix)**
  3. "태양중심설이 틀렸다" — 기준계 선택의 문제일 뿐
- **구현 제안**: '태양 기준' ↔ '은하 기준' 토글 + 60.2° 정확 반영 + "인터넷의 소용돌이 영상은 왜 틀렸나" 한 줄 — **오개념 교정 자체가 교육 콘텐츠다.** 사용자가 "몇 년 전에 알고 감동한" 그 지점을, 남들이 틀리게 아는 부분까지 바로잡아 주는 화면으로.

### 5-3. 은하

- 항성 데이터: **HYG v4.2 (12만 별, CC BY-SA 4.0 — 상업 OK)** 권장. ⚠️ **Gaia DR3 원본은 CC BY-NC(비상업)** — 유료화 예정이므로 직접 사용 금지 [확인].
- 스카이박스: NASA SVS Deep Star Maps 2020 (퍼블릭 도메인, 크레딧 표기).
- 은하 지도: Spitzer "Roadmap to the Milky Way" (NASA/JPL-Caltech/R. Hurt) — 오리온팔·태양 위치가 표시된 사실상 표준 이미지.
- 교육 포인트: 태양계는 오리온팔, 은하중심(궁수자리 A*)에서 2.6만 광년 / 알파센타우리 4.37광년 / 안드로메다 250만 광년 / 시리우스·베가·플레이아데스 — "이 빛이 출발했을 때 지구는 ~였다" 연출.

### 5-4. 기술 구조 [확인]

CesiumJS 는 뷰어당 중심체 1개라 **태양계·은하는 불가**. 결론: **3-씬 하이브리드** —
① 지구 = 기존 CesiumJS ② 달 = CesiumJS 재사용(Ellipsoid.MOON + Trek WMTS, 난이도 하~중) ③ 태양계~은하 = Three.js 별도 씬(로그 깊이버퍼 + astronomy-engine + HYG).
전환은 줌아웃 한계점에서 페이드/워프. 비활성 씬은 렌더 정지(발열 대책과 직결). 추가 번들 ~300KB 는 씬 진입 시 지연 로딩.
**데이터 비용 0원 경로가 존재한다** — Trek + astronomy-engine + HYG + SVS 조합.

## 8. 발열 · 경량화 — "효과 큰 순서" [확인 중심]

이미 한 것: requestRenderMode, 파문 수명 제한, 레이어 지연 로딩, 켜진 레이어만 수집.

1. **CloudFront (§1 과 동일 작업)** — JSON 자동 압축 70~90%, 한국 엣지 캐시. 오픈 전 필수.
2. **requestRenderMode 가 실제로 쉬는지 검증** — CallbackProperty·시계 tick 때문에 "영원히 idle 에 못 들어가는" 상태일 수 있다 [확인 — Cesium 공식]. `maximumRenderTimeChange` 크게, 갱신 시점에만 `requestRender()`, **postRender 카운터로 1분간 프레임 수 실측** (idle 이면 ~0 이어야 정상).
3. **해상도 계층**: `useBrowserRecommendedResolution=true` (iPhone DPR 3 의 프레임버퍼 부담 제거) + 저전력 모드에서 `resolutionScale` 0.7~0.75 + SSE 2→4 (위성영상은 체감 차이 미미).
4. **적응형 저전력 모드**: ⚠️ Battery API 는 **Safari/Firefox 미지원이라 설계에서 제외** [확인]. 대신 ① Compute Pressure API(Chromium — "serious"부터 자동 절전) ② **rAF 프레임타임 이동평균 휴리스틱(전 브라우저)** — 33ms 지속 초과 시 resolutionScale·SSE·파티클을 한 단계씩 강등 ③ 수동 절전 토글(최후 보장).
5. **바람 파티클**: 기기 등급별 수 차등(모바일 1/4) + 무입력 N초 후 일시정지 + 저전력 시 30fps 캡.
6. **구름 애니메이션의 비디오화**: 이미지 시퀀스 JS 루프 대신 Lambda 에서 mp4/webm 인코딩 → `<video>` 재생 — 하드웨어 비디오 디코더가 맡아 CPU 발열 급감 (rVFC 전 브라우저 지원 확인).
7. **뷰포트 컬링**: 736지점·6,840지점은 전송량보다 **엔티티 렌더 부하**가 진짜 비용 — 뷰포트 밖 `show=false` + 줌별 밀도 제한이 지역 분할 파일보다 우선.
8. 계측: 온도는 못 읽는다 — **프레임타임 + LoAF(Long Animation Frames, 원인 스크립트 귀속) + longtask** 를 프록시로 대시보드화.

"서버 분리"는 이미 돼 있다(정적 S3+Lambda). 남은 건 CDN 계층뿐이고 그것이 1번이다.

### 10-1. 시장의 가격대

| 서비스 | 가격 | 유료벽 |
|---|---|---|
| Windy | 연 $34.99 | 1시간 스텝, 위성 아카이브 365일, 알림 무제한 |
| Flightradar24 | $9.99~34.99/년 | **과거 이력 기간(90일→365일→3년)** |
| Zoom Earth | 연 $11.99 | 10일 예보, 나우캐스트, 알림 |
| MyRadar | $5.99 1회 | 광고 제거(1회성)+전문팩(구독) |
| Star Walk 2 | $2.99+IAP | 콘텐츠팩 소액 판매 |

심리적 가격선: **연 $10~35.** 우리 ₩39,000/년(≈$28)은 밴드 안 [확인]. 공통 패턴: **데이터가 아니라 '해상도·기간·알림 수'를 판다** — 우리 billing.js 철학("데이터는 전부 무료, 사용자별 계산·축적 이력만 유료")과 정확히 일치한다. 바꿀 필요 없다.

### 10-2. 단계별

**1단계 (웹):**
- 주력: 프리미엄 구독 — 유료벽 후보: 되감기·이력(→ **오늘부터 JSON 을 지우지 말고 쌓는 것이 곧 재고 자산**), 맞춤 알림 무제한, AI 3줄 브리핑(API 비용이 드는 기능이라 비용 전가 정당), 예보검증 상세(경쟁사에 없는 우리만의 것), 위성 전체 16,000개.
- 웹 결제(PG)는 앱스토어 수수료 0 — 1단계 마진 최대.
- 보조: 후원(BMC 수수료 5%) — 결제 연동 전 "지불 의사 신호" 수집용.
- 어필리에이트: Skyscanner 는 입점 심사에 기존 트래픽 요구 — 오픈 직후엔 어려움 (추정). Travelpayouts(항공 1.1%)로 시작, 트래픽 확보 후 직계약.
- **공공누리 1유형은 출처표시만 하면 상업이용·재배포 가능** [확인] — 기상청 파생 서비스 유료화는 법적으로 문제없다. 단 소스별 라이선스 매트릭스(히마와리·GDACS·CelesTrak 등) 작성 후 유료화 [확인 필요].

**2단계 (앱):** IAP 15%(양 스토어 공히 첫 $1M) · 결제 유인은 위젯·워치·라이브 액티비티(태풍 경로) — 경쟁사 검증된 패턴. 웹 결제 계정과 Supabase 로 통합해 수수료 낮은 쪽으로 유도.

**3단계 (지도):** **B2B 임베드/화이트라벨이 검증된 경로** (meteoblue 모델 — 스크립트 태그 임베드 판매) [확인]. 방송사·지자체 상황판·해운물류. 로컬 광고는 영업조직이 필요해 "기능으로 수익" 조건에 부적합 — 후순위. 교육(K-12가 에듀테크 시장 38.9% [확인])은 무료 경쟁(Google Earth)이 있어 **교사용 수업자료·과제 기능을 붙인 SaaS 형**이어야 함.

### 10-3. 지금부터 쌓아야 할 트랙션 지표 5 (IR 의 연료)

1. WAU + D7/D30 리텐션 (시드 심사 1순위 — v1 오픈일부터 경량 로깅 필수)
2. 평균 세션 시간 ("탐험형 체류"라는 우리 주장의 유일한 증명)
3. 알림·계정 옵트인 수 + 프리미엄 대기목록 (지불 의사 신호)
4. **아카이브 재고량** ("출시 시점에 이미 N개월치 독점 이력 보유" = FR24식 유료화의 원가)
5. 사용자당 월 인프라 비용 (무서버 원가 우위 — "MAU 1만에 서버비 X만원"은 심사역에게 가장 잘 먹히는 생존력 지표)
