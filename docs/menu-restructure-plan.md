### 배치 D — if (요청 6) · 2단계, 합계 ~4일

**원칙 충돌 주의**: ask는 "환각 불가능 — 추정 문장 금지"가 절대 규칙(router.js 12-15)이고 '왜'를 명시 거부한다. if(시뮬레이션)는 본질이 가정 서술 → **관측 계층과 시뮬레이션 계층을 화면에서 분리**해야 이 원칙이 산다. 시뮬레이션 답변에는 항상 "관측이 아니라 과거 사례 기반 추정" 라벨.

- **D1 (UI + 큐레이션 15)**: if 버튼 → 기존 askPanel 확장. 상단 = 인기 시나리오 15개(큐레이션, **야간 잡 사전계산** — brief.js 패턴, 브라우저에서 LLM 직접 호출 금지 원칙 유지). 하단 = 실시간 질문 결과 리스트(초기엔 빈 상태 안내). 기존 관측 Q&A는 그대로 동작
- **D2 (질문 큐)**: 사용자 질문 → Supabase 큐 적재 → 야간 배치가 router.parse()(구조화: datasets·place.box·time·intent)로 파라미터화 → readGrid/readAnomaly(answer.js:60,111)로 관측값 근거 수집 → LLM이 문장화 → 결과 S3 발행 → 리스트에 노출. router.misses()(현재 메모리뿐)를 Supabase로 영속화해 수요 파악
- ⚠️ 시뮬레이션 엔진은 현재 어디에도 없음 — v1은 "물리 시뮬레이션"이 아니라 "과거 유사 사례 + 현재 관측값 기반 시나리오 서술"로 정직하게 스코프. 자체 예보모델 금지 원칙과의 경계를 명시

## 4. 토큰 전략 (요청하신 "최적의 토큰 사용")
