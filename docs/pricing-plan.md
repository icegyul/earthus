# 구독 설계 — 얼마를 받고, 무엇을 유료로 할 것인가

작성 2026-08-04 · 판단 근거와 반대 의견을 함께 적는다.

---

## 0. 먼저, 받은 제안에 대한 답

> "우리가 가공하는 데이터는 요약은 무료로 보여주고, 디테일한건 유료서비스로 가는게 맞다고 나는 보고 있어"

**방향은 맞습니다. 다만 자르는 축을 바꾸는 게 좋겠습니다.**

⚠️ **"요약 무료 / 상세 유료"로 자르면, 이 앱이 지금까지 쌓은 신뢰를 파는 것이 됩니다.**

이 앱의 값어치는 숫자 자체가 아니라 **그 숫자를 어떻게 알았는지를 밝히는 것**에 있습니다.
출처, 몇 곳에서 쟀는지(n), 어떤 기준으로 갈랐는지, 무엇을 못 하는지(⚠️).
그런데 그게 정확히 "디테일"입니다.

그걸 유료로 막으면 무료 사용자가 보는 화면은 이렇게 됩니다.

> 경포 해수욕장 — 위험

근거도 없고, 누가 그렇게 판정했는지도 없고, 한계도 없는 단정.
**우리가 이 프로젝트 내내 거부해 온 바로 그 화면**입니다.
그리고 그건 다른 날씨앱과 구별이 안 되는 화면이기도 합니다.

### 대신 이렇게 자르자 — **"지금" 대 "시간"**

| | 무료 | 유료 |
|---|---|---|
| **지금 상태** | 전부. 출처·n·기준·⚠️한계 포함 | — |
| **과거** | 오늘 하루 | 되감기 · 지난 30일 · 작년 같은 날 |
| **미래** | 기관 예보를 그대로 | 내 지점 맞춤 계산 (위성 통과 등) |
| **범위** | 관심 지점 1곳 | 20곳 동시 감시 |
| **알림** | — | 관심 지점 알림 *(웹푸시 완성 후)* |
| **내보내기** | — | CSV · API |

무료는 **넓게**, 유료는 **깊게(시간)와 나에게(개인화)**.

이 축은 사장님 직관("디테일에 값을 매긴다")과 결과가 거의 같습니다.
차이는 **"근거"는 디테일이 아니라 기본**이라고 못 박는 것뿐입니다.

### ⚠️⚠️ 절대 유료로 넘기지 말아야 할 것 — 안전 정보

특보 · 지진 · 쓰나미 · **이안류 위험** · 낙뢰 위치.

세 가지 이유입니다.

1. **사람이 다칠 수 있습니다.** 오늘 새벽 경포·속초·낙산·망상·고래불이
   동시에 "경계 이상"으로 들어왔습니다. 이걸 결제창 뒤에 두는 앱은 만들면 안 됩니다.
2. **앱스토어 심사에서 문제가 될 수 있습니다.** 안전 관련 기능의 페이월은 리뷰에서 자주 걸립니다.
3. **원자료가 무료 공개자료입니다.** 기상청·국립해양조사원이 무료로 푼 것을
   우리가 막아서 파는 모양이 되면, 공공누리 표시 의무와 별개로 평판이 남습니다.

이건 요금제 항목이 아니라 원칙으로 코드에 박아 뒀습니다
(`billing.js` 의 `FREE_FEATURES` 두 번째 줄).

## 1. 가격 — 제안

|  | 현재 코드 | **제안** | 근거 |
|---|---|---|---|
| 월 | ₩4,900 | **₩3,900** | 4,900은 "커피 한 잔"과 견주는 구간. 3,900은 그 아래 |
| 연 | ₩39,000 | **₩29,000** | 월 환산 ₩2,417 · 38% 절약 |
| 창립회원 500명 | — | **연 ₩19,000** | 초기 사용자 확보 |

### 왜 내리자고 하는가

- **윈디 프리미엄이 연 $24.99입니다** (2025년 11월 인상, 그 전 7년간 $18.99).
  한화 약 ₩33,000. 일시불 1년권은 $29.99.
  ⚠️ 이 숫자는 커뮤니티 글 기준이라 결제 직전에 한 번 확인해 주세요.
  → 우리 ₩39,000은 **전 세계 표준인 윈디보다 비쌉니다.**
    신규 서비스가 그 자리에 앉으면 비교당하는 순간 집니다.
  → ₩29,000이면 윈디와 비슷한 자리이고, "한국·일본은 우리가 더 촘촘하다"로 설명이 됩니다.

- **국내 유료 날씨앱은 대부분 실패했습니다.** 기상청 앱이 무료로 강력하기 때문입니다.
  우리가 이길 수 있는 건 가격이 아니라 **기상청이 안 하는 것**입니다 —
  취미별 화면(서핑·낚시·등산·패러글라이딩), 일본 자료 통합, 출처 공개, 3D 학습.

- **심리 구간**: 넷플릭스 베이직 ₩5,500, 왓챠 ₩7,900.
  3,000~4,000원대가 "생각 없이 지르는" 마지막 구간입니다.

### 창립회원 500명을 왜 따로 두는가

- 초기 사용자 500명을 얻는 비용으로 광고보다 압도적으로 쌉니다.
  ₩19,000 × 500 = ₩9,500,000 — 매출이면서 동시에 마케팅비 절감입니다.
- 스키마에 이미 `founding_member` 컬럼이 있어서 추가 작업이 없었습니다.
- ⚠️ **"평생 이 가격"이라고 쓰지 않았습니다.** 지키기 어려운 약속입니다.
  화면에는 "1년 이용권 + 창립회원 표시가 계정에 남음"이라고만 적었습니다.

## 2. 왜 정기결제(자동갱신) 대신 이용권인가

⚠️ **처음부터 자동갱신을 붙이지 마세요.** 세 가지가 걸립니다.

1. **빌링키(자동결제)는 PG 별도 심사 대상**입니다. 사업자등록증이 필요하고 시간이 걸립니다.
2. **자동갱신은 분쟁이 가장 많은 지점**입니다. 초기에 고객응대 부담이 큽니다.
3. **단건 결제는 오늘이라도 열 수 있습니다.**

그래서 `plans` 테이블을 **개월 수(`months`)** 로 만들었습니다.
1개월권 / 12개월권을 팔고, 남은 기간에 **이어 붙입니다**
(`apply_paid_order` — 남은 기간을 빼앗지 않습니다).
자동갱신은 나중에 얹으면 되고, 그때도 이 표는 그대로 씁니다.

### 보안상 반드시 지킨 세 가지

1. **금액을 클라이언트가 정하지 않습니다.** `planId`만 보내고 금액은 DB에서 찾습니다.
   (브라우저에서 3900 → 39로 바꿔 보내는 것이 가장 흔한 결제 취약점입니다.)
2. **승인은 멱등입니다.** 새로고침하거나 웹훅이 재전송돼도 기간이 두 배가 되지 않습니다.
3. **시크릿 키는 Edge Function 안에만** 둡니다. `config.local.js`는 브라우저로 그대로 내려갑니다.

## 3.5 해외 결제 — 토스 말고 뭐가 더 필요한가

**답부터: 결제사를 하나 더 붙이는 문제가 아니라, "누가 판매자(seller of record)가 되느냐"의 문제입니다.**

### ⚠️⚠️ 먼저 알아야 할 두 가지

**① 한국 사업자는 Stripe 계정을 못 엽니다.** (2026년 기준)
2025년 10월에 "Stripe 한국 진출" 소식이 돌았지만, 실제 내용은
**해외 법인이 한국 고객의 원화 결제를 받을 수 있게 된 것**이지
한국 법인·개인사업자가 Stripe 셀러가 되는 게 아닙니다.
→ 해외 SaaS의 기본값인 Stripe가 **우리에겐 선택지가 아닙니다.**

**② 디지털 서비스는 해외에 팔면 첫 1건부터 세금 의무가 생깁니다.**
EU VAT는 **면세 한도가 없습니다** — 유럽 사람에게 €1 받으면 그 나라 부가세를 걷어
신고·납부해야 합니다. 영국 VAT, 일본 소비세(JCT), 호주 GST도 각각 있습니다.
⚠️ **이걸 1인 사업자가 직접 하는 건 현실적으로 불가능합니다.** 나라마다 등록·분기신고입니다.

### 그래서 실제 선택지는 셋

| | 누가 판매자인가 | 세금 | 수수료 | 우리 작업 |
|---|---|---|---|---|
| **토스** | 우리 | 우리 (국내 부가세만) | 약 2~3% | ✅ 어젯밤 완료 |
| **앱스토어 IAP** | Apple / Google | **Apple·Google이 전 세계 처리** | 15~30% | 어댑터 **이미 있음** |
| **MoR (Paddle 등)** | Paddle | **Paddle이 200개국 처리** | 5~7% | 어댑터 1개 추가 |

MoR(Merchant of Record)은 **결제사가 법적으로 판매자가 되는** 방식입니다.
Paddle이 우리 상품을 되파는 형태라 **부가세 책임이 통째로 그쪽으로 넘어갑니다.**
한국 셀러도 받아 주고, 국내 고객에게는 카카오페이도 붙습니다.

### 제 권고

**해외 웹 결제는 굳이 지금 붙이지 마시고, 순서를 이렇게 가세요.**

1. **지금** — 토스로 국내만 연다. (어젯밤 코드 그대로)
2. **앱을 낼 때** — iOS/안드로이드 IAP. 수수료는 비싸지만
   **전 세계 세금이 자동으로 해결되고 어댑터가 이미 있습니다.**
   ⚠️ 그리고 앱스토어 규정 3.1.1상 앱 안에서는 **IAP 말고 다른 결제를 쓸 수 없습니다.**
3. **해외 웹 매출이 실제로 생기면** — 그때 Paddle.
   ⚠️ 매출이 없는데 미리 붙이면 월 고정비와 심사만 남습니다.

⚠️ 해외 결제를 붙이는 날 **개인정보 국외이전 동의**가 따로 필요합니다
(개인정보보호법 제28조의8). 처리방침에 이전받는 자·국가·항목을 적어야 합니다.

### 코드는 이미 준비돼 있습니다

`billing.js` 의 `PROVIDERS` 가 어댑터 구조라, 새 수단은 **객체 하나 추가**면 됩니다.
그리고 어젯밤 스키마에 있던 결함 하나를 오늘 고쳤습니다 —
`orders` 의 금액 칸 이름이 `krw` 였습니다.
⚠️ **그대로 두고 해외 결제를 붙이면 USD 금액이 "krw" 칸에 들어가** 회계가 조용히 틀어집니다.
`amount` + `currency` 로 갈랐고, **최소 단위**로 저장하도록 못 박았습니다
(KRW는 원 그대로, USD는 센트 — 안 지키면 $21.99가 $2,199로 기록되는 100배 사고).

## 4. ⚠️ 사장님이 하셔야 하는 것 (제가 못 합니다)

제가 카드·계좌·상점키를 대신 입력하지 않습니다. 아래는 직접 해주셔야 합니다.

1. **토스페이먼츠 가맹점 신청** — 사업자등록증 필요
   → 테스트 키(`test_ck_` / `test_sk_`)는 신청 즉시 나옵니다. 그것으로 끝까지 돌려볼 수 있습니다.
2. **Supabase SQL Editor 에서 실행**
   - `prototype/supabase/schema.sql` (아직 안 하셨으면)
   - `prototype/supabase/billing.sql` ← 오늘 만든 것
3. **Edge Function 배포 + 시크릿 등록**
   ```
   supabase functions deploy checkout
   supabase functions deploy payment-confirm
   supabase secrets set TOSS_CLIENT_KEY=test_ck_...
   supabase secrets set TOSS_SECRET_KEY=test_sk_...
   supabase secrets set APP_ORIGIN=https://earthus.net
   ```
4. **`config.local.js` 에 두 주소 넣기** — `CHECKOUT_URL`, `CONFIRM_URL`
5. **사업자 정보 채우기** — `config.local.js` 의 `BUSINESS`
   ⚠️ 전자상거래법 제10조. **통신판매업 신고번호 없이 유료 판매하면 안 됩니다.**

### 가격을 바꾸고 싶으시면

두 곳을 **같이** 고쳐야 합니다 (한쪽만 고치면 화면과 청구액이 달라집니다).
- 표시: `prototype/js/billing.js` 의 `DEFAULT_PLANS`
- 실제 청구: Supabase `plans` 테이블 (`billing.sql` 의 `insert ... on conflict`)

## 5. 제 결론 한 줄

**무료는 "지금 무슨 일이 일어나는가 + 우리가 그걸 어떻게 아는가"까지.
유료는 "시간을 거슬러 보는 것 + 나에게 맞춰 계산하는 것".
안전 정보는 어떤 경우에도 무료.**

가격은 **월 ₩3,900 / 연 ₩29,000 / 창립회원 500명 연 ₩19,000** 을 권합니다.
코드는 이 값으로 넣어 두었으니, 다르게 정하시면 위 두 곳만 바꾸면 됩니다.
