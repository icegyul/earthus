# 사용 패턴 분석 — "어디를 자주 쓰고 어디서 불편한가" (2026-07-29 설계)

> "사용자가 서비스 이용할때 어디를 자주 사용하고 불편해하는지 분석해주는 것도 만들어야겠어.
> 그러면 개선점을 찾을 수 있겠지." — 만들지 않고 계획만.

이번 세션에서 고친 문제들(배너 두 줄 겹침·지명 오류·검색 없음)은 **전부 사용자가 먼저 겪고
대표님이 스크린샷으로 알려주신 것**이다. 이 시스템이 있었다면 배너 겹침은 "특보 시트가
0.3초 만에 닫히는 비율 급증"으로, 지명 오류는 몰라도 "그 카드 클릭 후 이탈률"로 먼저 잡혔을 것.
목표는 그 발견 과정을 자동화하는 것 — 사람이 우연히 보는 게 아니라 시스템이 먼저 짚어준다.

---

## 0. 이미 있는 것 — 그 위에 짓는다

- `consents` 테이블 (필수: tos·privacy·over14, 선택: marketing·location) — **analytics 항목 없음**
- `service_interest` 의 **insert-only RLS 패턴**: `with check (true)`, select 정책 없음,
  집계는 `SECURITY DEFINER` 함수로 개수만 반환 — 개별 행은 절대 밖으로 안 나간다
- `ui-apikeys.js` 의 **`#해시`로 숨긴 운영자 전용 패널** 패턴 — 새 인프라 없이 재사용
- `ui.js` 등 전역의 `safe(fn)` try/catch 래핑 — 이미 실패를 곳곳에서 잡고 있다.
  **여기 한 줄만 추가하면 에러 이벤트가 공짜로 들어온다**
- localStorage 로 익명 상태를 들고 다니는 관행(레이어 상태·동의 버전 등) — 세션 id도 같은 방식

## 1. 원칙 — 이 앱의 결벽증을 그대로 적용한다

이 앱은 익명 키로도 이메일 한 건을 못 읽게 짜여 있다(service_interest 검증 완료).
사용 분석도 같은 결벽증이어야 한다. 안 그러면 "믿을 수 있는 지구본"이라는 브랜드와 어긋난다.

1. **PII 없음, `user_id` 도 없음(v1).** 세션 id는 클라이언트가 만든 난수(UUID) — 이메일·IP·
   기기 지문은 물론 **로그인 계정과도** 묶지 않는다. 계정 연결이 필요한 분석은 v1 범위 밖(§1 참고).
2. **세션 리플레이 안 한다.** 화면을 영상처럼 재생하는 도구(Hotjar·FullStory류)는 v1 제외 —
   그건 사실상 개인 행동을 녹화하는 것이라 동의 설계가 훨씬 무거워진다. 이벤트 로그로 충분하다.
3. **제3자 벤더에 원데이터를 보내지 않는다.** GA4·Meta Pixel 류는 배제한다.
   ① 한국 이용자 데이터가 해외 광고테크로 흘러가는 구조 자체가 이 서비스의 신뢰 원칙과 안 맞고
   ② 개인정보 국외이전 이슈까지 겹친다. **Supabase(이미 검토·승인된 신뢰 경계) 안에 자체 파이프라인**
   을 두는 게 유일한 선택지로 보인다 — 신뢰 경계를 늘리지 않는다.
4. **집계만 밖으로 나간다.** 원본 이벤트는 운영자 전용, 화면에는 항상 집계(횟수·비율·중앙값)만.
5. **끄면 그 순간부터 안 보낸다.** 설정에 토글 하나 — 끈 사용자의 클라이언트는 이벤트 자체를
   만들지 않는다(서버에서 걸러내는 게 아니라 클라이언트가 애초에 안 보낸다).

### 동의 방식 — 결정 (2026-07-29)

처음엔 "옵트인 전체 vs 옵트아웃 전체"로 물었는데, 그건 **잘못 쪼갠 질문**이었다.
진짜 갈림길은 A/B 가 아니라 **"계정과 묶느냐"** 다 — 그 축으로 나누면 결정이 저절로 난다.

- **익명 세션 이벤트** (레이어·시트·마찰신호 — 가치의 대부분이 여기 있다):
  **고지 후 수집.** `user_id` 를 아예 붙이지 않으므로(아래 스키마 변경) "누구인지" 정보 자체가
  없다 — 개인정보보호법상 식별 가능성이 훨씬 낮아 고지+옵트아웃 토글로 충분한 근거가 된다.
  이 앱 안에서는 "지금 열려 있는 화면·클릭한 지점"이지 "당신이 누구인가"가 아니다.
- **계정과 묶는 이벤트** (재방문 패턴 등 `user_id` 필요한 것): **v1 에서 아예 뺀다.**
  `consents` 에 marketing/location처럼 이 항목만을 위한 새 체크박스를 만들 필요조차 없다 —
  필요성이 아직 없는 기능에 법적 부담을 미리 지지 않는다. 나중에 "재방문자가 검색을 더 쓰는가"
  같은 진짜 필요가 생기면 그때 marketing_agreed 와 같은 자리에 옵트인 항목을 추가한다.
- 이 구분이 [consents 테이블](../../aws/schema.sql)의 기존 원칙(필수 일괄 동의 vs 선택 개별 동의)과
  정확히 일치한다 — 계정과 결합되는 것만 별도 동의를 받는다는 게 이 서비스가 이미 쓰던 기준이다.
- 남는 실제 할 일: **개인정보처리방침에 "익명 이용통계 수집" 단락 추가.** 문구 자체는
  법률 검토 대상이라 여기서 임의로 쓰지 않는다 — 착수 시점에 대표님 확인.

⚠️ 이 결정으로 "대표님이 A/B 를 골라야 착수 가능"이라는 이전 블로커는 사라진다.
남은 건 정책 문구 확인뿐이라 P3 순서 그대로 진행 가능.

## 2. 무엇을 잰다 — "자주 쓴다"와 "불편하다"를 구체적인 신호로

### 자주 쓴다 (사용 빈도)
| 신호 | 방법 |
|---|---|
| 시트/패널 열람 빈도 | 커뮤니티·설정·관측소·이벤트 시트 등 open 이벤트 |
| 레이어 on/off 빈도·조합 | 어떤 레이어가 같이 켜지는지 (48종 중 실제로 쓰이는 건 몇 개인지) |
| 체류 시간 | 시트별 열림→닫힘 간격 (중앙값 — 평균은 이상치에 취약) |
| 재방문·복귀 주기 | v1 제외 — 계정 결합이 필요해 §1 원칙에 따라 이번 범위 밖 |
| 검색 쿼리 (검색 완성 후) | 무엇을 찾으려 했는가 — 제품 방향의 가장 직접적 신호 |

### 불편해한다 (마찰 신호) — 이게 진짜 가치
| 신호 | 판정 |
|---|---|
| **레이지 클릭** | 700ms 안에 같은 지점(반경 ~40px) 3회 이상 클릭 — "눌렀는데 안 됨" |
| **데드 클릭** | 클릭했는데 상태 변화가 없는 요소 (핸들러 없음/무반응) |
| **급취소** | 시트를 열자마자(<2초) 닫음 — 원하는 걸 못 찾음 |
| **레이어 즉시 원복** | 레이어를 켰다가 5초 안에 다시 끔 — 기대와 다른 결과 |
| **검색 허탕** | 검색했는데 결과 0건 또는 아무것도 안 누름 (검색 완성 후 유효) |
| **에러 발생** | 기존 `safe()` 래핑에 한 줄만 추가하면 **공짜로 수집** — 이미 곳곳에 있다 |
| **온보딩 이탈** | 코치마크 중간에 스킵/이탈한 지점 |
| **세션 중 이탈 직전 화면** | 마지막으로 본 곳 = 나가게 만든 화면일 가능성 |

⚠️ 레이지/데드 클릭은 **판정 로직 자체가 잘못되면 소음만 쌓인다.** 임계값(700ms·40px·2초·5초)은
잠정치 — 실 데이터로 튜닝 전에는 "얼마나 자주 발생하는가"만 보고 "심각하다"고 결론짓지 않는다.

## 3. 파이프라인

```
[클라이언트]           [Supabase]                [야간 Lambda]           [운영자 화면]
이벤트 발생          →  usage_events           →  집계·이상탐지        →  #usage 패널
배치(10개/10초) 전송     insert-only RLS            top 시트/레이어         (ui-apikeys.js 와
sendBeacon(이탈 시)     원본은 30일 후 삭제         마찰 신호 랭킹           같은 숨김 패턴)
                                                  주간 diff("이번 주
                                                  급증한 마찰 신호")
```

### 스키마 초안
```sql
create table if not exists public.usage_events (
  id          bigint generated always as identity primary key,
  session_id  uuid not null,              -- 클라이언트 난수, PII 아님
  -- ⚠️ user_id 컬럼을 v1 에서 아예 두지 않는다. 계정과 결합하는 순간 익명이 아니게 되고
  --    consents 에 별도 동의 항목이 필요해진다(§1). 필요해지면 그때 마이그레이션으로 추가.
  kind        text not null,              -- 'sheet_open'|'layer_toggle'|'rage_click'|'error'|...
  target      text,                       -- 'community:today' 같은 짧은 식별자. 자유텍스트 금지
  meta        jsonb,                      -- 최소한만. 좌표·검색어 원문 등 민감할 수 있는 값은 넣지 않는다
  client_ts   timestamptz not null,       -- 클라이언트 시각(배치 전송이라 서버 수신시각과 다를 수 있음)
  created_at  timestamptz not null default now()
);
alter table public.usage_events enable row level security;
-- ⚠️ service_interest 와 동일 원칙: select 정책을 만들지 않는다.
create policy ue_insert on public.usage_events for insert with check (
  kind in ('sheet_open','sheet_close','layer_on','layer_off','search',
           'rage_click','dead_click','error','onboard_step','onboard_skip')
);  -- 화이트리스트 — 클라이언트가 임의 kind 로 쓰레기를 못 넣게

-- 집계 함수만 노출 (원본 행은 운영자 서비스키로만 조회)
create or replace function public.usage_top_sheets(days int default 7)
returns table(target text, opens bigint) language sql security definer
set search_path = public stable as $$
  select target, count(*) from usage_events
  where kind = 'sheet_open' and created_at > now() - (days || ' days')::interval
  group by target order by 2 desc limit 20;
$$;
grant execute on function public.usage_top_sheets(int) to anon, authenticated;
```

### 클라이언트 (`js/usage.js`, 신규)
- `track(kind, target, meta)` — 큐에 쌓고 10개 또는 10초마다 flush
- 페이지 이탈 시 `navigator.sendBeacon` 으로 마지막 배치 전송 (이게 없으면 이탈 직전 데이터가 빠진다 —
  "어디서 나갔는가"가 가장 중요한 신호인데 안 잡히면 이 시스템의 목적 절반이 무너진다)
- 설정 토글 꺼짐 상태면 `track()` 자체가 아무 것도 안 함 (원칙 5)
- 레이지/데드클릭은 `document` 레벨 캡처 리스너 하나로 — 새 리스너를 화면마다 안 붙인다

### 야간 집계 (`usage-digest` Lambda, 신규)
- 시트/레이어 순위, 마찰 신호 랭킹, **주간 diff**("이번 주 급증한 마찰 신호 3개")
- 출력 `admin/usage-digest.json` — ⚠️ **공개 프리픽스에 두지 않는다.** 운영자 전용 버킷/프리픽스로
  분리하거나 CloudFront 에서 이 경로만 접근 제한. (실황 자료 `/ocean/*`·`/events/*` 와 다르게
  이건 사용자 행동 집계라 공개 노출 기준이 달라야 한다)

### 운영자 화면
- `ui-apikeys.js` 와 동일하게 **기본 숨김**, `#usage` 로 진입
- 시트별 열람 순위 · 마찰 신호 Top 10 · 주간 변화 · (참고용) 온보딩 이탈 지점

## 4. 회귀 방지 — 이 시스템 자체가 발열/성능 문제를 만들면 안 된다

이 앱의 최우선 원칙과 정면으로 만나는 지점이다.
- 이벤트 캡처 리스너는 **passive**로 등록, 레이어 렌더 루프에 절대 개입하지 않는다
- 배치 전송이지 실시간 전송이 아니다 — 요청 폭주로 이어지면 안 된다
- `power.animate()` 를 이 모듈이 호출할 일은 없다 — 순수 데이터 수집이라 화면과 무관해야 한다
- 레이지 클릭 판정용 최근 클릭 버퍼는 크기를 작게 고정(`_seen` 300개 캡 사고와 동일 원칙)
